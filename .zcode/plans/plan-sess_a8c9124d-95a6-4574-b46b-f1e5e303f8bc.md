# 知识库管理页面（新增「知识库」页）

## 前提与定位

- 知识库是独立项目（如 `E:\muyian\agent`，结构：`data/raw/` 原始资料、`kb/` 条目带 frontmatter（`source` 字段指回原始文件）、`index/index.json` 由仓库自带脚本生成），程序**只读不生成**：不改写 kb 内容、不跑生成脚本（跑 `py` 会违反「唯一外部程序是 git」的约束）。
- 程序做的事：① 指定知识库文件夹；② 原始数据管理——列出 raw 文件并判定「未入库 / 有更新 / 已入库」，一键复制整理指令（丢给 ZCode 等 Agent 去生成）；③ 知识库信息——条目清单、只读阅读、统计与索引状态；④ 仓库有远端时提供手动同步。

四个澄清问题未作答，按推荐项定案（同步按钮默认做，因为它复用现有通道成本极低；不想要删掉即可，计划里已把同步单独列为一节）。

## 更新判定口径（核心逻辑，放 `src/shared/knowledge.ts` 纯函数 + 单测）

- 扫描知识库根目录得平铺清单（每项带 `rel` / `mtimeMs`）；适配层按前缀拆三部分：`data/raw/` 下所有文件（任意后缀）→ raw 清单；`kb/` 下 `.md`（排除 `_catalog.md`）→ 读出后解析 frontmatter 得条目元数据；`index/index.json` → 索引信息。
- raw 状态判定：kb 条目 frontmatter 的 `source`（如 `data/raw/mu-ui/button.md`）归一化（统一 `/`、剥 `data/raw/` 前缀）后与 raw 相对路径配对——没有条目指向 = **未入库**；raw 的 `mtimeMs` > 指向它的条目里最新的 `mtimeMs` = **有更新**；否则 = **已入库**。依赖文件修改时间，是启发式（git 操作会重写 mtime），文档里写明。
- 索引一致性：`index.json` 的 `count` / `generated_at` 与实际条目数比对，不一致在信息面板提示「索引待重建：在知识库目录运行 py scripts/build_index.py」。
- 复制整理指令：固定文案 + 当前「N 个未入库、M 个有更新」计数，写入剪贴板（复用保险库现有的复制机制），`notifySuccess` 提示。

## 页面结构（照 SkillsView/NotesView 的既有模式）

- 未选文件夹（或目录已不在）：整页引导 `.panel`（说明 + 「选择知识库文件夹」按钮，`pickDirectory`）。
- 已选：顶部 `.filter` 工具带（位置 + 统计徽标：条目数/未入库/有更新；工具：刷新、打开文件夹（走现成 `reveal` 通道）、复制整理指令、同步（仅仓库有 origin 时出现）、换文件夹）。
- 主体两栏：左栏 `el-segmented` 切「条目 / 原始数据」——条目 tab 是搜索 + 条目列表（标题、标签、status、摘要、更新日期）；原始数据 tab 是状态筛选 chips（带计数）+ raw 文件列表（状态徽标、修改时间）。右栏：默认「知识库信息」概览（条目数、标签分布、状态分布、索引状态、仓库归属），点选条目后切只读阅读（复用 `MarkdownView.vue`，头部显示 source 出处与元数据）。
- 换页不关弹层、空态五分支显式区分、样式只用 global.css 现成类 + tokens。
