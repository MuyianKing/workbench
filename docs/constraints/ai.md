- **会话是这里的头等对象**：一个会话 = **一个工作目录里的一段连续对话**，与 Pi 自己的
  会话文件一一对应（见下面「会话留档」那条）。`aiSessions` 里只存调度用的那点东西
  （id / dir / title / createdAt / updatedAt，收敛在 `shared/ai.ts` 的 `sanitizeAiSessions`），
  对话本身不在应用的数据文件里。左栏那棵树按 `dir` 分组（`aiSessionGroups`）：
  **第一层是项目（一个目录）、第二层是这个目录下的会话**。
  **工作目录在会话里是定住的、创建后不改**：Pi 按目录给会话分组，换目录等于换一段对话 ——
  要换目录就新建一个会话（左栏那颗「+」或者项目行上那颗）。
  `aiActiveSession` 记「上次打开的是哪一个」（认不出来的回最近说过话的那个）。
  **「起一段新的」那几下只是切屏幕**（`stores/ai.ts` 的 `drafting` / `startNew`）：
  顶上那颗「+」= 切到起始那一屏（接着最近用过的目录），项目行上那颗 = 切过去 + 用这个目录；
  **一个空会话都不先建** —— 会话是发出第一句时才建的（见下面那条），所以这几处**别再改回
  成「建一个空会话再跳过去」**。`drafting` 期间 `activeId` 是空串（左栏哪一行都不铺底色），
  点左栏任一行或者那一句发出去就自动退出这个状态。
- **这一页是通用控制台，与知识库无关**：工作目录由用户挑（跟着会话走，与知识库的 `kbDir`
  互不相干）、指令由用户写（`shared/ai.ts` 的 `taskPrompt` 只把「在哪儿干活」说清楚）。
  **不内置任何一类任务的提示词、也不在跑完之后做与具体任务绑在一起的事**（不重建索引、
  不刷新谁的列表）—— 处理知识库只是「把目录指到那个仓库、写一条照它规范整理的指令」的一种
  用法。要做「知识库专用任务」，在这一层上面加模板，别往下面这条链路里塞分支。
  起始那一屏下方**不摆「用过的指令」**：那排 chips（`aiHistory`）已按用户要求整个去掉
  （2026-09-29），历史不再记、设置里不再有这个字段 —— 别把它加回来，也别拿任何预设模板填进去。
- **起始那一屏中间就是那条 composer**（`AiComposer.vue`，与控制台那一屏同一条）：
  一进来就能直接写，**会话在发出第一句时才建**（`stores/ai.ts` 的 `run` → `ensureSession`，
  用的是那一屏挑好的目录）—— 别把「新建会话」改回成发消息之前要单独点的一步。
  那一屏上没有线稿、没有标题：中间一张输入卡片，上面是位置那一栏、下面是用户写过的指令。
  **左栏顶上那颗「+」就是把这一屏叫出来的**（`startNew`，见上面「会话是这里的头等对象」
  那条）；一个会话都还没有时左栏按别处那副空态给一句说明（标题 + 一行小字，不成块、
  不描边、不摆按钮 —— 与笔记树 / 视频树同一套 `.tree__empty`）。
- **位置那一栏（`AiLocationBar.vue`）两屏共用**：挑中会话时目录是**定住的**（下拉里只有
  「在资源管理器里打开 / 复制完整路径」，换目录要新建会话），起始那一屏上它**就是挑目录的
  地方**（下拉里是最近用过的目录 + 「选择其他目录…」，挑完只记在 store 的 `newDir` 上，
  不建会话）。两屏说的都是「接下来在哪儿干活」，所以只探一个目录的分支（`watchedDir`）。
- **两屏的分界是「挑中了没有」**：挑中一个会话（包括还没说过话的新会话）就是控制台那一屏，
  一个都没挑中才是起始那一屏（`AiView.vue` 的模板）。装 Pi 的输出也算控制台那一屏
  的一部分（它画在运行面板里）；**缺 Pi 时那颗「安装 Pi」两屏各摆一颗** —— 控制台那一屏在
  运行面板顶部的通知条上（`AiRunPanel.vue`，它本来就只在有事情要说时才出现），起始那一屏在
  composer 底下那一行（那一屏没有运行面板）。发送那颗按钮的悬停里说的就是它。
- **控制台那一屏画的是聊天，不是步骤流**（`AiRunPanel.vue`，这一版的口径）：
  **用户自己写的那几句靠右**（浅底气泡、限宽 72%），**助手的话在左**（正文，无气泡框 ——
  它常常几屏长，框住只会少一圈阅读面积）；工具调用与系统那几行是浅灰的窄行注脚；
  一轮跑完在末尾补一行「用时 …」（`formatDuration`，它是这一轮的句号）；端点报了消耗的话
  同一行带上 token（`输入 … · 输出 …`，`parsePiUsage` 拆 `message_end` 带的 `usage`、按轮
  累加，输入含缓存读 / 写；没报就只有用时 —— 自定义端点不保证都有）。
  **回话是流式长出来的**（`message_update` › `text_delta`，`parsePiDelta` +
  `stores/ai.ts` 的 `onDelta`）：增量攒到 `STREAM_TICK`（80ms）才发布一次 —— 每个字都重画
  一遍对话区（还要重跑一遍 markdown）是白烧钱，攒一小会儿看着仍是连续长出来的；
  **整段到了（`message_end`）就以它为准**（增量拼起来只是过程版）。块的开头结尾
  （`text_start` / `text_end`）不画；
  被停掉的那一轮把已经吐出来的部分留在对话里（`endStream` 的 `keep`）。
  **一轮的过程整块收着**（`aiTurns` 切轮、`AiProcess.vue` 画那块，都有单测）：
  一轮 = 用户那句 + **过程**（想的那几段、工具调用、报错、旁白）+ **答案** +「用时 …」（收据）。
  过程摊着就是一面墙（一次读文件、一条命令各占一行），
  所以它默认收着、跑着的时候摊开（标题上转圈写「正在思考… / 正在执行…」）、跑完自动收起，
  点标题随时再摊开。**答案只认收尾时紧挨着收据的那段正文**：正文后面只要还跟着工具 / 思考行，
  它就是过程中的旁白（「我分块写入再合并」然后就去写文件了）—— 不然它一直占着「答案」的位置，
  后面新长出来的思考反而压在它头上（时序倒挂，踩过，已改）。旁白照常渲染 markdown，
  跟着过程一起收着；收据只收轮尾成串的「用时 …」，报错不进收据（红才丢不了）。
  **跑着的那轮不摘答案**（`aiTurns` 的 `live`）：正文落地也先留在块里，流式那段长在块末尾
  （落地不跳位置），收尾才把最后那段正文弹出去当答案。
  想的那几段（`thinking_delta` 喂出来，与正文同一套 `STREAM_TICK` 节流）走**纯文本**
  —— 草稿里那些半截标记不该被当成排版；一段想完以 `thinking_end` 给的整块内容为准。
  落进对话的行是 `kind: 'thinking'`，**打开旧会话那条路也认它**
  （`sessionMessagesToLines` 的 `thinking` 块，被厂商脱敏过的空块不画）。
  **「还在跑」不写在顶部那行状态里**：那行只说等你确认 / 接历史 / 在停 / 装 Pi / 出错；
  跑着的动静跟着过程那一块走（转圈 + 正在思考 / 正在执行、正文末尾一根竖条）——
  顶部再说一句「运行中…」既是重复，又把「某一段还在想」说成了整轮的状态（踩过，已改）。
  **轮与轮之间的「开始执行 / 执行结束」不画**（`stores/ai.ts` 的 `isTurnMarker`）——
  那种分节放在单次运行的步骤流里合适，连续对话里就是每轮插一句的噪音。
  **对话区自己不许铺底色、也不描边**（别写 `background: var(--bg-inset)` 那一类）：
  这一块就是那张卡片本身，底色归 `.panel` 与卡片不透明度管 —— 在它里面再铺一层灰底，
  用户看到的就是一大块灰压在对话上（踩过，已改）。
- **这一页不摆提示行，弹窗里也不写说明段**：说明、问候、「还差什么」都不写在页面上 —— 缺什么
  由 `blocking` 说，而它只出现在**发送按钮的悬停**里（`AiComposer.vue` 的 `sendTitle`）；问候
  只有顶栏那一处（见 HomeGreeting 的文件头）。页面上留下的字只该是控件自己的：控件上的标签、
  左栏那一栏的栏名、输入框的 placeholder、composer 里那句工具边界。这个应用是给作者自己用的，
  把控件已经说清的事再讲一遍就是噪音 —— 与首页那一行「不打招呼、不问好、不鼓励」同一条语气。
  **弹层里同理，而且没有「只留一句」的余地**：说明句、适用范围小字、空态提示、
  生效时机说明全都不写，弹窗里只剩控件与数据 —— 机制与理由都在文档里（本文件与架构文档）。
  踩过两次（2026-09-29 技能弹窗：先删到只剩一句开场加一句生效时机，当天被要求连这些也删，
  连同随「生效时机」给的那颗「结束它」一并去掉）；同一天第三轮又定了例外：**技能弹窗组头上的
  根路径与计数徽标摆回来了**（照技能管理界面的通行样子）—— 它们是数据不是说明句，
  这条禁令照旧管着的是说明段与提示行。也别加「点这里开始」「第一次用？」这类引导。
- **干活的不是应用，是本机的 Pi**（一个开源的编码 Agent）：**Pi 随包内置**，Node 用系统里的。
  内置的形态由 [scripts/vendor-pi.mjs](../../scripts/vendor-pi.mjs) 在构建 / 开发前生成到
  `resources/pi/`（不进版本库，见 .gitignore）：装**钉死版本**的 Pi，再删掉运行时用不到的
  云厂商 SDK（`@aws-sdk`、`@smithy`、`@google`、`@esbuild`、`openai`、`@anthropic-ai`、
  `web-streams-polyfill`）。**能这么删是因为跑的是那份 bundle**：真正被执行的只有
  `dist/bundle/cli.js`（→ `chunks/`，提供方实现按形态各内联成一个 chunk），它要的外部包只有
  `@earendil-works/chord`、`typebox`、`undici`、`@silvia-odwyer/photon-node`；`npm` 装出来那棵
  树里 `pi-ai/dist/api/*.js` **静态 import 了这些 SDK 的那几份副本运行时谁也加载不到**
  （给扩展 import 用的 `@earendil-works/pi-ai` 那条路留着，不删）。**删之前先找落点**：
  pi-coding-agent 带自己的 `npm-shrinkwrap.json`，npm 会把整棵树嵌进它自己的 `node_modules`
  下（顶层只有 `@earendil-works` 一项）—— 按顶层路径删会一声不响地整个空转（踩过：写着瘦身、
  实际 385MB 一个没少），脚本的 `findDeps` 就是为这个写的。瘦身后 59MB（未瘦身 385MB，其中
  `@esbuild` 那 26 份平台二进制占 284MB）；2026-09-29 在瘦身后的这份树上重验过两条提供方路径
  （`openai-completions` / `anthropic-messages`，也是 models.json 只认的两种）都照常发出真实请求。
  **Node 不内置**：跑内置 cli.js 要本机 node ≥ 22.19（版本判定在
  `shared/ai.ts` 的 `nodeSatisfiesPi`），跑不起来整个 AI 助手页明说原因。
  **升级 Pi** = 改 vendor 脚本里的版本常量 + 重跑 `npm run vendor:pi` + 把下面的瘦身验证
  重新做一遍（假 key 打一轮每个要用的提供方），**会话、续聊、权限扩展与确认帧那条链**照
  [dev-notes/pi-session-probe.md](../dev-notes/pi-session-probe.md) 的假端点探针再跑一遍。
- **干活的进程直启、不经 `cmd /C`**：`session::spawn_args`（程序 + 参数数组 + 一根
  **可写的 stdin**，与 git 直启同一条理由）—— 整行交给 cmd 时，**行内层引号会被 cmd 的引号
  剥离规则拆坏**（实测：cli.js 路径带引号时 node 收到的是被剥得只剩盘符的路径，报 EISDIR）。
  提示词与确认答复都走那根 stdin（见下面两条），不落临时文件、也不走 shell 重定向。
- **内置 cli.js 的路径解析有两处候选**（`ai.rs` 的 `resolve_cli`，与内置壁纸同一条路子）：
  打包后走 `resource_dir()/pi/...`，开发态读仓库 `resources/pi/`；两处都没有才退回 PATH 上
  的全局 `pi`。**resource_dir 给的是 `\\?\` 原样路径，必须剥掉前缀再用** —— cmd / 与若干
  程序对这种前缀的处理都不可靠（踩过：node 收到只剩盘符的路径）。
- **模型管理是「服务 + 模型」两层**（照通用客户端的样子）：一个**服务** = 名称 + Base URL +
  API 形态 + 密钥 + 模型清单；清单里每一条带**上下文窗口**、**最大输出**、**思考档位**与
  **能力（能看图）**（形状与收敛都在 [shared/ai.ts](../../src/shared/ai.ts) 的
  `AiProvider` / `AiModelEntry` / `sanitizeAiProviders`）。
  四样东西的落点各不相同 —— 名称 / Base URL / API 形态 / 清单进**设置**（`aiProviders`）；
  密钥进 **Windows 凭据管理器**（`Workbench/ai/<服务名>/token`，一个服务一条，只写不回显）；
  端点本身由 `ai.rs` 的 `models_write` 写成 Pi 的 **`models.json`**，
  落在 `%APPDATA%\Workbench\data\pi\`（`PI_CODING_AGENT_DIR` 指过去的那份 agent 目录，
  与用户全局的 `~/.pi` 互不掺和）。**一次写整份**（增删改都走它，不做增量：
  增量会在文件里留下上一次的残影）；**停用的服务与停用的模型都不进这份文件**
  （`aiProviderPayload`），所以界面上能挑的与 Pi 那边看到的是同一份。
  **`models.json` 里的 `apiKey` 是环境变量引用**（`$WORKBENCH_AI_KEY`，Pi 的插值语法）——
  密钥值只经环境变量注入，那份文件从头到尾不落明文（几个服务共用同一个变量名是安全的：
  跑一轮只起一个进程、`--provider` 也钉死了用哪一个）。
  **API 形态只认登记过的那两个 id**（`openai-completions` / `anthropic-messages`，见
  `shared/ai.ts` 的 `AI_API_FORMATS`）：都来自 Pi 自己的材料，别凭印象加。
  **服务名只收小写字母 / 数字 / 连字符**（`sanitizeAiName`）：它同时是 models.json 的键、
  凭据管理器目标名的一部分与 `--provider` 的值，别放宽。
- **厂商预设只填地址**（`AI_PROVIDER_PRESETS`）：「添加服务」第一步那张网格里一格一个，
  用户粘一把 API Key 就能连。收进去的判据是**地址与形态都没争议** —— 宁可少列几个：
  地址写错的代价是用户以为自己的 key 不对（401 / 404 长得一样）。剩下的走「自定义端点」。
  **清单由端点自己报**（不内置模型清单：各家的模型名变得太快）；但**能力默认值从随包
  Pi 的内置目录预填**（见下面「四层」那条）—— 端点只报 id 不报能力，不预填就会把
  视觉模型配成纯文本。
- **模型列表从端点拉**（`ai_models_fetch`）：地址由 Base URL 与形态推出来 ——
  `openai-completions` 的 baseUrl 本来就含 `/v1`，列表在 `{baseUrl}/models`；
  `anthropic-messages` 的 baseUrl 到主机为止（SDK 自己接 `/v1/messages`），走 `/v1/models`，
  带 `/v1` 的中转地址不再补一层（`ai.rs` 的 `models_url`）。**打的是用户自己那个端点**
  （同一个主机、同一把 Key，只是换个路径），只有人在弹窗里粘了 Key 或点了「获取列表」
  才会走 —— 这是 AI 那条出口的延伸，不是新出口。回包的几种形状都认
  （`data` / `models` / 顶层数组，字段名各家不同），**端点没报的那几样给 0 / null**
  （不是「不支持」），由渲染层兜底。密钥优先用草稿里刚粘的那把，空串才回凭据管理器取。
- **上下文 / 最大输出 / 思考档位 / 能看图是「端点说 → 内置目录认 → 按名字认 → 留空」四层**：
  1. 端点报了就用（OpenRouter 那种 `context_length`、`max_completion_tokens`、
     `supported_parameters`）；
  2. 没报的从**随包 Pi 自带的模型目录**认（`builtinModelMeta`；表是 vendor 脚本从钉死版本的
     Pi 里剪出来的 `ai-builtin-models.generated.ts`，认法是指定厂商 → 任意厂商 →
     「厂商/模型」后缀）—— **Pi 跑同一个 id 用的就是这张表**；图片能力（`input` 带
     `image`）只在这一层认得出来，端点不报、名字也猜不得；
  3. 目录没有的按模型 id 认一遍很确定的家族（`inferModelMeta`，表在 `shared/ai.ts`）——
     **规矩是宁缺毋滥**，认不出就留空，别编数字（上下文给大了会在该压缩的时候不压缩）；
  4. 都认不出：上下文 / 最大输出 0 = 不知道，**models.json 里不写这两个字段**（写 0 会被
     Pi 的 schema 挡下），Pi 按它自己的 128000 / 16384 兜底；思考按不支持、图片不勾。
     用户在模型那一行上随时能改。
  **「能看图」勾上了才写 `input: ["text", "image"]`**，**不写 Pi 就按 `["text"]` 算** ——
  read 读图、工具结果里的截图都被它丢掉（模型会说「我看不了图」，它的依据是 read 工具
  塞给它的那句注记，不是端点）。**渲染层 payload 与 ai.rs 的 ModelInput 字段名必须一字不差**
  （`imageInput` / `maxTokens` —— 前者是布尔，Pi 文件里的 `input: ["text","image"]` 由 Rust 落）：
  serde 对认不出的键是**静默丢弃**，两边名字对不上时**两边单测都会绿**（踩过：渲染层发
  `input: [...]`、Rust 收 `imageInput`，勾了「图片」永远写不进 models.json，排查了两小时）。
  思考档位落成 Pi 的 **`thinkingLevelMap`**（`aiThinkingMap`，只写与 Pi 默认不一样的那几档）：
  `reasoning: true` 时 off / minimal / low / medium / high 是**默认支持**的（不用写），
  `xhigh` / `max` **必须显式给一个字符串才算支持**，不支持的档位写 `null`。
  界面上的下拉只列这个模型支持的档位，挑了一档不被支持时退默认档（`pickAiThinking`）。
- **跑哪个模型是「默认模型」一条设置**（composer 上那个下拉，也是模型管理弹窗顶上那一栏）：
  存的是 `aiDefaultProvider` + `aiDefaultModel`（行为记忆），挑的没了（服务停用 / 模型关掉 /
  删掉）退回第一个能挑的（`pickAiChoice`），一个都没有就是空。**只由启动参数
  `--provider <服务名> --model <模型 id>` 指定**（`shared/ai.ts` 的 piLaunch，有单测）：
  内置 Pi **不读 `PI_MODEL` 环境变量**，`models.json` 里的清单它也只当候选 —— 两处都不给时
  它退到自己那张内置的「提供方 → 默认模型」表上（踩过：提供方叫 `opencode-go` 时它按内置表
  发了 `kimi-k2.6`，用户清单里的 `deepseek-v4.1-flash` 一个字没用上，端点回 410 说这个模型已下线）。
  **验法**：把 `models.json` 的 baseUrl 指向一个本地假端点（回 400 即可），看它实际请求的
  `model` 字段 —— 比读文档可靠；换 Pi 版本后要重验这一条。
- **思考档位也总是显式给**（`--thinking <level>`，`aiThinking`）：那七档是 Pi 自己认的
  （`off` / `minimal` / `low` / `medium` / `high` / `xhigh` / `max`，取自它的 `defaults.js`），
  **id 一个字符都不能改** —— 给它不认的值它会直接报错退出；界面上叫什么叫由
  `shared/ai.ts` 的 `AI_THINKING_LEVELS` 定（默认档 `medium`，与 Pi 自己的默认一致）。
  不显式给也能跑，但界面上挑了什么与它真跑的是什么就对不上了 —— 所以总是给。
  **给的是「这个模型支持的档位」里挑的那一档**：不支持思考的模型只有 `off`
  （Pi 那边 `getSupportedThinkingLevels` 就是这么算的，它自己也会把档位夹到支持的范围里）。
- **别把「读懂并改写内容」搬进应用**（在 Rust / TS 里写死一套改写逻辑）：怎么拆、怎么组织
  由用户与目录里的规范（AGENTS.md 之类）说了算，那是 Agent 的活；应用只做三件事 ——
  把目录与指令交给它、准备模型与密钥、把过程与结果画出来。
- **提示词与密钥都不经过渲染层**：Pi 跑 **RPC 模式**（`--mode rpc`），提示词是 **stdin 上的
  一行 JSON**（`{"type":"prompt","message":…}`，`ai.rs` 的 `prompt_frame`）—— 它含中文与
  换行，走命令行必炸；提示词因此既不落临时文件、也不进参数。**一句一轮，写的是同一根 stdin**：
  第一句由 `ai_run` 起进程时写，之后每一句都是同一条命令（进程在就只写这一句，见下面
  「一个会话一个进程」那条）。密钥存在凭据管理器里，只在起进程时注入**环境变量**
  （命令行参数在进程列表里是明文）。
- **用户贴的图随这一句走**（composer 里 Ctrl+V，缩略图画在输入框上面、角上那颗 × 删一张，
  **点一下开 EP 的 `el-image` 查看器看大图** —— 56px 的缩略图连截图上的字都认不出；
  对话里那句气泡上的图同一套）：
  收的只有 `image/png` / `image/jpeg` / `image/webp` / `image/gif` 四种（`AI_IMAGE_TYPES`：
  Pi 能直接内联给模型的那几种，别的格式它会换成一句「图被略去」），一次最多
  `AI_IMAGE_MAX` 张。**它们与提示词进同一行 JSON**：`{"type":"prompt","message":…,
  "images":[{type:"image",data,mimeType}]}` —— 这是 Pi `prompt` 命令的形状
  （`ImageContent`，见它 rpc-types.d.ts），`data` 是 base64、**不带 `data:` 前缀**
  （渲染层从数据 URL 切出来，`aiImagePayload`）。**渲染层 → Rust 的字段名是 `data` /
  `mimeType`**（`ai.rs` 的 `ImageInput`），serde 认不出的键静默丢弃 ——
  与 `imageInput` 那次同一个坑，改名字要两边一起改并各留一条单测。**一张都没有时不发
  `images` 键**；`sending` 的判据是「有字或有图」（只贴图没写字的那句也发得出去，
  标题这时记成「（N 张图）」—— 标题空着等于「还没说过话」，那个会话下次打开就不读历史了）。
  **一句里带的图会随会话文件一起落盘**（Pi 自己存），读历史时由 `sessionMessagesToLines`
  把 `{type:'image',data,mimeType}` 换回数据 URL 画进用户那句的气泡里 —— 两处形状对不上时
  图会静静地不显示，所以这一条也有单测。**这套形状用假端点探针验过**（记录在
  [dev-notes/pi-session-probe.md](../dev-notes/pi-session-probe.md)：能看图的模型收到的是
  数据 URL 的图、不能看图的收到的是那句占位）—— 换 Pi 版本后照那份清单重跑。
- **贴图的前提是当前模型能看图**（`AiModelChoice.imageInput`，就是 models.json 里的
  `input: ["text","image"]`）：不能看图的模型，Pi 会把图换成一句「图被略去」的占位发出去
  —— 用户以为发过去了。所以挑中不能看图的模型时贴的图照收（别把用户刚贴的图丢掉），
  但**发送按钮按不动**：理由经 `blocking` 出现在它的悬停里（这一页不摆提示行）。
  格式不认的图在**贴进来那一刻**就拦下来说一句（`notifyWarning`）—— 那种 Pi 会转成 PNG
  或直接略去，不如当场说清。
- **提示词开头那行脚手架不进界面**：`taskPrompt` 造出来的提示词是
  「`你在下面这个目录里工作：<目录>` + 空行 + 用户原文」（`AI_PROMPT_PREFIX`），模型看见的
  就是这一整份、落盘的也是它；但**界面上只显示用户自己写的那段** —— 读历史时用
  `visibleInstruction` 把那行剥掉。不剥的话，用户会在自己的气泡里看见一句他从来没写过的话
  （踩过：一整条气泡里就那行最显眼）。改那行字面量要连着 `AI_PROMPT_PREFIX` 一起改。
- **会话留档由 Pi 写，落点由我们钉住**：起进程时传 `--session-id <会话 id>` 与
  `--session-dir <数据目录>/pi/sessions`（`ai.rs` 的 `sessions_dir`）—— **不传
  `--no-session`**（那是「跑完即弃」时代的写法）。一段对话一份
  `<时间戳>_<会话 id>.jsonl`，Pi 自己写、自己续；**默认落点是用户全局的
  `~/.pi/agent/sessions/`，必须用 `--session-dir` 拨到应用的数据目录下**（与
  `PI_CODING_AGENT_DIR` 同一条理由：自己的东西自己收着）。
  **续聊与「重启后还在」就是同一个 id 再起一个进程**（实测：进程杀掉后按同一个 id 重开，
  `get_messages` 读得回全部历史；杀在半路也不留半行坏数据），应用不自己攒上下文。
  **删会话**（`ai_session_delete`）认的是**会话文件首行的 header 里的 id**
  （`{"type":"session","id":…}`），不认文件名 —— 时间戳与目录分组是 Pi 的实现细节。
  删之前**先把进程收掉**（活着的进程还在往那个文件里写，Windows 上删不掉）。
- **打开会话要把历史读回来**：`get_messages`（RPC）→ `sessionMessagesToLines`
  （`shared/ai.ts`）→ 对话区。**只有活的进程才答得出来**，所以打开会话时先按空提示词起一次
  进程（`ai_run` 的 `prompt` 空串 = 只起进程），再问它要消息；读过的会话（`hydrated`）不再读，
  之后的对话由事件流接着往上接。系统消息与**成功的**工具结果原文整条丢掉（前者是提示词与工具
  清单、后者一次几百行），只留用户说的话、助手的正文与工具调用那几行；**失败的工具结果要留一行
  错因**（`isError`，原文就一句；重开会话时它没了，用户回头只看到一行「读取 …」）——
  与实时那条同一句话，共用 `failureLine`。
  **还没说过话的会话（标题为空）直接跳过这一趟**：没有历史可读，为它起一次进程等于白花
  一两秒（用户看得出来是「卡了一下」）。第一句发出去时进程自然会起来。
  Pi 起进程时那句 `Warning: No project session found with id …` 也是这么来的 ——
  **那是我们要求的**（新会话就是这么建的），别画进对话里（`shared/ai.ts` 的 `BENIGN_STARTUP`）。
- **一个会话一个进程**（进程会话 id 是 `ai:<会话 id>`，`workbench/ai.ts` 的
  `aiSessionProcessId`）：一轮跑完**不收进程**（上下文就在它那儿），所以同一个会话可以一句
  一句聊下去；**几个会话可以同时在跑**（`runs` 是一张按会话 id 分的表，界面一次只画一个）。
  模型 / 档位 / 权限这三样是**起进程时定死的**（`--model` / `--thinking` / 那份权限扩展加不
  加载）：改设置之后闲着的会话当场收掉、正在跑的等这一轮跑完收掉（`stale`），下一句按新参数
  重开、历史从会话文件接上。**别把「跑完就杀」写回来** —— 那正是「单次对话」的成因。
- **替 Pi 关掉它自己那三条出网旁路**：起进程时注入 `PI_TELEMETRY=0`、
  `PI_SKIP_VERSION_CHECK=1` 与 `PI_OFFLINE=1` —— 它默认会报安装 / 更新遥测、向 pi.dev
  查最新版本，**RPC 模式启动时还会去刷一遍模型目录**（print 模式没这一下，换到 RPC 才出现；
  实测关掉后真正的模型请求照常）。这三条不在任何已登记的出口里，
  **不许删**，删了就变成「应用替用户向第三方发请求」。
- **工具面全开，问不问由权限模式定**（`aiPermission`，composer 左边那一栏，形状与收敛在
  `shared/ai.ts` 的 `AI_PERMISSION_MODES` / `sanitizeAiPermission`，默认自动编辑）：
  `auto-edit`（自动编辑）时 `ai.rs` 会写一份 **Pi 扩展**（agent 目录下的
  `permission.js`，全文是 `ai.rs` 里的一个常量：`pi.on("tool_call")` 里对 bash / powershell
  调 `ctx.ui.confirm`，答否则 `{ block: true, reason }` 把这次调用挡回去）并以 `-e` 加载；
  `full`（完全访问）不加载任何扩展 —— **「不问」是「没有扩展」，不是扩展里判了一下**。
  **不再传 `-xt bash,powershell`**；命令跑起来之后「不碰这个目录之外的东西」不再成立
  （那是命令本身的能力），拦住它的是自动编辑那一问 —— 两档的差别只有这一件事，
  读写文件两档都不问。
  **扩展文件只在内容变了的时候重写**：好几个会话可以同时起进程，每次都截断重写的话，
  另一个进程可能正好在这会儿加载它、读到半份。
- **扩展问的那一句要能答得回去**：RPC 模式下 `ctx.ui.confirm` 是 stdout 上的一条
  `extension_ui_request`（`shared/ai.ts` 的 `parsePiConfirm`），确认条画在运行面板的对话
  末尾（`AiRunPanel.vue`），答复是 `{"type":"extension_ui_response","id","confirmed"}`
  （`confirmFrame`）经 `session_write` 写回**同一条 stdin**。确认可能同时压着好几条
  （一轮里的工具调用是并发的），`stores/ai.ts` 用队列排着，答的是按 id 认的那一条。
  **确认是排在那条会话上的**：切到别的会话去干别的，那一条还在原来那个会话的运行面板里等着
  （左栏那一行的小圆点表示它还在跑）。
  **别在扩展里做 print 模式的兜底**：`--print --mode json` 下扩展的 UI 是空实现
  （`ctx.ui.confirm` 一律回 false），命令只会被全挡掉 —— 要问一句就得跑 RPC。
- **一轮的结束判据是 `agent_settled`，不是退出码**：RPC 的进程跑完不会自己退（等下一条命令
  才动），收到那条事件就是这一轮完了（`stores/ai.ts` 的 `settle`）—— **进程留着**。
  退出码只在**没跑完**时才算数：我们让它停的（用户点了停止 / 换了参数）不算失败，
  它自己退的非零退出码要如实说成「这一轮没有跑完」。事件流本身与
  `--print --mode json` 是同一份序列化（Pi 里那个 `toJsonEvent`），画步骤那一套照旧。
- **要读结果的命令靠应答配对**：`get_messages` / `abort` 这类命令的应答是 stdout 上的
  `response` 帧，请求自己带一个 id、应答原样带回来（`shared/ai.ts` 的 `parsePiResponse` +
  `workbench/ai.ts` 的 `aiRequest`）。**配上对的应答不再当日志画**（读回来的数据不是给人看
  的）；超时与进程退出都当失败，一条等不到应答的命令不该把界面吊死。
- **模型请求由 Pi 自己发**（直连用户配的那个端点），这是第 8 条出口、且由用户显式开启：
  名称 / Base URL / API 形态 / 模型 / 密钥缺一样界面上就跑不起来（`canRun` 会拦）。注意
  **它在这个目录里读到的内容、以及这一段会话的历史都会发给那个端点**（聊得越久发得越多，
  这是「连续对话」的代价）—— 与天气的城市名同一条性质，文档里要如实写。
- **一个会话一次一轮**：同一个会话里跑着一轮时发送那颗按钮是停止，按会话挡重复提交；
  **几条会话可以同时在跑**（互不相干，`runs` 按会话 id 分开）。
  **停止走 RPC 的 `abort`**（进程留着、上下文留着、这一轮正常收尾），**应答没回来**
  （卡在某个请求上答不出来）再按进程树杀（复用 session.rs 的 `stop`）—— 那颗按钮什么时候
  都得有用。一轮跑完在对话末尾补一行**用时**（跑没跑完都补；被停掉的那一轮由 `finish` 补）。
  换过参数重开进程时，对话里先写一行「在哪个目录里工作」，**那条命令行（含 cli.js 的绝对
  路径与一串开关）收进这一行的悬停提示**（`AiLogLine.detail`）——摆在正文里只会把对话开头
  堵死；同一个进程接着聊时不必每轮都写一遍。失败要落成错误行，两处的原文来源不同：
  **模型侧的长在 message 的 `errorMessage` 上，工具侧的在事件 `result.content[].text` 里**
  （`tool_execution_end` 的形状是 `{ toolCallId, toolName, result, isError }`，**没有 `error`
  字段** —— 只认 error 会把「找不到 bash」「EISDIR」「ENOENT」显示成同一句兜底文案），
  多行的原文窄行里只留第一句、全文收进悬停（`AiLogLine.detail`）；
  **跑完但有报错时状态行不能装作顺利；顺利跑完则不留状态行**（跟用户说一句
  「跑完了」没有信息量）。
- **技能 = `--no-skills` + 逐条 `--skill`，两头合起来才成立**：Pi（0.87.1）自己有两条技能来路 ——
  显式的 `--skill <路径>`（可重复）与**自动发现**（`~/.agents/skills`、信任过的项目里的
  `.agents/skills`（还会顺目录往上找）、`<agentDir>/skills`、`<cwd>/.pi/skills`、package 与扩展
  带来的）。**自动发现那条必须关掉**（`--no-skills` / `-ns`），否则「关掉某个技能」只是界面上
  关掉，模型照样在提示词里看到它 —— 实测（拿内置 Pi 跑 RPC 问 `get_commands`）：
  只给 `--skill` 时 `~/.agents/skills` 里的技能仍在清单里，加上 `-ns` 才只剩给出去了那几条。
  于是这条链路上 **应用那份表是唯一真源**：起进程时 `ai.rs` 的 `run` 先加 `-ns`，再把开着的
  技能逐个 `--skill <目录>`（目录不存在就跳过、按整条路径去重、上限 200 条）。
  代价要如实知道：**用户在应用之外装给 Pi 的技能（`pi` 的 package / `<agentDir>/skills` /
  `<cwd>/.pi/skills`）在应用的会话里看不见** —— 想用就在这个弹窗里装一份。
  `--skill` 认的也是「一个目录 + SKILL.md」（认了就不往里递归），所以给的是技能目录本身、
  不是技能根；项目技能**不依赖「项目被信任」**（显式路径总是加载），这是它相对自动发现的
  另一个好处。
- **两条技能根，都是用户自己的目录**（`shared/pi-skills.ts` 是口径的唯一出处）：
  **全局** `%USERPROFILE%\.agents\skills`（Rust 的 `pi_skills::global_root` 探出来，跟着
  `ai_runtime` 回给渲染层）、**项目** `<会话工作目录>\.agents\skills`。一个技能 = **根下一个
  带 `SKILL.md` 的子目录**（与技能页同一份约定，**散在根上的裸 `.md` 不算**）。
  全局那份**与别的 agent 共用**（ZCode 这类也按 `.agents` 约定读它）、项目那份**就是技能页
  「安装到项目」写的那一份** —— 两处共用是有意为之（技能页装过去的技能，AI 助手页直接能用、
  也能开合），**因此别把这里改成「应用自己另存一份技能」**；也**不要**去写仓库 / 用户目录里的
  `skills-lock.json`（那是别的 agent 的账本，两边对不上是预期之内）。
  另外留意：`<cwd>/.pi/skills` 是 Pi 自己的默认约定，应用**不碰**它，也不承诺读它。
- **开关是「关掉的那些」，且只对下次起进程生效**：`aiSkillsOff`（键是「根 + 技能名」，
  `skillKey` 统一大小写与分隔符；收敛 `sanitizeAiSkillsOff`）存在工作台数据文件里，
  新装进来 / 别处放进来的技能默认就是开着的 —— **不要改成「登记开着的那些」**，
  那样每加一个技能都要应用替它补一笔。起进程时 `ai.rs` 只把开着的那些拼成 `--skill`
  （配合 `-ns`，见上一条：关掉的就是真的关掉）；一个会话的进程一轮跑完是**留着**的
  （见上面「一个会话一个进程」那条），所以装 / 卸 / 开关**对活着的进程不生效** ——
  界面上不解释这件事，也没有「结束它」按钮（2026-09-29 连说明一起删了）：要新技能表生效，
  就结束这段会话的进程再续聊（走 `ai.recycle` 的路子，等价于停止那一轮的进程树、会话文件不动）。
  别指望在运行中的会话上「热加」技能。
- **装进来的东西只落盘，脚本一概不执行**（`pi_skills.rs`）：zip 解包是手写的
  （中央目录 + deflate，压缩交 `flate2` —— 它已在编译图里，见 Cargo.toml），**条目名逐段
  过 `sync::is_plain_segment`**（挡 `..` / 盘符 / 通配字符）并跳过符号链接条目，
  解到 `<根>/.tmp-…` 再整棵改名过去（同盘改名是原子的，半路失败不留半个技能）。
  上限：包 64 MB、解压后 256 MB、4000 个条目，不支持 zip64 / 加密包 / 非 deflate 的压缩
  （遇到说清楚，别硬猜）。没有 `SKILL.md` 的包不是技能包。**「导入目录」也不碰 git**
  —— 技能页那条「从文件夹导入」会在技能库所在的仓库里提交一次，而这两条根是用户自己的目录
  （项目那份多半就在他的仓库里）：替他提交不是这个应用该做的事。
- **输入框里那条 `/skill:名字` 必须摆在提示词最前面**：Pi 只在文本**开头**认它
  （`_expandSkillCommand` 一来就 `startsWith('/skill:')`，一次一条，名字取到第一个空白为止），
  而应用的提示词本来以「你在下面这个目录里工作：…」开头 —— 所以 `taskPrompt`（shared/ai.ts）
  在指令以命令开头时把脚手架**挪进命令的参数位**（展开出来正好是「技能全文 + 目录说明 +
  用户写的话」），`visibleInstruction` 对称地还原（**技能名留着**：那是用户自己的选择，
  屏幕上要看得见；脚手架去掉），`aiSessionTitle` 把命令剥掉当标题。
  **别把命令插到中间**（比如「用技能 /skill:x 干这个」）—— 那样 Pi 不认，整条命令会
  原样发给模型当普通文本。
- **装技能这条出口**（第 9 条，见 AGENTS.md 第 1 节）：只有「粘地址」这一种安装方式出网 ——
  地址由用户粘、点「装上」才走一次 GET，**主机不设白名单**（与「用户自己填的 git 仓库」
  同一类），跟着 `Location` 跳最多 5 跳（技能市场那条链是 302 → 对象存储直链），
  只收 zip、超过 64 MB 就停（`http::request_url_limited` —— 默认那个 8 MiB 的阀门是给
  JSON 用的，**别把它调大**：它是所有出口共用的上限）。导入本地 zip / 导入目录、装卸开关、
  `--skill` 注入全在本机，一次网都不出；除了那个地址本身，这一趟不带任何用户数据。
  http.rs 因此多了两样东西：响应里的 `location`（**它不跟重定向，跟不跟由调用方定**）
  与 `request_url_limited`。
- **索引重建归应用**：`kb.rs` 的 `index_build` 是知识库 `kb/_catalog.md` 与 `index/index.json`
  的唯一生成者（仓库转纯数据后没有别的生成者），格式与既有生成物一致（含 CRLF 换行、
  那个「请勿手改」的文件头与 JSON 的键顺序），`generated_at` 由渲染层按本机时区算
  （`shared/kb.ts` 的 `todayIsoDate`）。改输出格式只改 kb.rs 一处，内容断言在 kb.rs 的
  测试里。**别把索引交回给 Agent**：命令现在是能力之一，但索引仍归应用自己重建
  （它要的是「谁跑的结果都一样」）；清洗（知识库页那条线）的提示词同样明令 Pi 不碰生成物。
- **明确不做**：订阅登录（要走 Pi 自己的 `/login`）、云厂商的原生协议（Bedrock / Vertex / Azure ——
  那几家的鉴权要装回各自的 SDK，与瘦身冲突）、**拉 models.dev 的目录**（不新增出网与
  数据源：模型清单由端点自己报；能力默认值只认**随包 Pi 自带的那份目录** —— 同一个
  钉死包里的东西，vendor 脚本顺手剪出来，见上面「四层」那条）。
  **会话续跑已经在做**（会话文件 + 同一个 id 再起进程，见上面「会话留档」那条），
  但**不做的**是：会话改名（标题取第一条指令，之后不改）、跨目录搬会话（Pi 按目录分组，
  搬了等于换一段对话）、`/tree`、`/fork`、`/clone` 那些 Pi 自己的分支玩法 ——
  要在界面上做就得把 Pi 的会话树整套搬过来，现在只做「一段对话接着聊」。
