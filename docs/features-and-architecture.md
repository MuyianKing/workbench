# 功能与架构

本文件是 Workbench **当前功能与架构事实的唯一真源**：[README.md](../README.md) 只给一个概览，
细节（每一项功能为什么这么做、踩过哪些坑、数据落在哪）都在这里。改功能或调架构时更新本文件；
动手方法与施工记录放 [dev-notes/](dev-notes/)，工程约束放 [AGENTS.md](../AGENTS.md)。

## 功能

**导航与页面**

- 窗口分两层：顶部一条通栏（标题栏 + 欢迎语）横跨整个宽度，它下面才是「左侧导航栏 + 内容列」。
  导航栏 88px，做成一张**卡片**浮在画布上 —— 和首页那些面板同一副外壳（同样的圆角与投影，
  底色浓度跟着设置里的「卡片不透明度」走），四周留出与卡片之间一致的间距，高度贴着内容，
  菜单多起来时自己撑高。终端留在内容列里，不横跨导航栏
- **弹层开着时导航栏照样点得到**：弹层的遮罩铺满整窗，导航栏因此抬到它之上
  （`z-index` 取 int32 上限 —— Element Plus 弹层的层级是 2000 起步、每开一个弹层 +1 的动态值，
  写个「比 2000 大」的常数迟早被追平，只有上限追不上）。**换页不收弹层**：弹框留在原地，
  切走再切回来还是它，填到一半的输入不丢 —— 弹层挂在 `body` 上、不随页面隐藏，所以它是
  「跟着你看」而不是「跟页面一起收起来」
- **填内容的弹层不挡背后**（[AppDialog.vue](../src/renderer/src/components/AppDialog.vue) 的 `penetrable`）：
  密码、工作记录、命令、常用软件、添加项目、起名字、素材管理这几个弹层，遮罩只围住弹框自己 ——
  典型场景是「添加密码」时密码散落在笔记里：切到笔记页选中复制、切回来粘进弹框，全程不用关弹框。
  确认框（`ElMessageBox`）与退出确认框仍然挡住背后（那是个必须看见的决定），设置 / 技能这类
  不抄内容的弹层也照旧挡点击。**所有弹层都走 AppDialog**：`append-to-body`、这一条「挡不挡背后」
  与「可拖动」都只写在那个组件里，新增弹层时不必（也不该）在调用处重复
- **弹窗可以拖**（抓手是标题栏，`AppDialog` 统一开的）：填密码这类场景里把弹框拖开一点，
  被它压住的正文就露出来了；关掉之后位置复位 —— 拖动是这一次会话里的事，下次打开还是居中的那一份。
  头部被 CSS 藏掉的弹层（技能详情那种自绘头部的）拖不了
- 当前页只是 store 里的一个 id（取值登记在 `src/shared/views.ts`），**不引入 Vue Router**：
  换页就是换这个值，`App.vue` 用 `<KeepAlive><component :is>` 渲染，各页的滚动位置不会在来回切时丢掉；
  当前页随数据文件落盘，重启回到上次那一页。新增一页 = 登记 id + 挂组件两处
- 现在六页：**首页**（可自由布局的卡片画布）、**项目**（项目卡网格 + 分组筛选工具条）、
  **工作**（工作日志时间轴）、**笔记**（左目录树 + 右 markdown 编辑器）、
  **技能**（技能库管理，见「技能」一节）与**密码**（密码保险库，见「密码保险库」一节）。
  布局编辑态由顶栏那颗「编辑布局」进入（它只在首页出现），进入后欢迎语那一行原地换成操作条
  （布局编辑提示 + 恢复默认 / 完成）—— 行高不变，画布不会上下跳。那行提示是**不换行**的一句，
  窄窗口下必须让位给右侧按钮而不是把顶栏顶宽：`.app` 与 `.topbar` 的列定义都带 `minmax(0, 1fr)`，
  `.header` 带 `min-width: 0`，提示自己 `min-width: 0` + `overflow: hidden` + 省略号 ——
  这条链上少一环，窗口一窄整条顶栏就横着溢出窗外，右侧那几颗按钮跟着被推出去点不着
- **导航栏显示哪几页可以在设置里配**（设置 → 菜单那一屏）：存的是「关掉了哪些」
  （`AppSettings.hiddenViews`，空数组＝五页都在）。存这一侧而不是「显示了哪些」，是为了将来加一页时
  老配置里没有它、新页对所有人默认可见，不必去动谁的数据文件。三条约定：
  **顺序永远是 `VIEW_IDS` 的顺序**（关掉哪几项不影响其余项的先后）；**至少留一页** ——
  全关掉的补丁在 `sanitizeHiddenViews` 里被拦下（留下首页），设置界面上最后一颗开关是禁用的，
  否则界面上一个入口都不剩；**关掉只是从导航栏收起来，不是删掉这一页** ——
  当前页被关掉时退到第一页可见的，而用户主动的切页照旧过得去
  （那条 watch 只认「关掉的清单变了」，不认当前页变了，见 stores/projects.ts）
- 这一项住在 `theme.json` 里（与明暗、布局同属「界面长什么样」，见下），同步时跟着整份配置一起到
  另一台机器；而「上次停在哪一页」的 `activeView` 留在数据文件里 —— 那是机器状态，不是配置

**首页**

- **「认得你」的那行话住在顶栏**（标题栏下面那条通栏的左侧），下面才是工作区画布与九块卡片。
  这一行的位置原来归全局搜索，搜索移除后由它顶上 —— 首屏第一眼先是这句，首页画布整块让给卡片。
  这一行的「认得你」段落在：按时间段的称呼（早 / 中午 / 下午 / 晚，23 点到 5 点说「夜深了」），
  称呼后面跟着**设置里的程序名称**（「晚上好，MUYIAN」，与标题栏同一个值 —— 那是你给这个程序起的名字，
  取它是因为它一定有值，不会因为没登录就少半句），
  中间是几条**从本机数据里现取的实话** ——「2 个项目在跑 · 今天 12 次执行 · 连续 9 天」，
  **这里不放头像 / 昵称**（曾经放过，已去掉：它就在顶栏那颗头像的旁边，同一个账号在一条横线上
  画了两遍，看着像画重了 —— 身份那一层归右上角那颗头像，这一行只说事情）。四条约定：
  **只说非零的**（「连续 1 天」不显示，那只是第一次用，摆出来像自我表扬）；
  **深夜那份多一个「还」字**（凌晨两点看到「2 个项目还在跑」才是此刻真要知道的那件事 —— 有些东西忘了关）；
  **一行文字都不发 IPC** —— 用到的数都已在 projects / settings 两个 store 里（在跑的项目数、今天的执行次数、
  连续天数、程序名称），而这一行是首屏的一部分，不值得为它多等一轮往返；
  **不打招呼、不问好、不鼓励** —— 那些在这个应用的语气里是噪音（见 [AGENTS.md](../AGENTS.md) 的「如实说明」）。
  一个项目都还没有时它换成「还没有项目。加一个之后，这里会记下每天的动静。」，
  免得首屏是一句干瘪的称呼加九张空卡片
- 那一行里的连续天数走 `shared/activity.ts` 的 `streakOf`（单独导出就是为了它）：只取这一个数，
  不必为它把整张 371 格的日历铺一遍（活跃度图那边才需要整张）
- 首页是**一层工作区画布 + 九块可自由布局的卡片**：活跃度、Coding 用量、系统状态、我的项目、
  快捷操作、快捷启动、命令、今日完成、AI 热点。布局是**两层**的：**栏 → 行 → 卡片**。
  栏数、行数都不写死（默认三栏九行；栏 1 ~ 6 栏随便拆）：栏宽要么是一个像素值、要么是「自适应」
  （与其余自适应栏平分剩余宽度），行高同样是固定像素 / 自适应两种（自适应行吃掉所在栏剩下的高度）；
  一行里的卡片**横向平分这一栏的宽度、高度跟着这一行走** —— 于是「中栏上面一张宽卡、下面三张并排」
  这种摆法也表达得出来（布局落在 `theme.json` 的 `columns` + `cards`，行住在栏里）
- **拖卡片的落点是两维的**：落在某张卡片的**上 / 下缘**＝在那一行旁边另起一行（新行跟着这块卡片原来那一行
  的高度与模式走 —— 换个地方，大小不变），落在**中间**＝并进这一行、按左右半区换位。
  所以不必另设「拆行」按钮：想分出三张并排的卡片，把它们依次拖到第一张的中间即可。
  **行不留空**：一行里最后一块卡片被搬走时那一行就没了（`pruneEmptyRows`），一栏总留一行当落点
  —— 否则摆几次就会攒出一串空槽，而空槽平时不渲染、编辑态又没有删除的入口，用户根本收拾不掉
- **拆栏 / 收栏都在编辑态**（首页顶栏那颗「编辑布局」）：每一栏顶上有一条栏头 —— `＋` 在它右边拆出一栏
  （宽度跟着被拆的那一栏：自适应拆出自适应，两栏平分剩下的宽度）、`✕` 收掉本栏（栏里的卡片按原顺序并到
  相邻那一栏；只剩一栏时按钮禁掉）、中间那颗在「自适应 / 固定宽度」之间切换（切固定时取它此刻的显示宽度，
  所以切换前后那一栏看起来不动）。**拖的是两栏之间那条缝，不是某一栏**：一条缝一颗手柄，
  挂在它左边那一栏的右边界上，往右拖就是这条边界往右移 —— 两边都是固定宽度时**两栏一起改**
  （左 +dx、右 -dx，宽度之和不变），只有一边固定时只改那一栏（自适应那栏是「剩下的部分」，
  自己会让位）。这样不会有「一栏左右各一颗手柄」的歧义，也不会有哪一栏轮不到手柄
  （最后一栏就靠它左边那条缝：往左拖，它变宽、左边那栏变窄）。两边都是自适应的缝没有手柄
  —— 拖它谁也改不了（想让某一栏能拖，先点栏头那颗把它钉成固定宽度）。**编辑态每栏还画一个底**（虚线框 + 淡底），
  边界一眼看得见；正在拖的那一栏换成实线框、底色深一档，改的是哪一栏全程亮着。
  栏头只在编辑态出现，平时每栏就是一个紧贴画布的列
- **行的高度是行自己的**（`HomeRow.mode` / `HomeRow.height`：行右上角那颗药丸切固定 / 自适应、
  下缘中间那颗把手拖动改高度）：一行里几张卡片必然等高，否则并排起来高矮不齐。
  行的高度下限取行里最高的那条卡片下限（`rowHeightMin`，比如一行里放了 Coding 用量就至少 160）——
  卡片挪进一条比它下限还矮的固定行时行高会被提上去，下限之外再由 `min-height` 兜着
- 栏 id（`col-1` …）与行 id（`row-1` …）都是稳定、无意义的引用，**行 id 全局唯一**：
  卡片靠 `CardPlacement.row` 认自己在哪一行，它在哪一栏由行反查（`columnOfRow`）——
  拆一栏、收一栏都不会让别的卡片跟着换地方（新栏 / 新行取第一个没用过的 id）；
  `HomeColumn.width` 为 `null` 就是那栏自适应
- **显示哪几块卡片也可以在设置里配**（设置 → 菜单 → 首页那一页下面挂着的九块卡片）：
  每块卡片带一个 `hidden`（`CardPlacement` 的字段，缺省是开着的），关掉就是**不画**这一块 ——
  `visibleCardIdsInRow` 把它滤掉，一行因此空掉时整行不渲染、一栏里一行都不剩时整栏不渲染
  （与「空栏不渲染」同一条规则）。它那一行与行内位置都留着，再打开时回到原处，
  而不是被塞回默认位置；编辑态也不画关掉的卡片，免得摆位摆到一块自己看不见的卡片上。
  与导航菜单同一条下限：**至少留一块**（全关掉时第一块会被放开），首页不会出现一整片空白
- 默认布局（按当前配置固化，三栏：373 固定 / 自适应 / 345 固定）：第一栏自上而下是活跃度、快捷启动、
  系统状态、快捷操作、命令五张定高卡，最底下「今日完成」吃掉这一栏剩下的高度；第二栏整栏给我的项目
  （里面排的是整张项目卡，宽度富余时最好读）；第三栏上面是吃剩余高度的 Coding 用量，下面是 **AI 热点**
  （固定高度，条目多了在卡内滚）。**活跃度图** —— 照 GitHub 贡献图的样子，一列一周、53 列铺满一年，
  格子的深浅是当天执行了多少条命令；悬停看当天次数，下方一行是连续 / 最长 / 活跃天数与单日峰值。
  **默认布局是一张卡片一行** —— 升级过来的老布局也一样（见下面的版本那条），行这一层平时是看不见的，
  只有当用户把两张卡片拖进同一行才并排起来
- **AI 热点**卡片：热点源的**合并列表**，一条一行（标题 + 来源），点击跳原文。数据住在本机
  `ai-news.json`（**只在本机、不进同步仓库**，与工作日志同一待遇）。
  **源清单是一份内置白名单**（Rust 侧 `ai_news.rs` 的 `SOURCES`，经 `ai_news_sources` 命令交给适配层），
  **只放中文源**，现在只有量子位（RSS，3 小时一次）。这张卡片挂在中文界面上，混进英文标题读起来是
  两种东西 —— 曾经有过 Hugging Face 每日论文、arXiv cs.AI 两个英文源，以及一个要用户自己填 token、
  配额很紧（实测第二次请求就 429）的机器之心，都已按要求撤掉；解析器里 `atom` / `json-hf-papers`
  两个分支留着，是「将来加非 RSS 源」的扩展点（见 [shared/ai-news.ts](../src/shared/ai-news.ts)）。
  白名单放在 Rust 侧是有意的：渲染层只能报源 id、**拿不到任何地址**，联网边界因此收得住。
  **看或不看热点就是这张卡片在不在首页上**（设置 → 菜单 → 首页那一页下面的 AI 热点），
  卡片不画就不取 —— 没有「勾哪几个源」这一层设置。
  每个源**各自睡眠、各自退避**：状态按源分开存（`etag / nextFetchAt / failCount / lastError / items`），
  一个源被限流或挂掉不影响别的源，也不会把已经拿到的内容清掉；界面看到的是合并视图
  （只并清单里的源、按链接去重、按时间从新到旧、截断到 40 条）。
  刷新只处理**到了它自己刷新间隔**的源，并发拉取、带 `If-None-Match` 条件请求，
  429 / 网络失败走指数退避（5 分钟起、2 小时封顶）。
  卡片先读缓存摆出上次内容、再按策略后台刷新；某个源失败时其它源的内容照旧显示，
  失败原因逐条落在卡片底部一行小字里（`refreshAiNews` 返回的 `notes`）。
  **行里只放「每行都不一样」的东西**：标题与发布时间（今天给 `HH:mm`、更早给 `MM-DD`）。
  来源名只在**这一屏真的混着多个源**时才出现 —— 只有一个源时它十行都是同一个词，
  既白占本来就不够的标题宽度、又会被挤成「量…」（第一版就是这么难看的）；
  那一列 `flex-shrink: 0` 永不收缩，让位的是标题。页脚同理：只有一个源时不写「1 个源」。
  列表滚不到底时末行从底部渐隐（滚到底就把渐隐摘掉，最后一行因此不会被压暗）
- **点一条是在应用内读，不是跳浏览器**（`components/NewsArticleDialog.vue`）：这些源的 RSS 只给标题、作者与
  一句导语（量子位的 `description` 只有十来个字、`content:encoded` 是空的），正文得去原文页拿。
  所以点一行会开一个阅读弹层：Rust 按 **`article_hosts` 域名白名单**抓那篇原文（只认源站自己的域名与子域，
  `www.` / `pro.` 都算；非 https、非默认端口、白名单外的一律在发请求之前拒掉，实测 `evil-qbitai.com` 这种后缀伪造也拒），
  正文提取在 `shared/ai-news.ts` 的 `extractArticle` 里做 —— 删掉脚本 / 样式 / 注释，**按容器定位正文**
  （认 `article` / `entry-content` 那类类名，配平标签取子树；真实页面的「相关阅读」「热门文章」都在正文容器之外，
  靠文字分界去切会漏），再按段落取文本；产出是**纯文本**，页面脚本不执行、也不当 HTML 渲染。
  提不出正文（会员专属、脚本动态渲染）或抓取失败时**如实降级**：显示标题 / 来源 / 时间 / 导语 + 「在浏览器中打开」，
  而不是空白页。正文过长会截断并说明。抓取只在点开某一条时发生，同一篇文章再次打开用内存里的结果，关掉即丢
- 第二栏**原先是项目列表**：它搬去项目页之后那栏空了出来（空栏不渲染，默认会变成两栏、中间空一大片），
  所以把两张大图挪了进来
- **我的项目**卡片（id 仍是 `recent` —— 改 id 会让老布局整份回到默认，见下面那条）：
  **只画勾了「在首页展示」的那些项目**（`Project.home`）—— 首页是一份挑出来的名单，
  全量列表在项目页。三处开关：添加项目时勾、项目卡「⋯」菜单（在首页那张卡上点它就是把自己撤下来）、
  详情抽屉「基本信息」；老数据与没勾的一律不展示。顺序取**项目页的展示顺序**（`orderedProjects`），
  不是最近使用时间 —— 后者每启动一次就让卡片跳一次位置。
  **一个项目就是项目页上那张项目卡** ——
  启动 / 停止 / 打包 / 检测 / 安装与「⋯」菜单都在卡上，接着上次的活干不必先跳去项目页。
  排布跟着面板的实际宽度走：`auto-fill` 网格，下限取项目页那个 302px（它同时也是项目卡的设计宽度），
  栏宽拖宽了就多排一列，拖到 302 以下由卡片自己换行（操作行与元信息行都是 `flex-wrap`，
  项目页里因为网格下限就是 302，永远走不到这一档）。**这张卡不画面板壳**：没有标题行，
  底衬 / 边框 / 内边距一概不画，卡与卡之间只留一条「卡片间距」（设置里那个），
  整块看上去就是几张项目卡直接摆在画布上；高度下限也因此跟别的卡片同档（100px），
  拖矮了剩下的自己滚。**滚动条槽也不占**（`scrollbar-width: none`）：全站滚动条是「槽宽照旧占位、
  轨道透明」的 10px（见 global.css），别的面板有底衬兜着看不出来，这张卡没有底衬 ——
  槽里露出的就是画布，卡片看着就没排到本栏右缘。**空状态分两种**：一个项目都还没有时仍旧是
  「还没有项目」，有项目但一个都没勾时指路「在项目卡的「⋯」菜单或项目详情里打开「在首页展示」」——
  否则用户对着这张卡只会以为它坏了
- **今日完成**卡片：今天**标记为「已完成」**的工作记录，一条一行 —— 项目标签（实心标识色，
  与工作页时间轴上那枚同源）+ 正文去掉 markdown 标记后的一行（写长了截断，悬停看全文），
  标题右侧是本日条数。待办是还欠着的、别的日子也不算，都不进来。数据就是本机 `work-log.json`
  那一份（**不同步**，见「工作日志」），卡片**只读不写**：记一条、改内容都在「工作」页，
  切回首页时重读一次；点一行即跳到「工作」页看全貌
- 卡片清单变过（`theme.json` 里带 `version`，认版本不认「有没有哪个字段」）：v1 → v2 移出了「项目列表」，
  版本对不上就整份回到默认布局。代价是**自己摆过的位置会重置一次** —— 老布局里那张卡所在的栏会空出来，
  而空栏不渲染，剩下的栏会挤在左边、右边空一大片，比丢掉一次摆放更难看。
  后来加的 `hidden` 字段没动版本号：老文件里没有它，`sanitizeCardPlacement` 当「开着」处理
  （判据是「加一项能不能由默认布局补出来」，见下面 v4 那条）
- v2 → v3 换成可拆分的栏清单，这一次**不重置**：固定的左中右三栏能一字不差地翻过来
  （`migrateLegacyLayout`：`left / center / right` → `col-1 / col-2 / col-3`，左右两栏的宽度各归各栏、
  中间那栏仍是自适应），用户摆过的位置与调过的栏宽都留着
- v3 → v4 加出「行」这一层（见上面那条），同样**不重置**：老的一维布局按**一张卡片一行**铺出来
  —— 每块卡片自己那份高度模式与高度交给它新得到的那一行，所以升级后看起来一模一样
  （一行一张卡时，行高就是原来那张卡的高度），栏宽与摆放都留着。两处容易踩的：
  **迁移给老文件里没提到的卡片补顺序时，用的是它在默认布局那一栏里排第几**（`defaultRankOf`），
  不是照搬新结构里的 `order`（那已经一律是 0 了，照搬会让我的项目掉到系统状态后面）；
  **行 id 顺着列出来**（左栏六行、中栏一行、右栏两行），认不出来的老文件整份回默认布局时
  靠的就是这个顺序与 `DEFAULT_THEME` 的编号一致（`sanitizeTheme(null)` 必须等于默认布局）
- 「加一块卡片不必动版本号」这条对 v4 依然成立：老文件里缺的那块由默认布局补上 ——
  它在默认布局里那一行还在就用那一行，否则在它默认那一栏的末尾新开一行（`pickRow`）
  —— 用户摆过的位置一并留着。只有「把某块拿掉」、以及**改布局结构本身**才要动版本，后者照上面的例子补迁移
- 跨机器同步的那份配置认版本（见 `shared/sync-config.ts`）：仓库里那份版本对不上（还是 v3 及更早）的话，
  设置里会显示那台机器没有可用配置 —— 它按自己的节奏推一次新版本就好了，不会把老结构套到本机
- **Coding 用量**面板：读取本机 AI 编程工具（ZCode、DeepSeek Harness、CodeBuddy、WorkBuddy、Qoder）的
  本地用量数据，展示 今日 / 本周 / 本月 用量、趋势条形图（悬停一行一个口径：输入给出「缓存命中 / 全部输入」
  与命中率，再是输出、思考、请求次数），以及模型与工具占比。
  **计数分两个口径，标题行右侧的分段控件切换**（`UsageAxis`，一次只画一个）：
  `tokens` 是 token 计数（ZCode / DeepSeek Harness / CodeBuddy / WorkBuddy 这四个来源），
  `credits` 是按额度记账那类工具扣掉的额度（目前只有 Qoder）——
  两者量纲不同，既不能相加也不能画在同一根轴上。切口径即换一整套数字，窗口按新口径重新收敛
  （有数的那几天不一定一样），选中的柱子与展开的行一并作废；
  credits 那边不画模型占比（Qoder 的会话里模型名只有上游的内部别名 `qfmodel`，拆了看不出东西），只留工具占比。
  趋势窗口由头部的时间维度下拉给出（照 DeepSeek 用量页的做法）：
  近 7 天 / 近 30 天 / 本月 / 上月 四档预设直接定窗口（默认「本月」，按钮上只写当前档位），
  选「自定义」会在同一个面板右侧展开双月日历，第一下定起点、第二下定终点，定完即时生效；
  预设都按「今天」解析，跨过午夜自己跟着时钟走，可选的日子就是当前口径下有记录的那段（范围外的日期置灰）。
  下拉右边那行小字是实际生效的起止日 —— 快照不够长时预设会被收敛到最早那天，以这行为准。
  右侧 天 / 周 / 月页签只切换柱子的分桶宽度，窗口本身不变；柱子最宽 10px，窗口短时不会长成一块块方砖。
  模型 / 工具占比默认统计整个窗口，点击某根柱子则只统计那个天 / 周 / 月，再点一下回到全部。
  用量快照按天聚合后落盘 `token-usage.json`，上游清理旧会话或日志也不丢历史；
  某个工具读取失败时只对它提示原因，其余工具与快照照常展示。
  **打开程序先出上次的数据**：先读本地那份快照（含上次同步取回的别的机器的用量，几毫秒）摆出来，
  再实读覆盖它 —— 冷读一轮要一秒上下（要重新解析各工具的日志与会话），
  没有这一步的话这段空窗只能显示「暂无记录」，有数据的人会以为自己的记录丢了。
  ZCode 读它的本地 sqlite；DeepSeek Harness 读 `~/.dsh/sessions` 的会话文件（多帧 zstd，
  Rust 侧逐帧解压后交给渲染层解析）；CodeBuddy 没有落地用量库，解析它 IDE 扩展日志里的逐步 usage 记录
  （模型从请求链路反推）；WorkBuddy 读 `~/.workbuddy/projects` 下的会话正文，每次调用的用量就写在那一行里
  （带模型名，不用反推）；Qoder 读 `~/.qoder-cn/projects`（国际版是 `~/.qoder`）下的会话正文，
  取每条 assistant 事件的 `usage.credits`。五个来源都只取用量数字，日志与会话正文不进快照。
  **Qoder 只有额度、没有 token**：它的客户端不产生 token 计数（会话文件与 CLI 日志里的
  `input_tokens` / `output_tokens` 恒为 0，它自己的上下文快照里也写着 `tokenCountsAvailable: false`，
  用量面板是回头去问服务端的），所以这个来源只出现在 credits 口径下，tokens 口径下整个不出现
- **Token 用量可以在多台机器之间同步**（默认关闭，且**要先登录账号**）：登录之后在设置里填一个
  git 仓库地址，每台机器各自把
  **自己那份用量快照**推到仓库的 `token-usage/<设备id>.json`，读的时候把各台机器的合起来算。
  **没登录就没有同步**：读数只认本机，别人机器留在本地克隆里的分片也不参与合计 ——
  登录是同步的入口（推送用的凭据来自账号）。设置里填过的仓库地址不会因为退出登录而丢掉，登录回来接着用。
  一个设备一个文件、每个文件只有一个写者，所以永远不会有同文件冲突，也不需要人工合并；
  分片内部沿用「取较大者」（抗上游清理旧会话），分片之间**相加**（两台机器同一天的用量是两笔独立消耗，
  取最大值会把另一台整个丢掉）。面板标题行右侧那行小字说明状态（更新于 / 同步失败），悬停能看到
  已经合进来的设备；开了同步之后标题行多一个同步按钮，点一下立刻同步，平时在后台**每 1 小时**自动同步一次（按小时计的是「推送」的节奏：分片一变就推，
  十分钟一推会让仓库里堆出一串没有信息量的提交），
  内容没变化的文件不会产生提交（不会往仓库里堆空提交）。**同步不挡出数**：取数只读本地
  （含上次同步留在克隆里的别人的文件），首屏先出来；「推 + 拉」那一段在后台跑，跑完面板会自动再取一次，
  别人机器的新数据随即补上 —— 只有手动点的那次会等结果，因为按钮要给出成功 / 失败的提示。
  同步只发往你给的那个仓库，凭据默认用**登录账号**的 token（按 host 限定注入请求头，见下），
  私有仓库因此不必先手工配凭据；把它关掉则退回系统里 git 自己配好的那套 —— 那条退路针对的是
  token 过期 / 被撤销，不是「没登录也能同步」。
  **改了地址不用手动清理**：下一次刷新就按新地址同步（不必等自动同步的间隔），本地那份克隆会重新拉，
  读的时候也核对克隆是不是指向当前这个仓库 —— 换了仓库却还在读上一个仓库的数据，是踩过一次的坑。
  **仓库结构是「一个功能一个目录，一台机器一个文件」，两个目录是两条互不相干的出口**：
  `token-usage/` 放各机器的用量快照，`config/` 放各机器的外观配置（就是那份 `theme.json` 的整份副本，见下一段）
- **外观配置走同一个仓库，但在另一个目录、由另一个按钮推**（`config/<设备id>.json`）：
  设置 → 外观最上面那块「从别的机器取外观」旁那颗「同步一次」把本机 `theme.json` 整份推上去，
  并把别的机器的新配置读回来 —— 明暗、主题色、主题色文字、顶部样式、
  卡片不透明度、终端高度、程序名称、工作区背景、**导航菜单显示哪几页**、**首页布局**与
  **笔记页左栏宽度**都在里面。
  **这个动作只有手动那一次**：面板上的同步按钮与一小时一轮的自动同步都只推 / 拉 `token-usage/`，
  一次都不碰 `config/` —— 用量是只增的计数，自动来回推没有副作用；外观是「以谁的为准」而不是能相加的数据，
  自动推只会往仓库里堆没人要的提交，两台机器互相采用对方的那份更是会来回覆盖、永远收敛不了。
  换了机器或重装之后，在设置 → 通用 → 账号里填上同一个仓库地址，再到设置 → 外观点一次「同步一次」，
  那一屏的「从别的机器取外观」就会列出仓库里有文件的机器 —— 本机自己也列出来（标「本机」，
  它那份照常可「应用」，相当于取回上次推送时的外观），其余是别的机器
  （各自写清那份配置的时间），点「应用」就把本机的 `theme.json` 换成那一份；本机自己那份仍留在仓库里，
  随时能再取回来。采用**只能手动**：自动同步不替用户做这个决定。
  本机才成立的项刻意不进这个文件：开机自启、全局快捷键、数据目录、Token 同步仓库地址、
  终端收起后那颗悬浮按钮的位置（`terminalButtonTop`：它落在屏幕哪一处只对这台机器成立）各留各的
  （把仓库地址同步过去，等于让另一台机器往一个它没填过的地址推东西）；项目列表、快捷启动、独立命令
  那些带本机路径的数据同理，那是另一份东西；「上次看的那一档」那几项（项目排序、工作页范围与维度、
  目录树摊开的层数）也一样 —— 那是**这台机器上的行为习惯**，同步过去只会把另一台机器上正看的东西顶掉
  有一处如实说明的代价：配置是整份复制的，所以对方若是用**它本机磁盘上的一张图**当工作区背景，
  这个路径会跟着过来、在这边读不出来 —— 界面会照实显示「图片读不出来」，重新选一张即可
  （内置壁纸没有这个问题，它在两台机器上指向同一张随包发布的图）
- 面板按剩余高度铺开：项目少的时候下面不再是大片空白，窗口越高面板越舒展
- 一个项目都没有时，**项目页**换成欢迎页：上手三步 + 本机运行环境 + 快捷操作，而不是一个孤零零的按钮
- 工作区背景可以放一张图，也可以只用蒙版定个底色；它铺满整个窗口，顶栏与导航栏按「顶部样式」三档决定怎么让壁纸透上来

**快捷启动（常用软件）**

- 首页的**「快捷启动」卡片**（可拖到任意一栏），和其余面板同一副外壳，点图标即启动——和项目不是一回事，Workbench 不接管它们的进程（没有日志、没有停止，退出应用也不会连带结束）
- 面板标题固定，程序按可用宽度**自适应换行**；超过两行就在面板内部滚动，不会越撑越高
- 「添加软件」直接挑程序：对话框默认从**开始菜单**打开（常用软件的快捷方式都在这儿），支持 `.exe`、`.lnk`、`.bat` / `.cmd`
- 图标取系统的真实图标（不落盘）：**快捷方式会先解析到它指向的真正程序再取图标**，不会只拿到快捷方式那个通用小箭头。解析走 `.lnk` 里那段 IDList（交给 `SHGetPathFromIDListW` 解释），不重写一遍快捷方式的文件格式；解析不出来（目标已卸载、指向 UWP 应用）时退回 shell 画的那张 32px 通用图，总比界面上只剩一个首字母强。程序自己有 48px 图标资源时一律从资源里直取，不经过 shell 的图标缓存
- 只填「程序 + 名字」两项：启动、参数、工作目录一律交给系统按该程序的关联方式处理（快捷方式里自带的参数与工作目录照旧生效）
- 一个程序都没加时面板里只留一个「添加软件」块，任何状态下都能找到入口
- 排列顺序靠拖动，删除 / 编辑收在卡片右上角的「⋯」里；程序被移动或卸载后卡片标「失效」并给出原因，编辑一下换新路径即可
- 同一个程序可以加两次（比如 VS Code 一条带 `--new-window`），互不影响

**项目管理**

- **项目页**：整页铺开项目卡网格（1440 宽下一行 4 张），顶部一条工具带是分组筛选标签 +
  分组管理 + 排序；原先它在首页的顶部带与中间那张卡片里，独立成页后不再受栏宽限制
- 选目录即自动读取 `package.json`：识别框架、版本、全部 scripts、锁文件与产物目录
- 按命名约定预分类启动命令（`serve` > `dev` > `start` > 变体）与打包命令（`build` 及变体），可在界面上改
- 包管理器按锁文件判定（`pnpm` > `yarn` > `npm`），可手动覆盖；未安装时执行前拦截并说明原因
- 分组：新建 / 双击改名 / 删除；在**项目页的筛选栏**或「分组管理」弹窗里**拖动分组标签调整顺序**；
  把卡片拖到分组标签即完成归类（两者必须同页面，拖放才成立）；「未分组」标签只在真有未归类项目时出现；
  按分组过滤、三种排序
- **排序结果稳定**：按「最近使用」排序时，点启动不会让卡片跳到第一位（运行过就被记录，但要等你主动切换排序方式、增删项目或重启应用时才重排），避免操作时列表在眼皮底下重排。
  **排序方式本身会被记住**（下次打开还停在那一档，见设置那一节的「上次看的那一档会被记住」）；
  分组筛选则刻意不记 —— 它是临时的镜片
- **在首页展示**（`Project.home`）：首页那张项目卡只画勾了这一项的项目，缺省与老数据都不展示 ——
  首页是挑出来的一份名单（全量在项目页）。三个入口：添加项目时勾「在首页展示」、项目卡「⋯」菜单里
  一项跟着状态翻的「在首页展示 / 从首页移除」、详情抽屉「基本信息」里的开关。名单顺序跟着项目页的
  展示顺序走，所以项目页怎么排，首页就照着来
- **项目标识色**：抽屉「基本信息」里选一个颜色 —— 预设是 Element Plus 那五个主题色（主题色 / 成功 /
  警告 / 危险 / 信息），也可以选「自定义」用取色器挑任意颜色。项目卡上那个小圆点与工作日志里的
  项目标签都取它。**新加项目自动取一个「当前用得最少」的主题色**，所以前五个项目两两不同；
  老数据（没有这个字段）在启动时按同一条规则补一次并落盘。预设存的是**主题色名**而不是色值 ——
  明暗切换与自定义主题色都会跟着走；自定义色存 `#rrggbb`，跟着数据走、不随主题变
- 目录被移动或删除时卡片标记「路径无效」并屏蔽操作，支持「重新定位」
- 项目卡的「⋯」里有**在 VS Code 中打开**：走 VS Code 自己注册的 `vscode://file/<路径>/` URL 协议
  （`system.rs` 的 `open_in_vscode` 直接 ShellExecute），不去猜 `Code.exe` 装在哪 —— 装到哪个盘、
  PATH 里有没有 `code` 都由安装时定，只有协议处理器是「这台机器现在用哪个 VS Code」的可靠答案。
  路径按 URL 规则转义（空格、中文、`#`），结尾的 `/` 表示这是个目录；没装（协议没有关联程序）时
  按 ShellExecute 的错误码给一句明确的提示，而不是点了没反应
- 列表与设置写在数据目录 `%APPDATA%/Workbench/data/` 下（固定位置，没有「换目录」这一说）

**工作日志**

- 导航栏第三项「工作」：一条按天分组的**时间轴**，记「今天/昨天做了什么」。一天可以有多条记录，
  同一天里按写入时间倒排；**时间的最小刻度就是天**（没有「几点几分」这一层，那些细节写在正文里）
- 顶部四档时间范围：**今天 / 昨天 / 本周 / 本月**。本周从周一起算（与首页贡献图那列「按周日切」是
  两回事，后者是网格排版约定）；没有记录的日子不占一栏 —— 本月按自然日铺会有大半是空行，
  滚起来像翻日历。跨过午夜时「今天」这一档会自己跟着时钟走。
  **范围与维度都会被记住**（下次打开还停在那一档，见设置那一节的「上次看的那一档会被记住」）；
  同一排的「只看待办」刻意不记 —— 它是临时的镜片，记住了会让下次打开的时间轴莫名其妙少一半
- **这一档里没有记录时，空态会说「最近一次是哪天」**（从整份日志里数，所以拿到的必定是范围外的那一天）：
  只说「本月还没有记录」的话，用户分不清是自己没记、还是记录丢了，而此刻真正要知道的是前者还是后者。
  整份日志真的一条都没有时才是原来那句引导（`shared/work-log.ts` 的 `dayMeta` 给「昨天 / 前天」这层相对说法）
- **两种排序维度**（工具带右侧的下拉）：
  **按时间**是默认 —— 一天一栏，记录从新到旧；**按项目**—— 一个项目一栏、栏内仍从新到旧，
  回看「这个项目这段时间做了什么」用（栏内每条会带上日期，因为它跨了好几天）。
  项目维度里「未关联」与「已删除的项目」各占一栏，排在已知项目之后；已知项目按名字排。
  两种维度共用同一套筛选与分页
- **分页按「栏」走**（页大小 7）：时间维度是每页 7 天、项目维度是每页 7 个项目 ——
  一天（或一个项目）里的多条记录不该被翻页切成两半。页脚写着当前单位下有多少栏 / 多少条
- 一条记录四个字段：**所属项目**（下拉取自项目列表，非必填，选项上带该项目的标识色；项目被删掉后
  记录仍留着，标签显示为「项目已删除」）、**日期**（默认今天，停在「昨天」这一档时默认昨天）、
  **状态**（待办 / 已完成，**默认已完成**）、**工作内容**（必填，多行，支持 markdown）。
  弹窗里能在「编写 / 预览」之间切换，预览用的就是时间轴那套渲染
- **待办与已完成**：默认是「已完成」（写下这条时事情多半已经做完了），要记待办就在弹窗里点一下「待办」。
  待办的记录在项目标签后面挂一枚「待办」el-tag，**已完成的一条什么都不显示**（卡片本身与普通记录
  长得一样，不做置灰）；在时间轴上**点一下整条记录即可来回切**，右上角那三个动作（编辑 / 删除 /
  标记完成）统一在鼠标移上去时才显形。
  工具带上有**「待办 N」筛选标签**（N 是当前档位里的待办条数），点一下只看待办、再点回到全部；
  一条待办都没有时它是灰的。状态是一次普通改动，照样会刷新记录的最后修改时间
- 项目标签是一枚 **el-tag（`effect="dark"`）**：实心标识色 + 反白文字，用的是 Element Plus 自己的
  标签主题，**跟应用的明暗没有关系** —— 亮暗两套下都是同一枚实心块（预设色由 EP 按主题变量取色，
  自定义色则由组件把标签的几个 CSS 变量换成算好的底色与字色）。一条时间轴上一眼分得清哪些记录
  属于哪个项目
- 正文按 **markdown** 渲染（标题、列表、粗体、行内代码、代码块、引用、链接、裸地址自动成链）。
  正文写长了默认收起、留一个「展开」；链接点击交给系统默认浏览器打开 —— 界面是 WebView，
  点 `<a>` 默认会把应用自己导航走。解析用 markdown-it（`html: false`，原文里的标签只当文字显示）
- 记录写入本机的 `work-log.json`，**不同步、不上报**：它是最贴近「个人记录」的东西，
  多机合并也没有成立的口径（见「数据与隐私」）。换数据目录时它跟着搬，因为它和项目列表一样
  属于「这台机器上的数据」
- 每页只读一次文件：进「工作」页时取回整份、之后一直在内存里增删改，每次改动整份落盘
  （防抖在 Rust 侧，与其余三份数据同一套）
- 首页还有一张**「今日完成」卡片**读同一份记录（只列今天已完成的，见「首页」那一节）：
  它不另存一份数据、也不写，切回首页时重读一次；卡片上点一行就跳到这一页

**笔记**

- **笔记本就是本机的一个文件夹**（第一次进这一页必须先选它）：那一页的目录树就是这个文件夹
  本来的结构，正文就是里面的 `.md` 文件。于是笔记跟任何别的编辑器都能互相接手 ——
  拿 VSCode / Typora 直接改那些文件也成立，回来点一下刷新就是最新的样子。应用只记下
  「上次选的是哪个目录」（设置里的 `noteDir`，只对本机成立，不参与同步），
  **没有笔记数据文件**，也不往任何地方上报
- 没选文件夹之前整页只有一句引导与那颗「选择文件夹」按钮：没有文件夹就没有地方放笔记，
  先摆一排按钮只是挡路
- 左栏底部一行是「这个笔记本是谁」：目录名、篇数、刷新 / 换文件夹 / 素材管理三颗图标。
  **最近打开**（设置里的 `noteDirs`，最多 6 条，最近打开的在最前）是一份**点开才弹的浮层**：
  点目录名（旁边那颗小箭头就是「这儿还有东西」的提示，弹出时翻过来）从这一行上方弹出来，
  **与左栏的菜单区等宽、左缘对齐**（宽度是从底部那一行现量的，所以拖动左栏宽度它也跟得上）。
  不做成常显的一行：左栏本来就窄，这几个目录几天也不换一次，常显要吃掉大半屏的高度 ——
  收进浮层里，那段高度还给树。点一条就换过去（换过去的排到最前，当前打开的那条加粗且点不动），
  换完浮层收起；每条右边有个删除叉，删的只是这条历史记录，**当前打开的笔记本不受影响**
  （想换得另挑一个），点叉不关浮层 —— 那是个可能连着点几次的动作。
  与 `noteDir` 一样只对本机成立，也不参与同步
- 一页两栏：左边是**目录树**，右边的**正文编辑器**用 **Vditor**（即时渲染模式），
  正文存的是 markdown 原文 —— 数据不依赖编辑器，换掉它不影响已经写下的东西。
  两栏之间那条缝可以**左右拖**改左栏宽度（宽度存在 `theme.json` 的 `noteTreeWidth` 里，
  与首页那些栏宽同一套做法：拖动时只改本地跟手、松手才落盘）。
  那颗把手**平时不显示**，指针落到缝线上（或正在拖）才露出来 —— 它只是一条 10px 热区上的装饰，
  常显就是给每一屏都添一道竖线
- 目录树只收**文件夹与 markdown 文件**（`.md` / `.markdown`），扫的时候有一份**忽略名单**：
  点开头的目录（`.git`、`.obsidian`、`.vscode`、`.idea`…）一律跳，外加 `node_modules` /
  `dist` / `build` / `out` / `target` / `coverage` / `__pycache__` / `venv` / `vendor` 这些
  「不由点、但也不是笔记」的目录整棵不走（名单在 `src-tauri/src/notes.rs` 的 `IGNORED_DIRS`）。
  它们动辄几万个文件，扫一遍既慢又只会把树塞满
- **文件夹排在文件前面**，同层按名字排（带 `numeric` 的排序规则，
  `笔记 10` 排在 `笔记 9` 后面）。顺序是算出来的，所以树不提供「插到某一项前面」这种拖动
- 树里**没有「根行」那一层**（第一行就是笔记本里的第一个条目）：顶层条目直接铺开，
  「笔记本是谁」写在左栏底部。空文件夹时树里换成一块空态，上面是新建笔记 / 新建文件夹两颗按钮
- **拖动只认「文件拖进文件夹」与「文件拖到树下面的空白区」**：文件夹不可拖（拖进自己的下级
  能把整棵子树搬没，后端也挡着），落在文件上、落在原处都不放行。拖到空白区就是**移回最外层**
  （原来靠最上面那一行根目录行兜着，根行去掉后由空白区接手）。松手后真的去挪磁盘上的文件，
  失败时重新扫一遍 —— `el-tree` 在松手那一刻已经把自己那份数据挪过了，
  不重扫的话左栏会显示一个磁盘上并不存在的位置
- 树的增删改都在**右键菜单**上（顶部的工具条已经去掉，新建只剩这一条路加空态里那两颗按钮）：
  节点行上是新建笔记 / 新建文件夹 / 重命名 / 删除，**空白区上只有前两项、且一律落在笔记本根目录**。
  节点上新建时落在「你正指着的那个文件夹」里，右击笔记则落在它所在的文件夹
- 名字最终就是一个**文件名**：上限 60 字，`\ / : * ? " < > |`、以点开头、以及 `con` / `nul` 这些
  系统保留名都在名字弹窗里当场说清楚（不是只报一句「非法」）。**撞名自动往后退一格**
  （`新建笔记 2`）：从右键菜单新建时多数人不打算起名，为此弹一句「已存在同名」只是挡路；
  重命名不退让 —— 那是用户自己打的名字
- 起名字的弹窗新建与重命名**共用**：打开时预填、全选，回车即提交。聚焦与全选挂在弹窗的
  `@opened` 之后 —— 正文是打开时才挂上的，写在 `watch` 里即使等过一次 `nextTick`
  输入框也还没进 DOM（踩过，表现成「弹窗出来了、光标不在框里」）
- **删文件夹会带走整棵子树**，确认框里把「里面还有几项」说清楚（只说「删除文件夹？」的话，
  按下去才知道）；删掉的正是当前打开的那一篇时右栏一并收起来，否则下一次自动保存
  会顺着旧路径把它重新创建出来
- 选中与打开是同一件事：点文件夹就是选中它（右栏说一句「这是个文件夹」），点笔记才是打开来写。
  分成两套状态的话，新建完一个文件夹左栏没有任何反应，反而说不通。
  **选中项所在的那几层文件夹会自动展开**（`default-expanded-keys`：树的数据每次都是新对象，
  `el-tree` 会把节点重建一遍、丢掉展开态，只能每次重建时按这份清单恢复；
  清单里**只放祖先、不放选中项自己**，否则「点一行收起它」会被自己那份清单顶回去）。
  **这份清单由笔记页持有并落盘**（设置里的 `noteTreeExpanded`，见设置那一节的「上次看的那一档会被记住」）：
  上次摊开的那几层，下次进来还是摊开的。所以 `NoteTree` 是 `expanded` 进、`update:expanded` 出、
  **自己不留副本** —— 组件里再存一份就变成「两份状态谁说了算」；换笔记本时这份清单被清空，
  相对路径在另一个笔记本里指的是完全不同的东西。
  这一块另有两处 `el-tree` 的脾气，见 [`NoteTree.vue`](../src/renderer/src/components/NoteTree.vue)
  顶部的注释：`auto-expand-parent` 默认为 true，会让清单里任一子孙把祖先一起顶开 ——
  收起「选中项所在的那一支」时会被顶回去，表现成那一支怎么点都收不起来
- 右栏标题那一行：左边是**名字**加它**所在的那几层文件夹**（面包屑，最外层的东西没有上一级，
  那一段就不显示 —— 原来它把选中项自己也排进去了，于是「README README」并排重复），
  右边写着**保存状态**：正常是「已保存 · 最后修改时间」，写盘失败就换成原因。
  正文按 **600ms 防抖**落盘（写的是那个 `.md` 文件本身：先写同目录的临时文件再改名，
  断电不会留下半篇），切换笔记、离开页面时先把没写完的那一段冲刷出去（防抖窗口里切走不该丢字）。
  换篇时交出去的正文带着**它属于哪一篇的路径**，而上层把树交给后端的重新扫描结果 ——
  改名 / 拖动之后打开的那一篇路径会变，靠后端回来的新路径接着认（`remapActive`）
- 正文里的链接在组件里被接管、交给系统浏览器：界面是 WebView，点 `<a>` 默认会把应用自己导航走
  （Vditor 给正文里的链接写了 `target="_blank"`，在 WebView 里那是弹一个新窗口）
- **编辑器的动作全部挪到正文的右键菜单上**，编辑器那条工具带不再显示。
  菜单是三排图标按钮（撤销重做大纲全屏 / 行内格式 / 引用与列表）加两行带子菜单的
  （「段落」里是标题一到六，「插入」里是代码块与表格），共 17 项 —— 正好是工具带上的全部动作。
  位置贴指针、不越出窗口，右边放不下子菜单时整份翻到左边；点别处（左键）/ Esc / 滚轮 / 窗口变化收起。
  工具带藏起来之后界面上没有别的入口提示「格式在哪」，所以正文的 placeholder 里说了一句
- 菜单**自己不实现任何编辑动作**：每一项点下去是按名字去点工具带上对应的那颗按钮
  （工具带只是被 CSS 藏起来，元素还在），选区判断、markdown 往返、撤销栈都还是 Vditor 那套，
  行为与工具栏点击完全一致；代价是动作名必须与 NoteEditor 里那份 `TOOLBAR` 对得上，
  点不到时只在控制台留一句告警（工具带是藏着的，界面上看不出来）
- 菜单 Teleport 到 body（浮层不受卡片裁剪与堆叠影响），且按下时 `preventDefault` 掉 mousedown 的默认行为 ——
  否则焦点会从正文挪到按钮上、**选区没了**，「粗体」就没有可加粗的东西
- 磁盘上的路径一律以**相对笔记根的写法**在两端之间传递（`工作/周报.md`），
  `..` 与绝对路径在 Rust 侧被挡住；改名 / 移动 / 删除还多一道「不能对笔记根自己下手」的判断
- **粘贴的图片推到用户自己的一个 git 仓库**（不做「选文件上传」，也不把图片放进笔记本目录）：
  在正文里 Ctrl+V 贴一张图，它就传上去，正文里留下一条
  `![图片](https://…/images/<设备>/<笔记本>/20260916-104512-ab12cd34.png)` 这样的外链 ——
  于是笔记文件本身始终很小，搬到别的机器、用别的编辑器打开图都还在。
  一次上传就是一次 `pull → 写文件 → commit → push`（与 Token 同步同一套 git 机制、同一套凭据，
  但**克隆目录与仓库地址都是另一套**，见 `paths::image_sync_dir`）；图片按字节原样搬，不转格式、也不压尺寸
- 文件名是「时间戳 + 随机段」（`20260916-104512-ab12cd34.png`）：时间戳在前，仓库里按名字排就是按时间排；
  随机段在后，同一秒里贴两张、或反复贴同一张都不会互相覆盖
- **图片进仓库的落点是三层**：`<images>/<本机设备>/<笔记本>/<文件名>`。
  第一层（`shared/note-image.ts` 的 `NOTE_IMAGE_DIR`，值是 `images`）**不给用户配**，后两层由同一份代码的 `imageScopeDir` 现算 ——
  设备那一段是本机设备 id（`%APPDATA%/Workbench/data/device.json`，与 Token 分片同一个），
  笔记本那一段是「目录名小写 + 路径摘要」（如 `笔记-3f2a91c4`），摘要取整个路径，
  于是 `D:\a\笔记` 与 `E:\b\笔记` 不会落进同一层，同一个目录的 `E:\Notes` 与 `e:/notes` 也只会有一层。
  分这两层是为了**素材管理只看得见自己那一份**：图片仓库是所有笔记本、所有机器共用的一份，
  混在一起就没人说得清「这张图还有没有人在用」
- 访问地址**不是从仓库里读回来的**，而是照仓库地址算出来的：GitHub 拼 `raw.githubusercontent.com`、
  Gitee 拼 `/raw/`、GitLab 拼 `/-/raw/`。只认这三家公开托管，别的仓库（自建 GitLab / Gitea、图床镜像、Pages）
  拼不出来 —— 那时如实说明，而不是往正文里插一个点不开的地址
- **上传期间编辑器右下角挂一颗 loading 角标**（「正在上传图片…」，贴多张时带上张数）：
  一次上传就是一次 `git push`，几秒很正常，而这几秒里正文不会出现任何东西 ——
  没有提示就像按下去没反应。它是浮在正文上的小角标而不是整块遮罩：上传时用户往往还在接着写
- **没填图片仓库时粘贴只是提示**（去哪里填），既不上传也不退回「base64 内联进正文」：
  那样几篇带图的笔记就能把 `.md` 撑成几兆。图片上传是联网边界上的第四条出口，
  必须由用户显式开出来（见「数据与隐私」）
- **页面带文档级的 `no-referrer`**（`src/renderer/index.html`）：Gitee 的 `/raw/` 有防盗链，
  请求带 `Referer`（且不是 gitee.com）时直接 403，而 WebView 里 `<img>` 一定会带上它 ——
  少了这一条，「上传成功、地址正确、curl 也 200」的图在编辑器里就是裂的（踩过）。
  顺带的好处是：打开一篇引用了外链图片的笔记，不会把自己的来源地址送给图片服务器
- **素材管理**（左栏底部那颗图片图标）回答的是「我能安全删掉哪些图」：素材（图片）不在笔记本里，
  而在你的图片仓库里，所以列表来自仓库、引用次数来自笔记本，两边凑起来才知道哪张已经没人用了。
  **两边都只限当前这个笔记本**：清单就是上面那个三层目录里的一层，引用次数也数它自己的正文 ——
  别的笔记本、别的机器传上来的图既不在这份清单里，也**删不到**（这次传给 Rust 的目录就是那一层，
  越界路径逐条被挡回去）。没打开笔记本时这一页什么都不列：退回上一层去列图是把别的笔记本的图当成了可删的。
  面板里一行一张图：缩略图（点开就是在浏览器里看原图）、文件名、大小、被引用次数；**未引用的排在最前**、
  带一个「未引用」红字，引用次数大于 0 的行**勾不动**（删它一定会裂图）。底部是「全选未引用 / 清空选择 /
  删除 N 张」，删除前有一次确认，按下去就是**一次提交 + 一次推送**（与粘贴上传同一套 git 机制）——
  删图也是一次仓库改动，得进历史，不然别处克隆出去的那份还会把图带回来
- 引用次数是**数出来的**，不是记下来的：正文就是磁盘上的 `.md` 文件，别处编辑器随时能改，
  没有任何地方能维护一份「引用表」。所以口径是**打开面板就重新数一遍**（面板一开就扫，
  不靠用户记得点刷新；上次那份清单只用于先把界面显示出来，不参与「删不删」的判断）。
  数的是**文件名**在正文里出现了几次 —— 同一张图在正文里可能写成 raw 地址、带访问前缀的地址、
  相对路径，唯一确定指向它的只有文件名。于是「未引用」真的等于「这个笔记本里没人用」；
  唯一还能删错的情形是把地址**手工抄到别处**用过（另一个笔记本、自己的文档里），确认框里会说这一句。
  有笔记读不出来时（编码 / 权限）面板会如实说「有几篇没读到，引用次数可能偏少」，而不是当成「没人引用」
- 面板里那点缩略图取的就是图片自己的访问地址（与正文里显示图片是同一条路），**按行懒加载**：
  不给看不见的行发请求；拼不出地址的仓库（不在 GitHub / Gitee / GitLab 上）显示成占位图标，不是裂图。
  只扫上面那一层目录：仓库里还住着 README、别的笔记本的图，它们不该出现在这份清单里
- 这一版把图片从「全都在 `<images>/` 平铺」改成了按设备 / 笔记本分层，**改版前传上去的图不在任何一层里** ——
  它们不会出现在素材管理里（正文里的外链照样能用，图片也还在仓库里），要清理那些旧的只能去仓库里手工删
- **笔记可以整体同步到你自己的一个 git 仓库**（设置 → 笔记里的「笔记仓库」，留空就是不同步）：
  左栏底部那颗同步按钮把**当前这个笔记本**与远端对齐一次 —— 提交本机改动、拉回别处的改动。
  与 Token 用量 / 笔记图片那两处同步最大的区别是**没有克隆目录**：跑 git 的地方就是笔记本那个文件夹
  本身（`%APPDATA%` 里没有它的副本），首次同步会在文件夹里就地 `git init` 并接上这个地址，
  之后提交 / 拉取 / 推送都在它里面跑 —— 于是「笔记就是磁盘上那些 `.md`」这条仍然成立：
  换台机器 `git clone` 下来、拿别的编辑器接着写，还是同一份东西。
  三件按顺序说清楚：
  1. **文件夹连着别的仓库时只报错、不改它的 origin**（那是你的文件夹，换个地址等于把笔记推到
     你没选的地方）；本地路径的各种写法（`C:/a/b` 与 `C:\a\b`）认得出是同一个仓库；
  2. **冲突不替你挑边**：远端和本机改到同一处时，应用中止这次 rebase（**本地那笔提交留着**）、
     把冲突的文件名报出来，剩下的交给你手工合 —— 笔记是文字，自动挑一边就是悄悄改掉你的内容。
     文件夹里本来就留着半截 rebase / 合并时也会拒绝动手（那是你自己的现场）。
     报出来的名字**必须能直接看懂**：git 默认会把非 ASCII 路径转义成八进制
     （`周报.md` → `\345\221\250\346\212\245.md`），而这一页的笔记多半是中文名 ——
     所以每条 git 命令都带 `-c core.quotepath=false`（`sync.rs` 的 `GIT_GLOBAL_ARGS`，
     一处拼好、所有调用都走它，见 [constraints/sync-and-auth.md](constraints/sync-and-auth.md)）；
  3. **同步前会先把编辑器里还没落盘的那一段写下去**，所以点下按钮那一刻刚打的字也在这次提交里；
     回来之后左栏会重新扫一遍（远端可能带来新文件），**正开着的那一篇若被远端改过也会重新读进来**
     （否则编辑器手上那份旧的会在你下一次输入时把远端那份盖回去）。
  提交信息是 `notes: <设备名>`；没配过 git 身份时只在这个仓库里兜底一个 `Workbench` 身份，不动你的全局配置
- **Vditor 的静态资源随包带一份**：它的编辑器本体打在 JS 里，但图标（工具栏那套 SVG sprite）、
  语言包、markdown 引擎（lute）、内容主题、表情、代码高亮这几样是**运行时**按 `options.cdn` 去取的，
  默认指向 unpkg。这个应用默认不联网，所以 `cdn` 指向本地的 `public/vditor/`，
  内容由 `scripts/sync-vditor-assets.mjs` 在 dev / build 前从 `node_modules/vditor/dist` 复制
  （只带用得着的子集，约 4.8MB；整包 20MB 里其余是 katex / mermaid / echarts 那些这个页面用不到的东西）。
  复制挂在 vite 的 `configResolved` 上，dev 与 build 两条路都绕不过去；版本没变就跳过

**技能（skill）**

- 导航栏第五项「技能」：管理一批自定义的 skill —— 一个文件夹 + 一份带 frontmatter 的
  `SKILL.md`（给 AI 编程工具用的那种）。界面是**卡片网格**（与项目页同一副卡片外壳）：
  每张卡片展示自动提取的名字与描述（解析 `SKILL.md` frontmatter 的 `name` / `description`，
  只认「围栏内单行键值」的最小集合，多行块标量如实丢掉；解析与路径口径在
  [shared/skills.ts](../src/shared/skills.ts)，带单测）加文件数，没有 `SKILL.md` 的卡片挂一枚
  警示（它装不进项目），底部一排**悬停才显形**的操作（安装到项目 / 打开文件夹，
  与工作记录卡的动作同一交互；点击会 stopPropagation，别顺带把详情也拉开）。
  点卡片打开**详情弹窗**（1200px 宽的 `el-dialog`，窄窗口收着不出界）：
  编辑清单原文、安装到项目、版本历史、删除都在里面；关闭前有「放弃修改」的确认
  （编辑是手动保存的，没点保存就关，刚敲的字会真的丢）。没有 frontmatter 的技能照样列出来，
  名字回落目录名
- **技能库住在笔记文件夹下的一个子目录里**（设置里的 `skillSyncDir`，默认 `skills`），
  **不另设仓库、不另开网络出口**：技能与笔记是同一类东西（几份 markdown 加随带的小文件），
  凭据、克隆、冲突语义全部复用笔记同步那一套。这个路径住 `theme.json`（外观白名单）：
  它不是「界面长什么样」，但它是**仓库结构约定** —— 两台机器要落在同一层才互相看得见对方的技能，
  跟着配置一起同步过去正好保证这一点
- **版本管理就是 git 提交历史**：新建、保存、删除、导入都由适配层在笔记仓库里提交一次
  （提交信息 `skill: <id> 动作`；只 add 技能库那一个子目录，用户没提交的笔记不捎带）。
  **保存有必经的版本门槛**：SKILL.md 的 frontmatter 里必须有一个语义化版本的 `version` 字段
  （三段数字，如 `1.0.0`，容忍可选的 v 前缀；校验与归一化在 shared/skills.ts 的
  `skillVersionProblem` / `skillVersionOf`，新建模板自带默认的 `0.1.0`），没有或不合语义就
  **整个不落盘** —— 写了盘却记不上版本，比拒绝保存更糟。通过之后提交信息带着这个版本号
  （`skill: <id> 保存 1.0.0`），「这个改动是哪个版本」在 git 日志里直接可查。
  「版本历史」弹层现问 `git log`（没有缓存的中间态）。每一版有两条路：**「对比」**打开差异弹窗
  （那一版 vs 现在库里的这份，逐文件逐行看清楚这一版会改掉什么，弹窗底下那颗才是「恢复到这个版本」，
  见下一段那个弹窗），**「恢复」**是直接回去的快捷方式。恢复先把该目录下
  **已跟踪**的内容 `git rm` 掉再检出旧版（直接 `checkout <hash> -- <目录>` 只会把旧版文件盖回来，
  那一版之后新增的会残留，那就不是「恢复到那一版」了），恢复本身也是一次提交，历史里留得住痕。
  两侧内容由 `skills.rs` 的 `version_compare` 一次取回（工作区那份 + 那一版那份）：
  清单走 `git ls-tree -z`，内容走 `git show` 并**按原始字节**收 —— 见
  [constraints/sync-and-auth.md](constraints/sync-and-auth.md) 里「技能」那一节的硬约束。
  笔记文件夹还不是 git 仓库时（没配笔记仓库或还没同步过）技能照常增删改，
  只是如实没有版本与同步 —— 界面上把这句说明放在了保存按钮旁边
- **同步走笔记同步**：技能页的「同步」按钮调的就是笔记同步那条通道（同一个仓库，
  一次同步两者都带上）。所以「推」的节奏也一致 —— 增删改只在本机提交，**只有点同步才出网**。
  撞上冲突时同样「不替用户挑边」（中止 rebase、报出冲突的文件名，见 `sync.rs` 的 `sync_notes`）
- **项目里补充优化过的内容能更新回库**：用户可能直接在项目里改了装过去的副本
  （`<项目>/.agents/skills/<id>/SKILL.md`）。详情弹窗打开时会**只读检测**一遍各项目里的副本
  （`skills.rs` 的 `installed_versions`，路径在那里拼死在项目目录内，渲染层比对）。
  「有没有更新」**只看 SKILL.md 的 version**：解析双方 frontmatter 的 version（归一化后按数字逐段
  比较，见 shared/skills.ts 的 `compareSkillVersions` —— `1.10.0` 大于 `1.9.0`，字符串比会答反），
  **项目版本高于库版本**才列进提示条；version 没升时**即使其他文件内容不同也不算有更新**。
  库版本的解析失败（老数据）按 `0.0.0` 兜底，不把更新这条路堵死。
  **详情页只看库里的文件**（文件条切换就是安静地打开库里那一份）；**差异只在对比弹窗里看** ——
  弹窗顶部自带文件条（库里的全部文件，内容与项目不同的挂一枚圆点），点哪个文件看哪个的差异，
  不必关掉弹窗换文件。
  点「查看新版本内容」打开**对比弹窗** —— GitHub split 视图那样的逐行差异：左右行行对齐、
  行号、删红增绿、行内变化段更深一档。差异的**行模型是纯函数**（[shared/text-diff.ts](../src/shared/text-diff.ts)，
  算法用 `diff`（jsdiff，纯算法库无 UI：`diffLines` 出行块、`diffWordsWithSpace` 出行内变化段，
  配对与行号在这边，带单测），组件只负责画；红绿借 `--st-fail` / `--st-ok` 的「失败/成功」语义，
  深浅两档用 color-mix 出，不新增颜色。整张差异表住在一个滚动容器里 —— 一个滚动条控制左右
  两侧，同步滚动天然成立。确认后「用项目版本更新到库」
  —— 走的就是正常保存那条路：version 门槛照常（项目里改出的版本不合格照样拦下），
  提交信息照常带版本号，旧版本留在历史里随时可恢复。比对基准是**库里盘上的那份**，
  不是编辑器里没保存的草稿；没装、或文件读不出来的项目不参与更新（null 不能当新版本采用）
  （**「版本历史」里的「对比」用的是同一个弹窗**，只是右栏换成所选的那一版、底下那颗按钮换成
  「恢复到这个版本」。两处的右栏都是「要采纳的那一份」、左栏都是库里现在这份，
  所以差异表、文件条、红绿语义一点没变 —— 见 `SkillCompareDialog` 的 `mode` 与
  shared/skills.ts 的 `mergeVersionCopies`）
- **技能可以是多文件的**：详情弹窗里有一条文件清单（相对路径，横向滚动），点哪个编辑哪个
  —— 附属文件（脚本 / 模板 / 子文档）与清单走同一条保存通道，同样每次保存记一版
  （提交信息 `skill: <id> 保存 <文件路径>`）。**version 门槛只对 SKILL.md**：
  version 是清单的属性，附属文件没有这一说。切换文件时当前文件有未保存的修改会先确认；
  二进制文件读不出文本，如实提示、不支持在应用内编辑。文件清单在打开详情 / 保存 / 刷新时重拉
  （安装 / 导入本就是整棵复制，多文件天然带着走）
- **一键安装到项目**：把整个技能目录复制到 `<项目>/.agents/skills/<技能名>/`
  （各 agent 通用的项目级技能目录约定，与本仓库自己用的同一条）。已安装时先问「要不要覆盖」
  —— 覆盖是把项目里那份整个换成库里的当前版本，必须经过确认；没有 `SKILL.md` 的目录不是技能，
  装不出去（复制走 `walkdir`，点开头的目录整支跳过 —— 从别人的笔记文件夹里导入时，
  那些是别人的仓库与工具状态）
- **添加的三个入口**：新建（填名字与描述，生成 frontmatter 骨架，名字即目录名即安装时的 id）、
  从文件夹导入（整棵复制，同名已存在时报错而不是悄悄覆盖）、以及直接在文件管理器里往技能库里放
  —— 回来点刷新就是最新的样子，与笔记同一个道理：磁盘上的文件就是数据本身，应用不维护第二份
- 笔记页的目录树把技能库这一层藏起来（`withoutSkillDir`，只藏顶层同名的那个文件夹）：
  技能有自己的页面，树里再挂一份只会让人以为它也是笔记 —— 在那里改名 / 删除不会留下
  技能的版本提交。藏在更深处的同名文件夹不归它管

**密码保险库**

- 导航栏第六项「密码」：**按分组分段的卡片墙** —— 每一段一个段头（分组名 + 条数），
  段头下面是一行卡片（1440 窗口下五张、每张 256px）。
  **段头不画那条拉到右缘的细线**：加过一版，在内容稀疏的页面上露了馅 —— 一组只有一张卡时
  那条线仍然拉满一千三百像素，整页就成了几道横线夹着几张小卡，像一张没填完的表。
  这个应用里带标题的分组（工作页那天一天）本来就没有线，靠字号与留白分层。**工具带上只有搜索**：上一版有一排分组筛选标签，与段头把那几个数
  摆了两遍（同一屏里「测试 1」出现两次），整条带子也被它撑得没有重心 —— 找某一条用搜索、
  看某一组用分段，两条路都够了。搜索框按 `.sort` 那套控件规范做（28px 高、`--r-sm` 圆角、
  `--bg-surface` 底），工具带上的东西尺寸与圆角一致才像排过版的。
  **整页一条左基准线**：`.filter` 那个共用外壳本身是 `padding: 0 var(--sp-5)`（20px），
  而卡片墙的四周留白是 `--card-gap`（默认 10px，用户可调）—— 这一页把外壳的内边距压成与卡片墙同源，
  段头也不留内边距，于是搜索框、段头、卡片的左缘落在同一条竖线上。
  跨页面统一让位给页面之内的对齐：差这 10px 在项目页看不出来（那边的筛选标签是无边框的药丸，
  没有可见的左缘），而工具带左边是一个有硬边的输入框，差 10px 就明摆着没对齐。
  **两种引导屏（还没建库 / 已收起）同理**：`.empty` 那套（居中 + 无宽度上限）是给
  「一句话 + 一颗按钮」准备的，而这两屏的说明各有两三段话 —— 不约束宽度就会各自铺成一行
  一千来像素的居中长句，左缘右缘全参差。所以段落统一 `width: 32em` 并左对齐
  （写 `width` 而不是 `max-width`：`.empty` 是 `align-items: center`，只给上限的话短句仍比长句窄，
  左缘照样不齐），图标与按钮保持居中。
  分段用的是 `groupVaultRecords`：它要的是**排好序的那份**（`sortVaultRecords` 的输出），
  于是相邻的同组卡片自然连成一段，一个 Map 都不需要；排序管「谁先谁后」、分段管「哪儿断开」，
  拆成两个函数是因为混在一起就得在两处各写一遍比较规则，而它们迟早会不一致。
  **分组名不写在卡片上**（标题已经说了，一张卡再重复一遍只是占地方）。
  一条记录就是**名字、密码、备注、分组**四样。它是**备忘，不是密码管理器** ——
  一条记录只有**名字、密码、备注、分组**四样（`VaultEntry`）：没有用户名 / 网址那些字段，
  也不生成口令。多一个字段就多一份要填的东西，而这几样本来就是随手记下的东西（宽带账号、门禁密码、
  某台机器的口令），抄在哪儿都一样。
  卡片上只有**一行「标签 + 值」**（`密码` 那个灰字标签把值锚住，值那一列左边对齐）——
  没有标签的话，卡片上就是一段飘着的字（那是更早一版的样子）。**备注不摆在卡片上**：
  它是一句随手记下的话，长短不定，摊上去几张卡就高矮不齐；备注照旧记着，跟着弹框走。
  卡片是**用**的地方：密码默认遮住（遮罩是**固定八度**的点，不按真实长度铺 —— 长度也是信息），
  两颗按钮各管一件事 —— **一键复制**与**一键查看**，它们**常显**（这就是卡片存在的理由），
  压暗一档不抢内容的风头；亮着时密码**换行而不是截断**（查看密码就是为了读全）。
  改与删是偶尔才做一次的事，收在悬停 / 键盘聚焦才显形的「⋯」菜单里
  （菜单是 Teleport 到 body 的，指针一进菜单卡片就不算被悬停了，所以开着的这张要单独记住 ——
  `openMenu`，不然那颗按钮会在菜单还开着的时候淡掉）。
  **添加与编辑都走弹框**（把四个字段摊在每张卡片上，等于把最不常做的动作摆到最显眼的位置）。
  名字是唯一必填项（只记个名字也成立），校验就地显示在字段下面
  （`vaultEntryProblem` 是唯一那份规则，store 里再兜一次）
- **非对称加密**：一把 **ECDH P-256** 密钥对，每条条目单独走一次 ECIES ——
  现生成一把临时密钥对 → 与那把公钥做 ECDH → HKDF-SHA256 推出 AES-256-GCM 的密钥 → 加密条目正文。
  于是「有公钥能写、没有私钥读不出来」是真的成立：往仓库里写东西只需要公钥，读才要私钥。
  临时密钥对每次现生成，同一条正文加密两次得到的密文完全不同
- **密钥全部存在本地**：私钥存在 Windows 凭据管理器（`Workbench/vault/key`，DPAPI 按当前 Windows 用户加密，
  能在「控制面板 → 凭据管理器」里看到并手工删掉），**不进任何数据文件、更不进仓库**。
  所以这一页**没有主口令这一层** —— 设计上密钥就在本机，能打开这个程序就说明已经过了 Windows 登录。
  于是工具带上那颗**「收起密码」不是访问控制**：它把已解开的明文从屏幕与内存里清掉（离开座位时按一下），
  而解锁不需要口令、点一下就回来。这一句写在界面上而不是只写在文档里 ——
  一个叫「锁定」的按钮会让人以为它挡得住别人，而它挡不住，那比没有这个按钮更糟。
  真正的访问控制只有主口令这一条路（拿它派生一把密钥把本机密钥包起来），那是另一件事。
  另一台机器要用同一个保险库，就在密钥那一屏**导出成文件**带过去导入一次：导出的是一个纯文本文件，
  里面就是这把密钥（等于保险库本身），所以界面上只走文件、不上屏也不进剪贴板
- **数据上传仓库，所有设备公用一个文件**：密文放在同步仓库的 `vault/vault.json` ——
  与用量、外观、图片、笔记是**同一个仓库、同一条凭据**，所以它不是第七个网络出口（没登录就没有同步，
  保险库在没登录时照常能用，只是推不出去）。文件里的**信封是明文、正文是密文**：
  认身份靠 `id`、判新旧靠 `updatedAt`、破平靠 `by`、认删除靠 `deleted` —— 这几项必须在没有密钥时也读得出来，
  否则两台机器没法在本地算出同一个合并结果。露出去的只有条目条数、每条的改动时刻与设备 id、哪些 id 被删过；
  名字、密码、备注、分组全在密文里
- **它是仓库里唯一一个多写者文件**，于是「一台机器一个文件、单写者、不需要人工合并」那条约定在这里不成立，
  合并规则必须自己定死：**按 id 取并集，每条取 `updatedAt` 大的那份**（撞上时按设备 id 破平），
  删除留一个空壳墓碑。规则里没有「以我为准」这一项，所以两台机器各拿（自己的, 对方的）算一次，
  得到的是**逐字节一样**的一份（输出按 id 排序，顺序不确定就会堆出没意义的提交）。
  **墓碑永不清理**：清掉之后，一台离线很久的机器再回来时，本地那条老记录就成了「只在一边出现」的并集项，
  于是被原样推回去 —— 用户看到的是删掉的密码自己回来了
- **同一个文件不交给 git 去合**：两种改法让 git 去 rebase 只会留下一堆冲突标记让用户手工挑边，
  而这份数据本来就有确定的合并结果。做法是推送前核对远端还是不是合并时的基准，变过就**一个字都不写**、
  把远端那份交回去重新合一遍（最多三轮）。于是两台机器同时改也不需要人工介入，谁先推都一样
- **改动只重封那一条**：其余条目的密文原样留着 —— 整份重加密一遍会让字节全变，
  「内容没变就不产生提交」这条约定随即失效，仓库里会堆出一串无意义的提交
- 界面上**如实说三件读不出来的事**，否则用户只会以为密码丢了或同步没生效：
  有几条**解不开**（它们是用别的密钥加的密）、有几条**读不出来**（内容坏了或来自更新的版本）、
  以及**仓库里那份与本机这把密钥对不上**（能合并能推，但那些条目在这台机器上永远解不开 ——
  不说的话「同步成功，一条都没多出来」就说不通）。密钥那一屏还显示**公钥指纹**（`A1B2-C3D4-E5F6`）：
  两台机器上显示的应当是同一串，对不上就说明该重新导出一次密钥
- **分组名在收敛时去掉首尾空白**（`sanitizeVaultEntry`）：排序、筛选标签、分段三处都按
  `record.group` 这一个值比，各自 trim 一次反而会做出三个不同的判断（`开发 ` 与 `开发`
  会被排序当成两组、而标签按名字精确匹配点进去是空的）。**收敛只在这一处**，下游一律依赖这个不变量。
  同理，适配层 `save` 回来的那条记录用的是**收敛之后**的正文 —— `seal` 内部也会 sanitize，
  不收敛的话界面上拿到的（`开发 `）与磁盘上存下的（`开发`）会差一个空白，刷新一次标签就换了个写法
- 卡片上那颗「⋯」**平时透明但一直占着位置**（28px，与全局的 `.el-button--small` 一致）：
  于是悬停让它显形时整行不会跳一下。别改成 `display: none`。
- **卡片里那一行的高度由 22px 这一个数说了算**：标签、值、图标都落在同一条带子上。
  踩过一次 —— 标签与值是 20px 的行盒、而图标按钮吃的是全局 `.el-button--small` 的 28px，
  三者各自居中就是三条中线，标签偏高、图标偏低，一行里怎么看都不齐（而且越看越别扭）。
  所以图标按钮在这一页被压到 22px、横向内边距从 10px 收到 4px（10px 会把两颗图标的字距
  拉到 30px，看着像两个各管各的按钮而不是「复制 / 查看」这一对），文字的行高也写成 22px。
  **改任何一个都要一起改。**
- **同一行里字号不同的文字按基线对齐，不是按盒子居中**（段头那个 15px 的名字配 10.5px 的条数）：
  盒子居中的话小字会矮下去两三像素。
- **引导屏（还没建库 / 已收起）的上边距必须是 0**：导航栏那张卡片与每一页的第一个元素
  （工具带）都是紧贴顶栏下沿的，这里再补一圈 `--card-gap` 就会比导航栏低一截。
  左右与下边距仍然取 `--card-gap` —— 那两处要和卡片墙、工具带对齐。
- 引导屏里**文字与按钮共用一条左缘**（两者都 `width: 32em`），图标居中在上面：
  各自居中时图标、文字、按钮三条左缘各不相同，一排按钮缩在中间看着像另一块东西。
- **分组是一栏自由文本，不是一份要管理的清单**：弹框里那一栏是 `el-select`（`filterable` +
  `allow-create`），下拉给出现存的分组、也能直接敲一个新的。所以**没有**「新建分组 / 改名 / 删除」那一套，
  也没有一份要落盘的分组表 —— 分段与弹框的候选项都是从卡片里现算的（`groupVaultRecords` /
  `vaultGroups`）：某一组最后一条被改到别处或删掉，那一段自己就没了。没归类的记录自成一段，
  段头写「未分组」。
  卡片顺序是**先按分组、组内按名字**，未分组垫底 —— 于是「全部」那一档里同一组的卡片也是挨着的。
  **当前看哪一组刻意不落盘**（与项目页的分组筛选同一条口径）：它是临时的镜片，记住了会让下次打开
  看到一份莫名其妙少一半的卡片墙
- 同步**只有手动那一次**（工具带上那颗按钮）：保险库改动是用户自己做的事，替他在后台推上去没有意义。
  与其余几条同步一样，没登录 / 没填仓库地址时按钮给出一句能照做的话，而不是静默失败

**一键操作**

- 安装依赖 / 启动 / 打包 / 停止 / 重启；dev server 跑着的时候照样能点打包（一个项目可以同时挂着几条会话），
  所以**「停止」停的是卡片当前显示的那一类**：写着「打包中」就停打包，写着「运行中」才停开发服务
  （按 `runtime.kind` 命中对应会话；按端口结束外部服务那条路只在界面显示的就是那个外部服务时才走，
  否则停掉的是旁边的 dev server，打包照旧在跑）
- 打包成功后自动打开产物目录（探测顺序：手动配置 > 构建配置 `outDir` > `dist` 等常见目录 > 项目根目录），可项目级关闭；
  输出目录除了手填也能直接**选目录**：选项目内的会落成相对写法（如 `dist`），项目挪位置也不失效，选到项目外才记绝对路径，输入框下方始终显示拼好的实际路径
- 启动日志里识别 `localhost` 端口：显示在卡片上；若该端口已被别的进程占用，启动前提示占用者名称与 PID，可选择结束它后重试（不需要手填端口）
- **不代开浏览器**：地址解析只用于显示与端口占用提示，浏览器交给项目脚本自己开（如 Vite 的 `server.open`）
- 自定义命令（名称 + 命令行）挂在项目上，卡片「⋯」菜单里一键运行
- 状态机与指示灯：灰=空闲、黄=运行/安装/打包中、绿=命令正常退出（只有打包才显示成「打包成功」，其余按「已结束」）、红=失败
- 用户点一次「启动」或「打包」记一次活跃度（按下的那一刻、按当天日期），首页的贡献图就是这些次数铺出来的；
  安装依赖、自定义命令、停止与启动失败都不算 —— 计数落在适配层的 `workbench/state.ts`（`recordActivity`），
  **不在 Rust 侧**：这段在 Electron 时代是主进程 store 里的 `recordActivity`，迁 Tauri 时漏过一次，
  症状是图上的格子从此不再变深

**终端面板**

- **一个项目的一类操作一个终端**：同一项目的「启动」「打包」「安装依赖」以及每条自定义命令各自占一个
  Tab，输出互不覆盖，可以一边看打包日志一边跑 dev server
- 终端可关闭（× 在 Tab 上，运行中的终端要先停止）；日志只在内存里，重开应用即清空
- 应用刚启动时底部不占位置（没有终端就不渲染）；跑过一次命令后面板条常驻
- **收起 = 收进窗口最右侧的一颗悬浮按钮**（工具栏与面板条左侧那两个 `→` 都是收起，按钮上是 `←`）：点下去面板
  整块**向右滑出窗口**（滑进右缘那颗按钮里），按钮紧跟着从右缘滑出来；面板腾出的高度等它淡出之后才收拢，
  上面的内容因此不会被「往下折」的面板带着走 —— 展开是同一套倒着走
- 那颗按钮**不参与页面布局**：它挂在窗口右缘（`body` 上，贴死右边、只留左边两个圆角），
  纵向位置默认落在**终端面板自己的中线上**（收起看着像面板收进了它，而不是飘到屏幕别处），
  按住可上下拖，拖过的高度存进本机设置 `terminalButtonTop`（占窗口高度的百分比，换窗口大小仍停在差不多的高度）
- 还有命令在跑（黄点呼吸）或上次跑失败了（红点）时，按钮右上角带一个角标 ——
  收起后 Tab 上的状态点看不见了，这颗就是唯一提示
- 按行推送、清洗 ANSI 控制序列（进度条那类清行 / 移光标 / 颜色都丢掉，`\r` 按终端语义只保留最后一次改写）、
  stderr 高亮、显示当前执行命令
- 每个终端保留最近 5000 行，渲染超过 1000 行时只挂载尾部并提示省略行数
- 工具栏只剩「清空日志」（日志本来就在内存里，不留导出）

**系统集成（设置面板）**

- 面板是「左侧菜单 + 右侧内容」两栏：菜单四屏 —— **外观**（主题、背景、顶部样式、卡片不透明度与间距）、
  **菜单**（左侧导航栏上留哪几页，首页那一页下面还挂着它自己的九块卡片）、
  **通用**（程序、快捷键、启动、笔记、账号与同步）与
  **关于**（版本、数据目录、登录状态、联网边界），
  右侧各区独立滚动、菜单不跟着走。导航栏那一项单独一屏而不是塞进「外观」：它管的是
  **应用自己的入口留哪几个**，与「这一屏长什么样」不是一回事。
  「关于」也单独一屏：它不是设置，而是把「这个应用是什么、数据在哪、什么时候才会联网」如实摊开
  —— 联网那一段把六个出口逐个列出来（与本文档「数据与隐私」同一份事实，改了一边就要改另一边），
  这一屏**只读**，数据目录与账号的可编辑入口仍在「通用」那一屏，不在这儿再摆一份
- 程序名称：标题栏、托盘提示与窗口标题上显示的名字，以及**首页问候行上称呼后面那个名字**
  （默认 `MUYIAN`，可在设置里改）。
  托盘提示与窗口标题归系统画，只能在 Rust 侧设（`set_app_name` 一条通道同时改窗口标题与托盘提示）——
  名字一改就推一次，启动时由 settings store 那个 `immediate` 的 watch 补上第一次；
  窗口要到页面加载完才显示，所以中间那一下看不到
- 「关于」里显示的版本号取自 `tauri.conf.json` 编译期内嵌的那一份（`app_version` 命令）：
  界面上不写死，免得改版本号时只有一处忘
- **上次看的那一档会被记住**（这几项不在设置界面上，所以单列一条）：项目页的排序方式、
  工作页的时间范围与排序维度、笔记页目录树**摊开的那几层**。它们记的不是界面长什么样，
  而是「你习惯怎么看」—— 所以住在数据文件里、**不进 theme.json 的白名单**：那份是
  「这台机器该长成什么样」的配置，会整份同步到别的机器，而「我上一眼在看什么」换台机器不成立
  （与 `activeView` 同一条口径，见 [constraints/ipc-and-state.md](constraints/ipc-and-state.md)）。
  刻意**不记**的两项：项目页的分组筛选、工作页那颗「只看待办」—— 它们是临时的镜片
  （找某样东西时才戴），记住了会让下次打开看到一份莫名其妙少一半的列表。
  目录树的展开态**换笔记本时清空**：清单里存的是相对路径，换到另一个笔记本就指向别的东西了
- 主题：跟随系统 / 亮色 / 暗色（默认暗色）
- 主题色：开关、选中、聚焦环与主按钮这些交互态用的颜色，内置几档预置色也可自选，留空是原本的中性灰；
  只影响交互态，运行状态色与终端不变
- 主题色文字：铺在主题色上的字按主题色深浅自动取黑或白（红底白字、浅灰底黑字），也可手动指定
- 卡片不透明度与卡片间距（外观那一屏，两行挨着）：前者是卡片底色的浓度，20%–100% 可调
  （默认 55% 半透），调低后背景图从卡片底下透出来，只动底色、边框与文字不变；
  后者是卡片之间（行间与行内）与页面四周的留白（px）
- 左侧导航栏（菜单那一屏）：一行一页、一个开关，关掉的页从导航栏上收起来
  （至少留一页；全关掉时首页会留下）
- **首页那一页下面挂着它自己的九块卡片**（同一屏，缩进一层 + 一条竖线把父子关系摆明）：
  一行一块、一个开关，关掉的卡片不画在首页上（位置与高度留着，再打开回到原处），至少留一块。
  两块开关清单都排在说明文字下面，一行两个，不给某一屏撑出一整屏高
- 全局快捷键唤起或隐藏窗口（默认 `Ctrl+M`，可自行录制；被占用时自动停用并提示）
- **关闭按钮 = 收进托盘**：窗口不会真的关掉，托盘常驻，点托盘图标或快捷键都能找回来；最小化是否也收进托盘可单独设置（默认收进托盘）
- 右键不弹 WebView2 的原生菜单（返回 / 刷新 / 另存为 / 打印 / 更多工具 / 检查 那一套）：界面是自绘的，浏览器这套菜单在这里没有意义；
  菜单键与 Shift+F10 触发的是同一个事件，也一样不出。调试因此没有「检查」可点，改走远程调试端口（见 [AGENTS.md](../AGENTS.md) 第 6 节）
- 开机自启（默认开启，仅打包后生效）
- 账号与同步：账号那一块在通用那一屏的最后（登录前只有「登录状态」一行，登录后多出同步仓库地址，
  留空即不同步）；**从别的机器取外观**（列出仓库里有文件的机器，含标了「本机」的那条、
  逐台点「应用」把本机外观换成那一套 —— 本机那条相当于取回上次推送时的外观）
  在**外观那一屏的最上面**，旁边那颗「同步一次」就地推拉一次，不必回首页
  （做法见上面的「外观配置也走同一个仓库…」）
- 退出提醒（用 `el-dialog`，遮罩 / 焦点 / Esc 与其他弹窗同一套）：从托盘菜单真正退出时，若还有项目在运行会弹窗二选一 —— 「关闭所有项目并退出」先结束进程再退；
  「直接退出」保留这些进程，交给下次启动的残留清理处理。**收不收进程只由这个选择决定**：
  Rust 侧的退出钩子（`RunEvent::Exit`）不再兜底收一次 —— 它是所有退出路径（`AppHandle::exit` 就在其中）的必经之处，
  在那儿收等于把选择抹平，选「直接退出」的照样被一起杀掉（改前就是这个毛病）。「运行中」既包括本次会话启动的进程，
  也包括启动检测按端口认出、不归 Workbench 管的服务（后者按端口结束）。
  **推事件之前先把窗口唤到最前**（`request_quit` 里调 `show_main_window`）：这个框是应用内弹窗而不是系统消息框，
  窗口收在托盘、最小化或压在别的程序后面时弹了没人看得见，而 Rust 侧还要等满 60 秒超时才按「直接退出」收场；
  点了「取消」则把窗口放回唤出之前的样子（原本收在托盘就再收回去、原本最小化就再最小化）

**账号登录**

- 顶栏右上角可以**用一个已有的 GitHub / Gitee 账号登录**：不需要额外注册任何东西，
  也不用在设置里填 client_id 之类的凭据 —— OAuth 应用是构建期打进安装包的，做法与 VS Code 相同
  （使用者的体验就是「有一个账号就行」）
- 流程也是 VS Code 那种：点登录 → 系统浏览器打开授权页 → 在浏览器里点同意 → 自动跳回应用。
  原理是应用在本机 `127.0.0.1:45871` 起一个极小的 HTTP 服务，并把那个地址注册成两家的回调地址 ——
  浏览器只是在访问本机的一个普通网页，所以**不需要注册自定义协议、也不需要管理员权限**
- 登录的用途是**授权 Token 同步的私有仓库**：登录之后才在设置里出现同步仓库地址那一项。
  凭据就用这个账号的 token 推送（凭据管理器里存着就自动用），省掉
  「先在命令行里给 git 配一次凭据」这一步；不登录也能同步、走系统 git 凭据 —— **那条退路一直是通的**：
  用不了的凭据（过期又续不上的）会被跳过而不注入，等于自动退回它
- **access_token 会过期，所以凭据里连 refresh_token 与到期时刻一起存**（Gitee 的 access_token 只有一天）。
  每次同步之前按需续期一次：没到期就是一次纯本地判断，不打网络；续期换来的新 refresh_token 要落盘 ——
  Gitee 是轮换的，旧的那张随即作废。到期又续不上时（老版本存的凭据里没有 refresh_token、或者平台拒绝了续期），
  同步失败的信息里会写清「去设置 → 账号里重新登录一次」，而不是只丢一句 HTTP 403
- 一次只保留一个账号（换一家登录会清掉上一家）：同步仓库只有一个，多留一个 token 只会让
  「现在到底是谁」变得含糊
- **凭据不落数据文件、也不进渲染层**：access_token、refresh_token 与到期时刻一起存成 Windows 凭据管理器里
  一条 `Workbench/<平台>/token` 的普通凭据（按当前 Windows 用户加密，能在「控制面板 → 凭据管理器 →
  Windows 凭据」里看到并手工删掉），界面只拿得到昵称与头像
- 回调没跳回来时（端口被占用、浏览器被拦下）弹窗里有**手动入口**：把浏览器地址栏里那条地址粘回去即可

**Node 版本与残留清理**

- 读取 `package.json` 的 `engines.node` 或 `.nvmrc`，与系统 node 比对，不满足时提示（不阻断）
- 检测 nvm-windows 已安装的版本，可为单个项目指定 Node 版本：执行时把该版本目录前置到子进程的
  `PATH`，不动全局软链、不需要管理员权限，多个项目可以同时跑不同版本
- 应用被强杀后，下次启动会清理上次残留的 dev server：先核对记录里的 `ownerPid`（宿主还活着就一律不动），
  再按**进程创建时间 + 存活判据**（`OpenProcess` + `GetProcessTimes` + `GetExitCodeProcess`）认进程 ——
  只判进程存在会把 PID 被复用的情况误当成「有主」而永远保留，而**已退出但进程对象尚未回收时创建时间依然可查**，
  得比对退出码才知道它已经死了；这两个坑都记在 `proc.rs` 的注释里。老记录缺这些字段时一律跳过，
  清理残留宁可漏掉几个，也不能杀错进程
- 清理有一处已知局限：会话记的是 `cmd /C` 那个**包装进程**的 PID，应用被强杀时它的 stdout 管道断裂、
  cmd 往往先于真正的 dev server 退出，记录里的 PID 没了，其后代也就无法定位 —— 这类孤儿清不掉。
  要彻底解决得给每个会话建 Job Object（`KILL_ON_JOB_CLOSE`，由系统在进程退出时连带收掉整棵树），
  但那会和退出确认里「直接退出（保留进程）」的语义冲突，需要先定取舍；抓整棵进程树（ToolHelp32）
  记录所有后代也能缓解，同样没有做

**npm 镜像源（nrm）**

- 系统状态卡片里多一行 nrm：能读到时显示**当前 npm 镜像**，点开下拉换一个（`nrm use <name>`）；
  命令行要等一次 node 冷启动，所以这一行是首屏之后异步补上的
- 镜像清单不写死在代码里：一律解析 `nrm ls` 的输出（含各镜像地址），taobao 改名 npmmirror 这类变化不用改代码；
  当前项优先认输出里的 `*`，认不出（没打星号 / 颜色干扰）时再拿 `npm config get registry` 对一遍地址
- 没装 nrm 时这一行整块是个安装按钮，点一下走 `npm install -g nrm`，过程与包管理器安装共用同一条通道
  （输出顶在卡片上、完整日志进底部终端、超时按进程树收掉）
- 切换改的是 npm 的**全局** registry，此后所有不带自己的 `.npmrc` 的项目都走新源；镜像名会先进一次
  合法性检查再交给 shell，避免名字里混进命令分隔符

## 技术栈

| 层 | 选型 |
|---|---|
| 桌面框架 | Tauri 2（Windows 上走系统 WebView2，不再随包附带 Chromium） |
| 后端 | Rust（窗口 / 托盘 / 单实例、子进程与日志、文件与 sqlite、系统能力） |
| 前端 | Vue 3（组合式 API + `<script setup>`）+ Element Plus + Pinia |
| 工作日志渲染 | markdown-it（只服务工作日志正文：`html: false` 转义原文里的标签、`linkify` 认裸地址、`breaks` 让单个换行就是 `<br>`，链接统一新窗口 + 交系统浏览器打开） |
| 笔记编辑器 | Vditor（只服务笔记正文；静态资源随包带一份、不走 CDN，见「笔记」那一节） |
| 构建 | Vite 8（渲染层，打包器是 rolldown）+ cargo / Tauri CLI（后端）。根 `package.json` 是 `"type": "module"`，所以三个 vite / vitest 配置里用 `import.meta.dirname`（`__dirname` 只在旧的打包式加载器下被 shim 出来；仓库里也不要有 CJS 的 `.js` / `.cjs`，它们会被当成 ESM） |
| 语言 | TypeScript（渲染层）+ Rust（后端）；契约与纯逻辑共用 `src/shared` |
| 持久化 | 本地 JSON，由 Rust 侧 `store.rs` 负责（防抖 300ms、临时文件 + rename、退出前同步落盘） |
| 子进程 | `std::process` 起 shell 命令（按批回传输出，Windows 下 `taskkill /T /F` 结束整棵进程树） |
| 端口 → 进程 | `GetExtendedTcpTable`（iphlpapi，一次系统调用拿到监听表）+ `QueryFullProcessImageNameW`；不再起 `netstat` / `tasklist` 解析文本输出（全量检测会并发问十几个端口，原先每个端口两个子进程） |
| Coding 用量数据源 | ZCode：`rusqlite` 只读打开本地 sqlite（WAL 并发读）；DeepSeek Harness：Rust 逐帧解压 `~/.dsh/sessions` 的多帧 zstd 会话；CodeBuddy：Rust 列扩展日志清单、渲染层读内容并解析；WorkBuddy：Rust 列会话正文清单、渲染层读内容并解析；Qoder：Rust 列 `~/.qoder-cn/projects` 的会话正文清单、渲染层读内容并解析（只取 `usage.credits`，它不报 token）。五者都只读，且只取用量数字 |
| Token 多机同步 | 可选（默认关闭）：`std::process` 直启系统的 `git`（不经 `cmd`，参数行不会被二次解析），推 / 拉一个用户指定的仓库；`token-usage/` 与 `config/` 两个目录、都是一台机器一个文件，且是两条互不相干的出口（用量自动 + 手动都只动前者，外观只在设置里点「同步一次」时动后者；采用别人的配置也只能手动点）。凭据默认走系统 git，登录过账号则改用该账号的 token（按 host 限定注入请求头，过期前自动续期，见下） |
| 账号登录 | 可选：GitHub / Gitee 的授权码流程 + 本机回环回调（RFC 8252 那套，与 VS Code 同路）。HTTPS 走系统自带的 WinHTTP，access_token 与 refresh_token 存 Windows 凭据管理器（DPAPI）—— 两者都只给已有的 `windows-sys` 加 feature，**没有引入任何新的 crate**。两家都要求 clientId + clientSecret，凭据由 `build.rs` 编译期内置 |
| 依赖取舍 | 新增 crate 的标准是**「不新增编译单元」**而不是「不新增名字」：`url` / `percent-encoding` / `form_urlencoded` / `walkdir` / `base64` / `sha2` 都已被 tauri / tao / wry / tauri-utils 拉进编译图（`cargo tree -e normal -i <crate>` 可查），所以直接用它们替掉手写的 URL 编解码、目录递归与摘要实现，代价为零。反过来，`reqwest`（hyper + tower + TLS 整套）、`git2`（libgit2 的 C 依赖）、`sysinfo` 会新增成片的编译单元，一律不引 |
| 测试 | Vitest（渲染层与 shared）+ `cargo test`（Rust） |
| 打包 | Tauri CLI → NSIS 安装包（Windows x64） |

架构上值得单独说一句：**后端刻意做薄**。它只提供「取原始数据 / 落盘 / 调系统能力」这几类能力，
合并、排序、修剪、状态机、命令构造这些业务语义都在渲染层的适配层里（`src/renderer/src/workbench/`）。
好处是绝大多数改动仍然是 Vite 的秒级热更新，只有动到系统能力时才开始重编 Rust（实测增量 4~15 秒，见 [dev-notes](dev-notes/)）。

适配层顶替的是「preload + 主进程」那条**进程边界**，所以它递给渲染层的列表一律是快照（`structuredClone`）：
渲染层的乐观追加（`[...list, created]`）不会和适配层刚改过的那份数据叠在一起，渲染层往自己列表里 push
也写不进要落盘的数据。在 Electron 版这件事是进程间复制免费给的，边界搬进同一个 JS 上下文后必须自己补 ——
漏掉时的表现是「添加一个程序先变成两个，过一会儿刷新又合成一个」。

**IPC 命令默认跑在主线程上**：`#[tauri::command]` 不加参数时是「阻塞」执行上下文，函数体会在
IPC 处理器所在的那个线程（主线程）上内联跑完。所以凡是会起子进程、读写文件、解码图片、跑 SQL 的命令
都标了 `(async)`（宏会生成为 `async_runtime::spawn`，落到工作线程），只有纯内存读写与窗口控制保持同步。
判断标准很简单：这个函数会不会等外部资源。漏标一个的后果不是「慢」而是「界面卡死」——
窗口消息循环被一起堵住，拖不动也不重绘，而渲染层的 `await` / `Promise.all` 完全挡不住（并发只在
JS 的 Promise 层面，真正干活的 Rust 还是那一条线程）。启动路径上踩过一次：包管理器探测（4 次
`cmd /C npm --version`）加壁纸缩略图把首屏冻了好几秒；现在这两项都改成了「挂载之后再拉」。

**工作区背景图走 asset 协议，后端不碰它的像素**：不再「解码 → 缩到 2560 → 编 JPEG → base64」回传
（一张 3824×2400 的实测 **249ms**、产物 270KB，而且每次启动都重算，那 249ms 正好落在首屏之后，
看起来就是「背景图要等一会儿才出来」）。现在渲染层只调一次 `allow_background`：后端只读文件头确认
它是张能解码的图（1ms 量级），再把**这一个文件**的读取权限授给 asset 协议，URL 由 `convertFileSrc`
转出来交给 CSS，图片由 webview 自己读、自己缩放。代价是全尺寸原图进 webview 内存（就是原图那么大）。
`tauri.conf.json` 里 `assetProtocol.scope` 刻意留空 —— 授权一律在运行时按文件给，
**别为了省事写成 `**`**，那等于把整个磁盘敞开给界面读。

## 开发

```bash
npm install

npm run dev              # 启动开发态（Rust 后端 + 渲染层热更新）
npm run typecheck        # 渲染层与测试两个 tsconfig 一起做类型检查
npm test                 # Vitest 单元测试（渲染层与 shared）
cargo test --manifest-path src-tauri/Cargo.toml   # Rust 侧测试
npm run build:renderer   # 只编渲染层，产物落 out/renderer
npm run preview:renderer # 只把渲染层跑在浏览器里，方便看布局（产物落 .preview/）
```

环境前置：Rust stable（`x86_64-pc-windows-msvc`）+ MSVC 生成工具 + Windows SDK。
不需要再为 native 模块准备编译环境 —— `better-sqlite3` / `node-gyp` 那套随 Electron 一起去掉了。

用 Token 多机同步的话，还需要系统里能跑 `git`（`git --version` 有输出即可），并且先登录账号。
**登录后这一步就不必再配 git 凭据**：同步用账号的 token 推送（凭据管理器里存着 token 就自动用），
而且 token 到期会自动用 refresh_token 续一次（Gitee 的只有一天，不续的话每天都会失败一回）。
不登录也能同步、走系统 git 凭据，但那种情况下首次同步一个私有仓库会直接报错而不是弹输入框
（子进程没有终端可问），得先在命令行对这个仓库执行一次 `git clone`（或 `git fetch`）把凭据存下来，
或者用 SSH 地址配好 key。

### 启用账号登录（只做一次，只有开发者需要）

OAuth 应用是**构建期内置**的，所以使用者拿到安装包就能直接登录、什么都不用配；代价是**打包的人**
要先去两家各注册一个应用。不是为了发布、只是自己用也一样 —— 凭据得有来源。

1. 把 [`src-tauri/oauth.example.json`](../src-tauri/oauth.example.json) 复制成 `src-tauri/oauth.local.json`
   （后者已在 `.gitignore` 里，**不要提交**）
2. **GitHub** → [github.com/settings/developers](https://github.com/settings/developers) → OAuth Apps → New OAuth App
   - Authorization callback URL 填 `http://127.0.0.1:45871/callback`（必填）
   - **取消勾选 "Expire user access tokens"**：它默认是勾上的，勾着的话 token **8 小时**就过期。
     勾着也能用（这种回包会带 refresh_token，应用到期会自己续），但为此多存一张每天要换的票没有好处
   - 填 `clientId` 与 `clientSecret`，**两项都要**。GitHub 支持 PKCE，但授权码流程里 client_secret
     仍是必需的（官方文档标为 Required）—— 只填 clientId 的话浏览器能授权成功，换 token 那一步会被
     `incorrect_client_credentials` 挡回来，表现成「点了登录没反应」
3. **Gitee** → [gitee.com/oauth/applications](https://gitee.com/oauth/applications) → 创建应用
   - 应用回调地址同样填 `http://127.0.0.1:45871/callback`
   - **权限范围至少勾 `user_info` 与 `projects`**：Gitee 的权限是注册时预先勾死的（不像 GitHub
     运行时再申请），漏勾 `projects` 会让同步私有仓库 403
   - `clientId` 与 `clientSecret` 两项都要填
4. 重新构建。凭据是**编译期**注入的：改了 `oauth.local.json` 不重新构建就不生效。
   没填凭据时应用照样能编译，只是账号弹窗会显示「当前构建未内置 OAuth 凭据」

改回调端口的话要同时改 `src-tauri/src/oauth.rs` 的 `REDIRECT_PORT` 与两家平台上注册的地址，
两边必须逐字一致（`oauth.rs` 里有一条测试钉住了这个串）。

```bash
npm run icons        # 需要改图标时：重新生成 src-tauri/icon.ico（窗口与托盘共用）
npm run dist:dir     # 产出免安装目录（只编不打包，用于快速验证）
```

打包配置见 [`src-tauri/tauri.conf.json`](../src-tauri/tauri.conf.json)；NSIS 安装包落在
`src-tauri/target/release/bundle/nsis/`。几点需要留意：

- 渲染层产物 `out/renderer` 是在**编译期**被内嵌进可执行文件的，所以改了前端要先 `npm run build:renderer`
  （`npm run dist` 与 `npm run dev` 都会自动带上这一步）。
- 内置壁纸经 `bundle.resources` 映射到 `backgrounds/`，运行时由 Rust 从 `resource_dir()` 读取
  （清单与缩略图用）；开发态资源不经过打包流程，`list_wallpapers` 会回落到仓库里的 `resources/backgrounds`，
  不过 `tauri dev` 会把资源拷到 `target/debug/backgrounds/` 下，实际优先命中那一份。
  工作区背景图本身经 asset 协议按文件加载，不走 `resource_dir()` 这条链。
- release 档位是 thin LTO + 16 个 codegen 单元，链接器换成工具链自带的 `rust-lld`
  （配置在仓库根的 [`.cargo/config.toml`](../.cargo/config.toml)）。**打包前先停掉 `npm run dev`**：
  两者会抢 `target/` 的构建锁并互相拖慢。取舍、实测数据与更多坑见
  [`dev-notes/build-performance.md`](dev-notes/build-performance.md)。

安装包为单用户、可选安装目录，卸载时保留 `workbench-data.json`，不会连带删掉项目列表。

## 数据与隐私

应用**默认不联网**。对外发请求的只有六处，且都是你自己开出来的：

- **Token 用量同步**（可选、默认关闭）：登录账号、且在设置里填了仓库地址之后，应用才会推 / 拉那个仓库；
  退出登录就停。**密码保险库推的是同一个仓库的另一个目录**（`vault/vault.json`），
  推上去的只有密文 —— 密钥只在本机（见「密码保险库」那一节），所以它不是第七个出口
- **账号登录**（可选）：点登录时才会访问 GitHub / Gitee 的授权接口；登录之后不会在后台反复打网络请求
  （头像只在打开账号弹窗时才重新拉一次）。唯一的例外是 access_token 到期后的**续期**：它只在同步之前
  （或打开账号弹窗刷新资料时）按需发生一次，走的还是那个换 token 的接口
- **笔记里的图片上传与清理**（可选、默认关闭）：只有填了图片仓库、并且你**真的往正文里粘贴了图片**
  （或打开素材管理删图），才会碰那个仓库；没填就是一句提示。文档里存的是外链，图片本身在你自己那个仓库里。
  正文里引用的外链图片与素材面板里的缩略图由 webview 直接按那个地址取 —— 取的是你自己仓库里的东西，
  与前面几处同一条边界（且页面级 `no-referrer` 让这些请求不带来源地址，见「笔记」那一节）
- **笔记本身的同步**（可选、默认关闭）：只有在设置里填了笔记仓库、并且你**点了那颗同步按钮**
  （或它将来接上自动同步时到点）才会走一次 git。同步的就是你那个笔记文件夹，推到你自己填的仓库里。
  **技能跟着这次提交一起走**：技能库就住在这个文件夹的子目录里（见「技能」一节），
  平时的增删改只在本机提交 —— 技能不是第七个出口，它就是笔记仓库里的另一种内容
- **命令执行本身**访问网络（`npm install`、dev server 之类），那不属于应用的行为
- **AI 热点**（量子位，免费、不需要凭据）：首页「AI 热点」卡片的数据源。**源地址是一份内置白名单**
  （Rust 侧 `ai_news.rs` 的 `SOURCES`，**只放中文源**），渲染层只能报源 id、拿不到任何地址。
  只有首页画着那张卡片、且到了它自己的刷新间隔，才会 GET 它；只读不传
  （每源独立 TTL + ETag 条件请求 + 429 退避，见 `shared/ai-news.ts`）。
  **站内阅读**是同一个出口的延伸：点开某一条时才去抓那篇正文，域名另有 `article_hosts` 白名单卡着
  （只认源站自己的域名与子域），页面脚本不执行、只取正文纯文本

六处都不经过任何第三方服务：三处 git 同步发往你自己给的那三个仓库（用量与配置、图片、笔记），
登录走两家平台官方的 OAuth 接口，AI 热点只 GET 宿主侧白名单里的那个公开源，
没有任何自建服务端，也不上报任何数据。落盘除了数据文件，还有一处**应用之外**的：

- **Windows 凭据管理器**：登录账号后那一组凭据（access_token / refresh_token / 到期时刻）存成一条
  `Workbench/<平台>/token` 的普通凭据。
  它刻意**不写进 `workbench-data.json`** —— 那是数据目录里的明文 JSON，能打开那个目录的人就能读到它。
  能在「控制面板 → 凭据管理器 → Windows 凭据」里看到并手工删掉，登出时应用也会删掉它。
  **密码保险库那把密钥也在这里**（`Workbench/vault/key`），同一条理由，而且更硬：
  它是解开全部密码的唯一一把钥匙，落进数据目录等于把明文密码摊在盘上。
  这一处与账号那条还有一个区别：**密钥会过一次 IPC**（加解密在渲染层做，见「密码保险库」那一节），
  是全项目唯一一处机密进渲染层的地方 —— 别把它当成可以推广的先例
- 数据文件里的账号资料只有昵称、头像与登录名，**没有 token**

其余落盘都在**数据目录**里（固定 `%APPDATA%/Workbench/data/`，不跟着任何设置走；
根目录 `%APPDATA%/Workbench` 是迁到 Tauri 之前的 Electron 版留下的 Chromium 配置目录，数据文件不跟它混）：

- `workbench-data.json`：项目列表、分组、快捷启动的常用软件、应用设置（含 `activeView` 与
  项目排序 / 工作页范围与维度 / 目录树摊开的层数这几项**行为偏好**，见上面的「上次看的那一档会被记住」）、
  按天聚合的活跃度计数（只留最近一年）、上次运行残留的子进程记录、账号的显示资料
- `token-usage.json`：**本机**的 Coding 用量快照，按「工具 → 天 → 模型」聚合（只留最近一年），
  也就是同步时推到 `token-usage/` 的那份文件（旧名字 `token-data.json` 会在启动时自动改名过来）。
  结构按多工具来源设计，明细不复制 —— ZCode 自己的数据库是明细账本，快照用于对抗上游清理。
  计数里带一个 `credits` 字段（额度口径，只有 Qoder 会填），它与 token 那几项同住一份快照、
  同一套合并规则，但**不参与 token 总量**：面板按口径二选一展示
- `work-log.json`：工作日志（工作页那条时间轴）。**只在本机**：它既不在
  `workbench-data.json` 里、也**不会被同步** —— 工作内容是最贴近个人记录的东西，
  多机合并也没有成立的口径（它不像用量数字那样可相加）。它就住在数据目录里，只属于这台机器
- `ai-news.json`：AI 热点卡片的上次拉取结果。**按源分开**存（每源一份 `etag / nextFetchAt /
  failCount / lastError / items`），合并视图是读的时候现算的 —— 所以撤掉一个源之后它的内容会立刻
  从卡片上消失（旧缓存里那份不再被并进来），不必等一次刷新。**只在本机、不进同步仓库**，
  与工作日志同一待遇。单源时代（v1）那种「字段都在顶层」的老结构
  不再迁移：里面的内容只属于那个已经撤掉的源，读到就当成空缓存，按当前清单重拉一遍即可。
- `vault.json`：**密码保险库**（见「密码保险库」那一节）。里面**只有密文** ——
  条目正文（名字 / 密码 / 备注 / 分组）全在密文里，明文只在内存中；密钥不在这里，
  它在 Windows 凭据管理器里。文件里露出来的只有条目条数、每条的改动时刻与设备 id、哪些 id 被删过。
  它同时是同步到 `vault/vault.json` 的那一份：与其余几个目录不同，**那份文件是所有机器共写的**
  （用户的要求），合并规则因此自己定死（按 id 取并集、取改动时间新的那份），不交给 git 去合
- **笔记没有数据文件**：笔记本就是用户自己挑的那个本机文件夹（见「笔记」那一节），
  里面的 `.md` 文件就是全部内容 —— 应用不复制它、也不把它写进任何数据文件，
  只记下「当前打开的是哪个目录」与「打开过的那几个」（都在 `workbench-data.json` 的设置里，
  即 `noteDir` 与 `noteDirs`；左栏**宽度**那份界面参数在 `theme.json`，与内容无关）。所以它天然
  **不进同步仓库**，换台机器接着写只需在那边选同一个文件夹（或它的一份拷贝）。
  旧版那棵笔记 JSON 树（`note-data.json`）早就不再读写，盘上那份可以自己删掉
- 快捷启动只存程序路径与参数，不放程序本体
- 程序图标按「路径 + 程序文件的修改时间」缓存在 `workbench-data.json` 里（每个 1.5~4.4 KB）：
  修改时间没变就直接用，不再打开程序解析图标资源（实测每个 27~53ms），程序升级换了图标会自动失效。
  只缓存抽成功的图标；抽取失败的不落盘，下次启动照常重试
- `device.json`：本机设备标识（一个 uuid），首次用到同步时生成。它**不会被同步**，
  两台机器拿到同一个 id 会互相覆盖文件，而且不会有任何报错

**一件需要如实说明的事**：安装包里内置了 OAuth 应用的 client_id（Gitee 还有 client_secret）。
这是「使用者零配置」的前提 —— VS Code 不需要你配任何东西，正是因为微软替它内置了；
代价是那个 secret 理论上能从安装包里逆出来。影响面被「回调地址必须是 `127.0.0.1:45871`」限死：
拿到 secret 也接不到别人的回调，且它只能冒充本应用、拿不到别的权限。不接受这一点的话，
就只能退回「每个使用者自己去两家平台注册应用」那条路。

读取别人的数据时一律只读、不改动它们的文件：ZCode 是 `~/.zcode/cli/db/db.sqlite`（WAL 下并发只读打开，
另有 `ZCODE_HOME` 可指到别处）；DeepSeek Harness 是 `~/.dsh/sessions/<项目>/<会话>/` 下的会话文件
（`DSH_HOME` 可指到别处；同一会话目录里 v3 与旧版文件并存时**只读 v3**，两个都读会把那次会话算两遍）；
CodeBuddy 是 `%APPDATA%/CodeBuddy CN/logs`（国际版没有 `CN` 后缀，`CODEBUDDY_DATA_DIR` 可指到别处）
里扩展目录 `Tencent-Cloud.coding-copilot` 下的 `.log`；WorkBuddy 是 `~/.workbuddy/projects/<项目>/`
下的会话正文 `.jsonl`（`WORKBUDDY_HOME` 可指到别处，注意它和 Electron 那个
`%APPDATA%/WorkBuddy` 不是一个目录，后者只有窗口状态）；Qoder 是 `~/.qoder-cn/projects/<项目>/`
下的会话正文 `.jsonl`（国际版是 `~/.qoder`，`QODER_DATA_DIR` 可指到别处）。
这五处的正文里都带着对话内容，我们只解析其中的用量字段，**不会把正文写进快照** ——
所以同步推给仓库的也只有模型名与计数。
Qoder 的会话里没有可读的 token 计数（它自己就不产生），解析出来的只有每次请求扣掉的额度，
落在 `credits` 那一个字段上、只喂 credits 口径。

同步用的克隆目录在 `%APPDATA%/Workbench/token-sync/`（机器本地的缓存，删掉会在下次同步时重新克隆）。
仓库里就两个目录：`token-usage/<设备id>.json` 是模型名与 token 计数（**没有对话内容**），
`config/<设备id>.json` 是那份 `theme.json` 的副本（明暗 / 主题色 / 顶部样式 / 卡片不透明度 /
终端高度 / 程序名称 / 工作区背景 / 导航菜单 / 首页布局这几个数字和字符串与清单）。
两者都**没有图片本体、没有项目信息**，别的机器上的文件我们也从不改动，只读取自己那份。
仍然建议用私有仓库。

一处如实说明：`config/` 里的背景字段是原样复制的，所以本机若用了一张自己磁盘上的图，
那条路径会出现在这个文件里（只是路径，不是图片）。这份**只在用户点设置 → 外观的「同步一次」时才推** ——
用量那条出口（面板按钮与一小时一轮的自动同步）不碰它，采用别人的配置也只能手动点「应用」。

三个已知边界：设备 id 在重装系统 / 清掉 `%APPDATA%/Workbench/data` 之后会变成一台「新设备」，
旧文件还留在仓库里就会把同一台机器的历史算两遍（需要到仓库里手工删掉旧文件）；
日期一律按各台机器的本地时区归天，两台机器不在同一时区时跨天边界会对不齐；
**数据目录不要设成多台机器共享的位置**（网盘 / 网络盘）—— 设备身份写在 `token-usage.json` 里，
共享之后两台机器会顶着同一个设备往同一个文件里写。共享数据目录在启用同步之前就已经不成立了
（项目列表是整份覆盖写，两台机器会互相盖掉），别为了同步把它指到网盘上。

笔记则本来就是用户自己目录里的文件，见「数据与隐私」）。
