# 悬浮球（float-ball）

显示实时上下行速率的一颗球，**在桌面上随便摆**。拖到屏幕左 / 右边缘才算**贴边** —— 贴边时**收起**
成一条竖流量条（6×48），鼠标移上去滑出来变成**整颗刻度环球**（76×76）、鼠标移开 1.5 秒再收回去；
**浮在桌面中间的球不收**，一直是整颗球。
它是一扇独立的置顶窗口 —— 主窗口收进托盘、最小化、被别的程序压住，它都照样在桌面上。

## 约束

- **窗口尺寸必须等于可见形状**。透明窗口的隐形区域照样吃鼠标点击（见 [screenshot.md](screenshot.md)
  的「透明不影响点击」），开一个大窗口只画一小颗球的话，那圈看不见的地方会把桌面上的点击全吃掉。
  所以收起就是那条竖条本身的 6×48、展开是 76×76，**收起 / 展开要真的改窗口尺寸与位置** ——
  这两件事全由 Rust 做（`ball.rs`），前端一条都不碰：capability 里位置 / 尺寸 / 置顶那几项一个都不给。
  收起态**只有那条竖条**：外面没有半圆底、没有边框、没有阴影 —— 有底就得把窗口开成底那么大，
  那圈看不见的地方正是上面说的问题。
- **球上不许有「画到窗口外面」的投影**。投影（模糊 + 偏移）一定画到窗口之外，而窗口就那么大，
  系统会把越界那部分齐着窗口边切掉 —— 落在桌面上就是「中间是圆、四边是直的灰方块」，
  四个角尤其扎眼（用户报的就是这个）。球填满窗口时没有哪种投影能不越界，所以这一层的深度只留
  **内侧**高光（`inset 0 1px 0`）。中心那枚钮的投影是安全的：它离窗口边 15px、模糊只有 5px，整圈都在窗口里。
- **贴边那一档一点缝都不留**。留缝看着好看，但鼠标甩到屏幕边时会被系统钳在最后一个像素上，
  那一像素落在缝里就是「不在窗口内」—— 展开态的球收不到 hover，于是「收起 → 指针落回竖条 → 展开」
  每两秒来回抖一次。贴边之后，指针在边上就永远在窗口里。（浮着那一档离边远，没有这回事。）
- **只有贴住屏幕左 / 右边才收起，浮着的一直是整颗球**。判据就一条：窗口撞到工作区左沿或右沿
  （`dock_of`）。屏幕中间摆着的一条 6×48 竖条既不像东西、也没地方可贴（用户报的就是这个：
  「这种情况不要收起，因为没有贴近侧边」）。Rust 与前端各拦一道：`set_open` 回绝浮着时的收起，
  前端鼠标移开之前先看贴没贴边。
- **不吸附**（用户明确要求）。松手停在哪儿就是哪儿，横向不往边上飞。够得着「贴边」的只有一种动作 ——
  往屏幕外拖、被工作区夹住（`sync_from_window`），松手时那一档就是精确贴边。所以拖到屏幕中间的球
  不会自己跑回边上，拖到边上的球松手就收起来（这一档由位置定，跟前端推的意图无关）。
- **只装适配层，不装 store、不 initState**。它是第四个 HTML 入口（`ball.html`），
  与 capture / pin 同一套规矩：独立窗口、各自的 JS 上下文，装了 store 会与主窗口抢着读写同一批 JSON。
- **采样口径：字节数排除环回、只要「已连接」的网卡，其余全部相加**（用户选的「所有网卡合计」）。
  **已知偏差**：开着 VPN / WSL / Hyper-V 时同一份流量会在虚拟网卡与物理网卡上各算一次，数字偏大。
  要精确就得改成「在设置里勾选网卡」，那是另一个设置项加一条列网卡的通道，这一版不做。
- **链路速率（表盘量程的顶）只认物理网卡**（`InterfaceAndOperStatusFlags` 第 0 位），且取**最快那条**而不是相加 ——
  虚拟网卡报的 100Gbps 是虚数，相加之后量程被推到几百 GB/s，等于把刻度抹平。
- **表盘的量程是自动换挡的，不是「占链路带宽的比例」**（用户报的：「网速大部分时间都比较小，
  外围的圈长时间没有绘制」）。`dialShare` / `dialRange`（[meter.ts](../../packages/net-meter/src/meter.ts)）里定这一条：
  满刻度取 **1MB/s 的 2 的幂**（1M / 2M / 4M / 8M…），**换挡点在量程的一半** ——

  | 速率 | 满刻度（这一档的 100%） |
  | --- | --- |
  | < 0.5M | 1M |
  | 0.5M ~ 1M | 2M |
  | 1M ~ 2M | 4M |
  | 2M ~ 4M | 8M |
  | 以此类推 | … |

  于是点亮的部分总在 1/4 ~ 1/2 圈之间：**速率翻倍就换挡、弧长回落到 1/4 那一头**，
  「又翻了一倍」一眼能看出来，量程也不会被顶死（旧口径在千兆网里给 1.6MB/s 只有 1 格）。
  刻度环与收起态那条竖条**共用这一个占比**，不许各算一套。
  唯一一处例外：量程翻到**链路带宽那一档就到头**（满环 = 跑满自己的管子，再快夹在 1）；
  取不到链路带宽（只有虚拟网卡）时不封顶，量程照翻。
- **入口的高度链必须是定值**：`html` / `body` / `#ball` 一路都要 `height: 100%`（见 `ball.html`）。
  CSS 里百分比高度遇到 auto 高的父级会退化成 auto —— 组件根上的 `height: 100%` 一失效，
  里面按百分比算高度的那几层（中心那枚钮是 68%）就只剩内容的自然高度，球会变成一个**扁椭圆**
  （宽 76、高四十出头）。pin / capture 那两个入口同一条链也是 auto 的，它们没露馅只是因为
  内容高度恰好接近窗口高度 —— 球这边内容矮得多，一上来就现形了。
- **收起 / 展开时先记状态、再摆位**：摆窗口尺寸与位置会派发出 `Moved` / `Resized`，
  而那两条事件是异步派发的、处理时会读当前状态。顺序反了的话，事件读到的还是旧状态，
  会按旧状态算出来的 x 把刚摆好的位置改回去（现象是窗口宽 76、位置却还留在贴边那一档）。
  `BallState::moving` 那面旗是第二道保险：程序化摆位的那一小段里，事件一律不参与落定。
- **建窗口的命令必须标 `#[tauri::command(async)]`**：IPC 命令默认在主线程跑，而
  `WebviewWindowBuilder::build()` 要等主线程去泵消息 —— 在主线程里等主线程就是死锁，
  现象是这条通道永远不返回、窗口停在 `about:blank`（踩过一次，见下面「验证」）。
  `capture_prewarm` / `pin_create` 两条建窗口的命令同此。
- **只用 64 位计数器**（`GetIfTable2` / `MIB_IF_ROW2`）。`GetIfTable` 那套的 `dwInOctets` 是 32 位，
  100Mbps 下几分钟就在 4GB 处回绕，读数会突然变负再爬回来 —— 这个功能每秒读一次，正撞在回绕上。
- **Rust 只取原始数，不算速率**。速率 / 单位进位 / 平滑都在 `packages/net-meter`
  （后端只做「取原始数据 / 调系统能力」，业务语义留在 TS 这一侧）。
- **本功能没有任何新的联网出口**：读的是本机网卡的计数器，一个包都不发、也不上报。
  （十处出口的清单见 [features-and-architecture.md](../features-and-architecture.md) 的「数据与隐私」。）
- **位置只对本机成立**：落 `data\ball.json`（`pins.json` 同一待遇），不进同步仓库、不上云。
  记「窗口左上角的 x / y + 贴着哪一侧」，**不记收起还是展开** —— 那是位置的即时结果，重启回来按位置
  重算一遍（贴边的回到那条边、浮着的还在原地）。上一版那份「只记 side + y」的账认不出来，
  当没记过、重新落一个默认位置。
- **拖动时两个方向都只夹进工作区，横向不往边上吸**。夹的是「不出屏幕、不压任务栏」；横向在这儿贴边的话
  窗口就弹回原来那条边，中心永远跨不过屏幕中线，球也就摆不到桌子中间
  （踩过一次：用户报「无法左右拖动」就是它）。贴没贴边留到**松手**之后判，见 `settle_drop`。
- **「松手了没有」认左键，不认静默**（`dragging` 读 `GetAsyncKeyState`）。系统的
  `WM_EXITSIZEMOVE` 到不了这一层，只能自己认；而「多久没 `Moved`」分不出**拖着停住**与**已经松手**：
  只判静默的话，拖到一半停一下就被当成松手，球在手里被摆一道（现象是拖动不跟手）；
  而真松手那一下**不产生任何 `Moved`**，那一轮已经用掉，没人再补一次落定 —— 球停在半路上。
  巡检线程因此要**活到真的松手**：按着就一直等，松手再落定。
- **只有「手按着搬出来的」位移才安排落定**（`sync_from_window` 里看左键按没按着）。悬停展开 / 收起
  也是程序化摆位、同样会派发 `Moved` / `Resized`，可那不是拖动 —— 它们要是也走进落定，
  「贴边就收起」会在 250ms 后把刚摊开的球收回去，指针还压在球上就又摊开，收放收放没完
  （用户报的）。落定要回答的是「用户把球丢在哪儿」，所以判据与「松手了没有」同一条：左键按着。
- **尺寸与位置必须一起落地**。写摆位的有仨：展开、收起（前端推的两条命令各跑在一条工作线程上）
  与松手落定（巡检线程）。`set_size` 与 `set_position` 是分开下发的，中间被别的写者插一脚，
  两者的档位就配错 —— 尺寸落成展开的 76、位置却是收起那一档的 x，球只剩屏幕边上半条
  （用户报的「收不起来 / 只剩一条」）。所以：整对在同一把锁里下发（`PLACE_LOCK`），
  而且**落定那一下连尺寸一起比对、对不上就整颗重新摆**（它读的 `open` 也要在同一把锁里读，
  否则会拿刚过期的那份去算位置）—— 半截状态最多留到下一次落定，不会一直挂在那儿。
- **整块球都标 `data-tauri-drag-region="deep"`**。裸属性只认「正好按在带属性的那个元素上」：
  球中间的数字、单位与 48 格刻度线都是子元素，按在那儿起不了拖动 —— 现象是「球抓不住、
  只有摸到某几处才拖得动」。球里没有一个可点元素（没有 `a` / `button` / `tabindex`），
  `deep` 不会顺手把别的交互吃掉；双击最大化那条路也走不到（球是 `resizable(false)`，
  `internal_toggle_maximize` 自己会跳过去）。
- **前端的「上一次推给 Rust 的意图」要跟着实际状态对齐**。展开 / 收起是双向的：前端推的
  （鼠标进出）、Rust 自己也会改（松手贴边就收起 / 摊开）。`requested` 只在推的时候记、回包时不校正的话，
  松手贴边收起之后指针再移上去，那次 hover 正好撞上判重 —— 窗口明明收着，指针移上去却没反应。
- **展开后 600ms 内不收回**。展开是「窗口长大 + 往屏内挪」同时发生的：窗口刚挪完，指针可能正好落在球外面，
  于是立刻收到一个 `mouseleave` —— 不设这条就会「展开 → 收回 → 再展开」来回抖。
- **开关的语义**：关掉 = 关掉那扇窗口（位置留着，下次开回来还在原地）；开着 = 桌面上一直有它。
  值由渲染层推（Rust 不读设置，理由同 [screenshot.md](screenshot.md) 的快捷键那一条）。
- 收起态那条竖条与展开态的表盘**共用同一个 `netCounters` 读数**，不给收起态单开一条通道。

## 实现

**涉及文件**

- `packages/net-meter/src/` —— 纯逻辑：`meter.ts`（速率 / 平滑 / 单位 / 表盘占比 `dialShare`）、`dial.ts`（表盘几何与尺寸常量）、
  `wire.ts`（IPC 契约：`NetCounters` / `BallContext`）
- `apps/desktop/src-tauri/src/net.rs` —— 读网卡累计字节与链路速率（`GetIfTable2`）
- `apps/desktop/src-tauri/src/ball.rs` —— 窗口、收起 / 展开、贴边判定、记账
- `apps/desktop/src-tauri/Cargo.toml` —— 给已有的 windows-sys 加 `Win32_UI_Input_KeyboardAndMouse`
  （判左键还按着没有，见「松手了没有认左键」那条；只是加 feature，不新增编译单元）
- `apps/desktop/src-tauri/src/paths.rs` 的 `ball_file()` —— `data\ball.json`
- `apps/desktop/src/renderer/ball.html` + `src/renderer/src/ball/` —— 第四个入口与那颗球
- `apps/desktop/vite.config.ts` 的 `rollupOptions.input`（四个入口）
- `apps/desktop/src/renderer/src/workbench/index.ts` 里那一段通道、`types.ts` 的 `ballEnabled`
- `components/settings/GeneralPane.vue` 的「网速球」开关
- `apps/desktop/src-tauri/capabilities/capture.json`（`windows` 里含 `ball`）

**两个状态与两套尺寸**（`ball.rs` 的 `place()`，纯函数、带单测）

| | 收起 | 展开 |
| --- | --- | --- |
| 窗口（逻辑像素） | 6×48 竖流量条 | 76×76 整颗球 |
| 位置 | 贴齐屏幕左 / 右边（不留缝） | 贴边时同样贴齐；浮着时就是记账里那个位置（只夹进工作区） |
| 什么时候 | 贴着左右边时（默认 / 鼠标移开 1.5s 之后） | 浮着时（默认，鼠标移开也不变）/ 贴边时鼠标移进竖条 |

宽度按 `scale` 折成物理像素再算 x 与夹取：**尺寸给的是逻辑像素**（DPI 变了系统自己跟着缩放），
**位置给的是物理像素**（与遮罩窗口同一条口径）。两者混着算就会在缩放屏上错位。
贴边那一档的 x 由那条边算出来（左：工作区左沿；右：右沿减窗口宽）—— 收起 6 宽、展开 76 宽，
照搬记账里的 x 会露一条缝或者伸出屏幕外。

**贴边判定与拖动**

`dock_of`（纯函数）判贴没贴边：窗口撞到工作区左沿（`x <= left`）或右沿（`x + width >= right`）就算贴住
那一边，否则是 `None`（浮着）。**不留容差、也不是磁吸** —— 拖动中横向会被夹进工作区，
所以「往屏幕外拖」落到这儿就是精确贴边；离边差一个像素的球就停在那儿、不收。

拖动交给系统（页面上的 `data-tauri-drag-region="deep"`，跟手），Rust 挂在窗口的 `Moved` / `Resized`
上把几何读回来（`sync_from_window`）：两个方向都只夹进工作区、**横向一点不吸**，顺手把 x / y 记进账；
**只有左键按着的那几次才安排落定**（见上面那条约束）—— 悬停展开 / 收起也走这两个事件，
它们不该被当成「丢下球」。松手之后由一条巡检线程（每 80ms 看一眼：**左键松开了**、
且静默满 `DRAG_SETTLE_MS` 才动手）落定（`settle_drop`）：判贴没贴边 → **贴边就收起、浮着就展开**
→ 记账 + 摆位。左键那一下读 `GetAsyncKeyState`（`dragging()` / `should_settle()`）—— 只给已有的 windows-sys 加一个 feature
（`Win32_UI_Input_KeyboardAndMouse`），不新增编译单元。这一轮巡检**活到真的松手**才收工：
按着不动就一直等着（位置归手），所以「拖着停住」不会把球抢走。
展开 / 收起 / 落定三处的摆位排在同一把 `PLACE_LOCK` 上（`place_now` / `place_locked` / `settle_drop`）：
`set_size` 与 `set_position` 是一对，中间插进别的写者会把两者的档位配错（见上面那条约束）。
落定那一步是「读位置 → 判贴边 → 落地」整段持锁，并且**尺寸对不上也回正** —— 它同时兜住
「被拆开过的窗口」这一类半截状态。
`BallState::moving` 那面旗是让程序化摆位期间的事件不参与落定 —— 但 `set_size` / `set_position`
在非主线程上是**排队下发**的，事件往往在旗落下之后才到，真正兜住「不拿旧状态盖新位置」的是
`set_open` / `settle_drop` 里「先记状态、再摆位」那个顺序。
多屏时按窗口当前所在那块屏的工作区算（`current_monitor`，取不到就退到主屏）。

**前端那条链**（`BallApp.vue`）

`open`（画哪一副）与 `side`（贴没贴边，`null` = 浮着）都以 Rust 的回包为准，挂在窗口 `resize` 上重读
（`syncContext`）—— 松手贴边「自动收起 / 摊开」是 Rust 改的，前端只能从那儿知道。
`applyOpen` 判重用的**不是**窗口的实际状态 `open`，而是「上一次推给 Rust 的意图」（`requested`）——
收起还在路上时指针又移回球上，拿 `open` 判会把那次展开吞掉（窗口停在收起那一档、指针明明在球上，
得先把指针挪开再回来才好）；而每次拿到回包（`syncContext` 与 `applyOpen` 各一次）都拿实际状态
对齐一遍 `requested`（理由见约束里那条）。
鼠标移开（`onLeave`）之前先看 `side`：**浮着的不收**，也就不会白推一次注定被回绝的收起。
`ready` 之前什么都不画（窗口本来透明）：窗口尺寸是 Rust 定的，形状还没取回来时画任何一帧都可能是错的
—— 浮着的球可能正好是 76 见方，照收起态画出来就是一条拉满窗口、顶着两个圆头的怪条。

**表盘几何**（`dial.ts`）

**刻度环**：一圈 48 格刻度（内端在半径 29、长 4.4、粗细 1.7），第 0 格在 12 点、顺时针排。
点亮多少格 = **上下行合计在当前量程上的占比**（`round(48 × dialShare(...))`，凑不满半格就是 0 ——
宁可看着没动静，也不虚报一格）；点亮的那一段里，**靠前的几格是下行的份（绿）、后面是上行的份（橙）**，
所以一圈刻度同时说了两件事：这一档用了多少、其中上下行各占多少。
量程怎么换挡（1M / 2M / 4M / 8M…，换挡点是量程的一半）见约束里那条，只写在 `dialRange` / `dialShare` 一处，
组件与用例都从它取。整圈刻度始终画满 48 格（没点亮的一格是 8% 白的暗轨道）——
`dialShare` 不返回「未知」，所以「一格都不亮」只会出现在真没流量的时候。

那圈刻度是画在**球自己那层玻璃上**的（`.ball--open` 的圆底），不是飘在桌面上 ——
少了这层底，未点亮的几十格（8% 白）压在浅色桌面上等于没有，整圈看着只剩亮起来的一段。

中心那枚 hub 是抬起来的一层（顶部高光 + 外投影，投影整圈都在窗口里），数字用等宽字体、
单位缩到 0.72 倍并降到 62% 不透明度。
没流量时亮的格与数字一起降级 —— 球看起来是「睡着了」，而不是还在报 0。

**收起时那条竖条**：竖条**就是窗口本身**（6×48 逻辑像素，贴着屏幕边），里面是一段自下而上的填充 ——
总高 = 上下行合计在同一个量程上的占比（与刻度环同一条口径，见约束里那条），
填充里靠下的橙段是上行的份、上半的绿段是下行的份。
轨道用 92% 的深色（没有半圆底了，9% 白压在浅色桌面上等于没有）。没流量时填充退成 16% 白。

**采样与节流兜底**

球窗口每秒问一次 `net_counters`，用两次累计字节的差算速率，**按真实经过时间折算、不假设正好一秒**。
间隔短于 200ms 当重复触发、长于 5000ms 当被节流（窗口被完全遮住时 WebView2 的定时器会被节流，
见 [mail.md](mail.md)）：这两种情况都**整帧丢掉、保留上一次读数**，而不是把「五分钟的平均值」当成一个瞬时速度。
计数器倒着走（网卡被拔掉、计数器重置）按 0 算，不报负速率也不报尖峰。

**记账**

`data\ball.json` 只有三个字段：`{ "x": 880, "y": 300, "side": "left" | "right" | null }`。
`x` **只在浮着时算数**（贴边时 x 由那条边算，见「两个状态与两套尺寸」），`side` 为空就是浮在桌面上。
首次出现贴在右侧、纵向约 40% 处。窗口被系统关掉（Alt+F4 / 任务管理器）**不清记账** ——
它是位置偏好，不是「这个球还开着」的凭据；开关在设置里。

## 验证

界面上没有第二条入口，验证走真应用那条路（配方见
[browser-preview-verification.md](../dev-notes/browser-preview-verification.md) 的「在真应用里验证」）：

1. 起来之后 `/json/list` 里应当**多出 `ball.html` 那个 target**（但只有开了开关才有窗口）；
2. 在设置里打开「网速球」→ 桌面右边缘出现那条竖条，`data\ball.json` 里出现 `x` / `y` / `side`；
3. 鼠标移上去 → 窗口从 6×48 变成 76×76（用 `EnumWindows` + `GetWindowRect` 量，或者连球窗口的 CDP
   读 `innerWidth` / `innerHeight`）；**指针停在球上不许收放来回抖**（会抖就是落定那道闸没关严：
   程序化摆位也派发 `Moved`，见约束里那条）；移开 1.5 秒再变回去；
4. **从球正中间（数字上）**按住拖到屏幕中间松手 → 球**停在落点**（不弹回边上）、鼠标移开也**不收起**；
   `ball.json` 里就是那个 `x` / `y`，`side` 是 `null`（那儿曾是死区：裸 `data-tauri-drag-region`
   只认正好按在带属性的元素上，见约束里那条）；
5. 拖到屏幕左 / 右边缘（横向被夹住）松手 → 位置贴齐那条边、窗口收成 6 宽的竖条，`side` 跟着变；
   再从那块拖出来松手 → 摊回整颗球、`side` 变 `null`；
6. 拖到屏幕中间**按住不动**一两秒 → 球停在手底下，不许被摆一道；松手就停在落点；
   尺寸与位置必须是同一档：贴右边展开态是 `x = 屏宽 − 76`，出现「76 宽的窗口挂在 `x = 屏宽 − 6`」
   （屏幕上只剩贴着边的一条）就是摆位被拆开了（见约束里那条）；
7. 重启应用 → 球回到记账里那个位置（贴边的回到那条边、浮着的还在原地，`ball::load` 读的就是那份记账）；
8. 平时带点流量（刷网页、看视频，1~2MB/s）→ 刻度环就该亮出**十几二十格**、中心数字也在动；
   速率翻一倍时弧长会**回落到 1/4 圈那一头**（换挡，不是掉速）；下载一个大文件 → 弧继续爬；
   把管子跑满（或者量程顶到链路带宽）时整圈点亮（`net_counters` 的 `inOctets` 在涨，
   单位进位与一位小数由 `@workbench/net-meter` 的用例覆盖）。**只有一两格就是量程没生效** ——
   千兆链路上 1.6MB/s 按老的「占链路带宽比例」正好是这个样子（`dialShare` 的用例里有这个数）；
9. 关掉设置里那个开关 → 窗口消失，`ball.json` 仍在。
