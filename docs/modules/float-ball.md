# 悬浮球（float-ball）

显示实时上下行速率的一颗球，**在桌面上随便摆**。拖到屏幕左 / 右边缘才算**贴边** —— 贴边时**收起**成一条竖流量条
（6×48），鼠标移上去滑出来变成**整颗刻度环球**（76×76）、鼠标移开 1.5 秒再收回去；**浮在桌面中间的球不收**，
一直是整颗球。它是一扇独立的置顶窗口 —— 主窗口收进托盘、最小化、被别的程序压住，它都照样在。

## 约束

- **窗口尺寸必须等于可见形状**。透明窗口的隐形区域照样吃鼠标点击（见 [screenshot.md](screenshot.md) 的「透明不影响
  点击」），开大窗口只画小球的圈看不见的地方会把桌面点击全吃掉。所以收起就是竖条本身的 6×48、展开是 76×76，
  **收起 / 展开要真的改窗口尺寸与位置** —— 全由 Rust 做（`ball.rs`），前端一条都不碰：capability 里位置 / 尺寸 /
  置顶那几项一个都不给。收起态**只有竖条**：外面没有半圆底、边框、阴影 —— 有底就得把窗口开成底那么大。
- **球上不许有「画到窗口外面」的投影**。投影（模糊 + 偏移）一定画到窗口外，窗口那么大，系统会齐着边切掉 —— 落在
  桌面上就是「中间圆、四边直的灰方块」，四角尤其扎眼。球填满窗口时没有哪种投影能不越界，所以深度只留**内侧**高光
  （`inset 0 1px 0`）。中心那枚钮的投影安全：离窗口边 15px、模糊只有 5px，整圈都在窗口里。
- **贴边那一档一点缝都不留**。留缝好看，但鼠标甩到屏幕边会被系统钳在最后一像素，那一像素落在缝里就是「不在窗口
  内」—— 展开态的球收不到 hover，于是「收起 → 指针落回竖条 → 展开」每两秒抖一次。贴边后指针在边上就永远在窗口里。
- **只有贴住屏幕左 / 右边才收起，浮着的一直是整颗球**。判据一条：窗口撞到工作区左沿或右沿（`dock_of`）。屏幕中间
  摆一条 6×48 竖条既不像东西、也没地方可贴。Rust 与前端各拦一道：`set_open` 回绝浮着时的收起，前端鼠标移开前先看
  贴没贴边。
- **不吸附**（用户明确要求）。松手停在哪儿就是哪儿，横向不往边上飞。够得着「贴边」的只有一种动作 —— 往屏幕外拖、
  被工作区夹住（`sync_from_window`），松手时那一档就是精确贴边。
- **只装适配层，不装 store、不 initState**。它是第四个 HTML 入口（`ball.html`），与 capture / pin 同一套规矩：独立
  窗口、各自 JS 上下文，装了 store 会与主窗口抢读写同一批 JSON。
- **采样口径：字节数排除环回、只要「已连接」的网卡，其余全部相加**（用户选的「所有网卡合计」）。**已知偏差**：开
  VPN / WSL / Hyper-V 时同一份流量会在虚拟与物理网卡各算一次，数字偏大。精确就得改成「在设置里勾选网卡」，那是另一个
  设置项加一条列网卡的通道，这一版不做。
- **链路速率（表盘量程的顶）只认物理网卡**（`InterfaceAndOperStatusFlags` 第 0 位），且取**最快那条**而不是相加 ——
  虚拟网卡报的 100Gbps 是虚数，相加把量程推到几百 GB/s，等于抹平刻度。
- **这条过滤不许拿「链路速率不超过多少」当用例判据**：那是台机器一条的判据 —— CI runner 那块网卡自己就是**带
  `HardwareInterface` 位的虚拟网卡**、报 50Gbps，「≤ 40Gbps」哨兵在那边必炸（2026-10-14 踩过）。只认物理网卡这条
  过滤由 `net.rs` 里**合成数据**的用例覆盖；真机只验口径 —— 报出来是**某张网卡实际报的值**、且有网卡能相加时它不等于
  合计（`net::tests::本机的链路速率是某一张网卡那一档而不是各卡相加`）。
- **表盘量程自动换挡，不是「占链路带宽的比例」**（用户报的：「网速大部分时间都比较小，外围圈长时间没绘制」）。
  `dialShare` / `dialRange`（[meter.ts](../../packages/net-meter/src/meter.ts)）定这一条：满刻度取 **1MB/s 的 2 的幂**
  （1M / 2M / 4M / 8M…），**换挡点在量程的一半** ——

  | 速率 | 满刻度（这一档的 100%） |
  | --- | --- |
  | < 0.5M | 1M |
  | 0.5M ~ 1M | 2M |
  | 1M ~ 2M | 4M |
  | 2M ~ 4M | 8M |
  | 以此类推 | … |

  于是点亮部分总在 1/4 ~ 1/2 圈之间：**速率翻倍就换挡、弧长回落到 1/4 那头**，「又翻了一倍」一眼能看出，量程也不会
  顶死（旧口径在千兆网里给 1.6MB/s 只有 1 格）。刻度环与收起态竖条**共用这一个占比**，不许各算一套。唯一例外：量程
  翻到**链路带宽那一档就到头**（满环 = 跑满自己的管子，再快夹在 1）；取不到链路带宽（只有虚拟网卡）时不封顶。
- **入口的高度链必须是定值**：`html` / `body` / `#ball` 一路都要 `height: 100%`（见 `ball.html`）。百分比高度遇到 auto
  父级会退化成 auto —— 组件根 `height: 100%` 一失效，里面按百分比算的几层（中心钮是 68%）只剩自然高度，球变成**扁椭圆**
  （宽 76、高四十出头）。pin / capture 同一条链也是 auto 的，它们没露馅只是内容高度恰好接近窗口高度。
- **收起 / 展开时先记状态、再摆位**：摆尺寸与位置会派发 `Moved` / `Resized`，那两条异步派发、处理时读当前状态。顺序
  反了的话事件读到旧状态，会按旧状态算的 x 把刚摆好的位置改回去（窗口宽 76、位置却还在贴边那档）。`BallState::moving`
  旗是第二道保险：程序化摆位那一小段里事件一律不参与落定。
- **建窗口的命令必须标 `#[tauri::command(async)]`**：IPC 默认主线程跑，而 `WebviewWindowBuilder::build()` 要等主线程泵
  消息 —— 主线程里等主线程就是死锁，现象是通道永远不返回、窗口停在 `about:blank`。`capture_prewarm` / `pin_create`
  两条同此。
- **只用 64 位计数器**（`GetIfTable2` / `MIB_IF_ROW2`）。`GetIfTable` 那套 `dwInOctets` 是 32 位，100Mbps 下几分钟就在
  4GB 处回绕，读数突然变负再爬回来 —— 这功能每秒读一次，正撞回绕。
- **Rust 只取原始数，不算速率**。速率 / 单位进位 / 平滑都在 `packages/net-meter`。
- **本功能没有任何新的联网出口**：读的是本机网卡计数器，一个包都不发、也不上报。（出口清单见
  [features-and-architecture.md](../features-and-architecture.md) 的「数据与隐私」。）
- **位置只对本机成立**：落 `data\ball.json`（`pins.json` 同一待遇），不进同步仓库、不上云。记「窗口左上角 x / y +
  贴着哪一侧」，**不记收起还是展开** —— 那是位置的即时结果，重启按位置重算（贴边的回那条边、浮着的还在原地）。
  上一版「只记 side + y」的账认不出来，当没记过、重新落默认位置。
- **拖动时两个方向都只夹进工作区，横向不往边上吸**。夹的是「不出屏幕、不压任务栏」；横向在这儿贴边窗口就弹回原来
  那条边，中心永远跨不过中线，球摆不到桌子中间（用户报「无法左右拖动」就是它）。贴没贴边留到**松手**后判，见
  `settle_drop`。
- **「松手了没有」认左键，不认静默**（`dragging` 读 `GetAsyncKeyState`）。系统的 `WM_EXITSIZEMOVE` 到不了这层，只能
  自己认；「多久没 `Moved`」分不出**拖着停住**与**已经松手**：只判静默的话拖到一半停一下就被当松手，球在手里被摆一道
  （拖动不跟手）；真松手那下**不产生任何 `Moved`**，没人再补落定 —— 球停在半路。巡检线程因此要**活到真的松手**。
- **只有「手按着搬出来的」位移才安排落定**（`sync_from_window` 看左键在不在按）。悬停展开 / 收起也是程序化摆位、同样
  派发 `Moved` / `Resized`，可那不是拖动 —— 也走进落定的话，「贴边就收起」会在 250ms 后把刚摊开的球收回，指针还压着
  就又摊开，收放没完。落定要回答「用户把球丢在哪儿」，判据与「松手没」同一条：左键按着。
- **尺寸与位置必须一起落地**。写摆位的有仨：展开、收起（前端推的两条命令各跑一条工作线程）与松手落定（巡检线程）。
  `set_size` 与 `set_position` 分开下发，中间被别的写者插一脚，两者档位就配错 —— 尺寸落成展开的 76、位置却是收起那档的
  x，球只剩屏幕边上半条（用户报「收不起来 / 只剩一条」）。所以整对在同一把锁里下发（`PLACE_LOCK`），而且**落定那下连
  尺寸一起比对、对不上就整颗重摆**（它读的 `open` 也要在同一把锁里读）—— 半截状态最多留到下一次落定。
- **拖动由 Rust 按光标位置自己搬窗口，不走系统移动循环**。原先整块球标 `data-tauri-drag-region="deep"`（交给 Windows
  模态移动循环），可这扇窗是「透明 + 不抢焦点（`focused(false)` → `WS_EX_NOACTIVATE`）+ 置顶」的小窗 —— 那条循环对它
  **只画一个矩形轮廓、不搬内容**（用户报「拖动时球不走，只有矩形边框在走」）。现在前端只在 `pointerdown` 喊一声
  `ball_drag`，Rust 记住按下那刻光标在窗口里的偏移，之后每 16ms 按光标位置摆一次，松开左键收工（`drag_loop`）；夹取
  口径与 `sync_from_window` 一样。位置仍然**一条都不经前端**（capability 里那几项照旧一个不给）。
- **起手 3px 之内不算拖动，没真的挪动就不落定**。双击球是唤出主界面：按下那下不该把球挪走，更不该顺势落定 —— 展开
  着的贴边球会被收回 6px 竖条，双击第二下就甩到球外面。所以 `drag_loop` 一次都没搬过时直接回当前状态、不调 `settle_drop`。
- **拖动期间前端不推收起 / 展开**（`BallApp.vue` 的 `dragging`）。窗口在跟光标跑，指针从窗口滑出去（贴边被夹住那档）
  不是「鼠标移开」；更要紧的是那两条命令都会顺手摆一次窗口，照着推会把球从手底下摆回原来那条边。
- **前端的「上一次推给 Rust 的意图」要跟实际状态对齐**。展开 / 收起双向：前端推的（鼠标进出）、Rust 也改（松手贴边
  就收起 / 摊开）。`requested` 只在推时记、回包不校正的话，松手贴边收起后指针再移上去，那次 hover 正好撞判重 —— 窗口
  明明收着，指针移上去却没反应。
- **展开后 600ms 内不收回**。展开是「窗口长大 + 往屏内挪」同时发生的：刚挪完指针可能正好落在球外，立刻收到 `mouseleave`
  —— 不设这条就会「展开 → 收回 → 再展开」抖。
- **开关语义**：关掉 = 关掉那扇窗口（位置留着，下次开回来还在原地）；开着 = 桌面上一直有它。值由渲染层推（Rust 不读
  设置，理由同 [screenshot.md](screenshot.md) 快捷键那条）。
- 收起态竖条与展开态表盘**共用同一个 `netCounters` 读数**，不给收起态单开通道。

## 实现

**两个状态与两套尺寸**（`ball.rs` 的 `place()`，纯函数、带单测）

| | 收起 | 展开 |
| --- | --- | --- |
| 窗口（逻辑像素） | 6×48 竖流量条 | 76×76 整颗球 |
| 位置 | 贴齐屏幕左 / 右边（不留缝） | 贴边时同样贴齐；浮着时就是记账里那个位置（只夹进工作区） |
| 什么时候 | 贴着左右边时（默认 / 鼠标移开 1.5s 之后） | 浮着时（默认，鼠标移开也不变）/ 贴边时鼠标移进竖条 |

宽度按 `scale` 折成物理像素再算 x 与夹取：**尺寸给逻辑像素**（DPI 变了系统跟着缩放），**位置给物理像素**（与遮罩窗口
同口径）。混着算会在缩放屏上错位。贴边那档的 x 由那条边算（左：工作区左沿；右：右沿减窗口宽）—— 收起 6 宽、展开
76 宽，照搬记账里的 x 会露缝或伸出屏幕外。

**贴边判定与拖动**

`dock_of`（纯函数）判贴没贴边：窗口撞到工作区左沿（`x <= left`）或右沿（`x + width >= right`）就贴住那一边，否则
`None`（浮着）。**不留容差、不是磁吸** —— 拖动中横向被夹进工作区，所以「往屏幕外拖」落到这儿就是精确贴边；离边差
一像素的球就停在那儿、不收。

拖动是 **Rust 自己搬**（`drag_loop`，前端的 `pointerdown` 经 `ball_drag` 叫起）：按下那刻记下光标在窗口里的偏移，
之后每 `DRAG_TICK_MS`（16ms）按光标位置摆一次（`drag_target` 纯函数：光标减偏移、两个方向都夹进工作区、**横向一点
不吸**），松开左键收工。光标读系统坐标（`screen::cursor_point`），所以窗口跟走时指针始终压在同一相对位置；被屏幕边
夹住后指针跑到窗口外，这一轮照旧继续 —— 判据是左键（`dragging`），不是指针在不在窗口里。`ball_drag` **跑到松手才
返回**：等最后一笔 `set_position` 真落到窗口上（它是排队下发的，早读一帧就拿上一帧位置判贴边），再当场 `settle_drop`
一次，把落定后的状态回给前端。没真的挪动（点击 / 双击）时直接回当前状态，不落定。巡检线程那条路还在
（`schedule_settle`）：`sync_from_window` 在拖动中把位置读回来、记账，顺手起一轮巡检；它按 `dragging()` + 静默
`DRAG_SETTLE_MS` 落定，与 `ball_drag` 那次幂等（第二次读到的位置 / 尺寸已对得上，不会再摆）。Rust 还挂窗口的
`Moved` / `Resized` 把几何读回来（`sync_from_window`）：两个方向都只夹进工作区、**横向一点不吸**，顺手把 x / y 记进账；
**只有左键按着的那几次才安排落定** —— 悬停展开 / 收起也走这两个事件，它们不该被当成「丢下球」。左键读
`GetAsyncKeyState`（`dragging()` / `should_settle()`）—— 只给已有的 windows-sys 加 feature
（`Win32_UI_Input_KeyboardAndMouse`），不新增编译单元。巡检**活到真的松手**才收工。展开 / 收起 / 落定三处摆位排在同一把
`PLACE_LOCK` 上（`place_now` / `place_locked` / `settle_drop`）：`set_size` 与 `set_position` 是一对，中间插别的写者
会把档位配错。落定那步是「读位置 → 判贴边 → 落地」整段持锁，并且**尺寸对不上也回正** —— 同时兜住「被拆开过的窗口」
这类半截状态。`BallState::moving` 让程序化摆位期间的事件不参与落定 —— 但 `set_size` / `set_position` 在非主线程是**排队
下发**的，事件往往在旗落下后才到，真正兜住「不拿旧状态盖新位置」的是 `set_open` / `settle_drop` 里「先记状态、再摆位」
那个顺序。多屏时按窗口当前所在那块屏的工作区算（`current_monitor`，取不到退主屏）。

**前端那条链**（`BallApp.vue`）

`open`（画哪副）与 `side`（贴没贴边，`null` = 浮着）都以 Rust 回包为准，挂在窗口 `resize` 上重读（`syncContext`）——
松手贴边「自动收起 / 摊开」是 Rust 改的，前端只能从那儿知道。拖动那条路更直接：`pointerdown`（左键）→ 喊 `ball_drag`，
**它跑到松手才返回**，回包就是落定后的 `open` / `side`，顺手把 `requested` 一起对齐；这段时间 `dragging` 把 `onEnter` /
`onLeave` 全挡住。`.ball` 上 `user-select: none` —— 按下就搬窗口，中心那几个数字不该被框选。`applyOpen` 判重用的**不是**
窗口实际状态 `open`，而是「上一次推给 Rust 的意图」（`requested`）—— 收起还在路上时指针又移回球上，拿 `open` 判会把那次
展开吞掉；而每次拿到回包（`syncContext` 与 `applyOpen` 各一次）都拿实际状态对齐一遍 `requested`。鼠标移开（`onLeave`）
之前先看 `side`：**浮着的不收**，也不会白推一次注定被回绝的收起。`ready` 之前什么都不画（窗口本来透明）：窗口尺寸是 Rust
定的，形状还没取回来时画任何一帧都可能是错的 —— 浮着的球可能正好是 76 见方，照收起态画出来就是一条拉满窗口、顶着两个
圆头的怪条。

**表盘几何**（`dial.ts`）

**刻度环**：一圈 48 格刻度（内端在半径 29、长 4.4、粗细 1.7），第 0 格在 12 点、顺时针排。点亮多少格 = **上下行合计在
当前量程上的占比**（`round(48 × dialShare(...))`，凑不满半格就是 0 —— 宁可看着没动静，也不虚报一格）；点亮那段里，
**靠前的几格是下行（绿）、后面是上行（橙）**，所以一圈刻度同时说了两件事：这一档用了多少、其中上下行各占多少。量程
换挡见约束那条，只写在 `dialRange` / `dialShare` 一处，组件与用例都从它取。整圈始终画满 48 格（没点亮的是 8% 白的暗
轨道）—— `dialShare` 不返回「未知」，所以「一格都不亮」只会出现在真没流量时。那圈刻度画在**球自己那层玻璃上**
（`.ball--open` 的圆底），不是飘在桌面上 —— 少了这层底，未点亮的几十格压在浅色桌面上等于没有。中心那枚 hub 是抬起的
一层（顶部高光 + 外投影，投影整圈在窗口里），数字用等宽字体、单位缩到 0.72 倍并降到 62% 不透明度。没流量时亮的格与
数字一起降级 —— 球看起来「睡着了」，不是还在报 0。

**收起时那条竖条**：竖条**就是窗口本身**（6×48 逻辑像素，贴着屏幕边），里面一段自下而上的填充 —— 总高 = 上下行合计
在同一量程上的占比（与刻度环同口径），填充里靠下的橙段是上行、上半的绿段是下行。轨道用 92% 的深色（没有半圆底，
9% 白压在浅色桌面上等于没有）。没流量时填充退成 16% 白。

**采样与节流兜底**

球窗口每秒问一次 `net_counters`，用两次累计字节的差算速率，**按真实经过时间折算、不假设正好一秒**。间隔短于 200ms
当重复触发、长于 5000ms 当被节流（窗口被完全遮住时 WebView2 定时器会被节流，见 [mail.md](mail.md)）：两种情况都**整帧
丢掉、保留上一次读数**，而不是把「五分钟的平均值」当瞬时速度。计数器倒着走（网卡拔掉、计数器重置）按 0 算，不报负
速率也不报尖峰。

**记账**

`data\ball.json` 只有三个字段：`{ "x": 880, "y": 300, "side": "left" | "right" | null }`。`x` **只在浮着时算数**
（贴边时 x 由那条边算），`side` 为空就是浮在桌面上。首次出现贴右侧、纵向约 40% 处。窗口被系统关掉（Alt+F4 / 任务
管理器）**不清记账** —— 它是位置偏好，不是「球还开着」的凭据；开关在设置里。

## 验证

怀疑链路速率取错（表盘不随流量涨、或「亮满不降」）时，先看机器上的网卡清单：

```powershell
Get-NetAdapter | ft Name,InterfaceDescription,LinkSpeed,Status,HardwareInterface
```

`HardwareInterface=False` 的那几张（Hyper-V / WSL / VPN 隧道）**不许**出现在链路速率里 —— 上界该等于 `True` 里最快的
那条。

界面上没有第二条入口，验证走真应用（配方见
[browser-preview-verification.md](../dev-notes/browser-preview-verification.md) 的「在真应用里验证」）：

1. 起来后 `/json/list` 里应当**多出 `ball.html` target**（但只有开了开关才有窗口）；
2. 设置里打开「网速球」→ 桌面右边缘出现竖条，`data\ball.json` 里出现 `x` / `y` / `side`；
3. 鼠标移上去 → 窗口从 6×48 变成 76×76（`EnumWindows` + `GetWindowRect` 量，或连球窗口 CDP 读 `innerWidth` /
   `innerHeight`）；**指针停在球上不许收放来回抖**（会抖就是落定那道闸没关严）；移开 1.5 秒再变回去；
4. **从球正中间（数字上）**按住拖到屏幕中间松手 → **拖动全程球本体跟着光标走**（不是只有矩形轮廓，那是系统移动循环的
   老现象）；松手后球**停在落点**（不弹回）、鼠标移开也**不收起**；`ball.json` 里就是那个 `x` / `y`，`side` 是 `null`；
   顺带确认**双击球**还能唤出主界面；
5. 拖到屏幕左 / 右边缘（横向被夹住）松手 → 位置贴齐那条边、窗口收成 6 宽竖条，`side` 跟着变；再拖出来松手 → 摊回整颗
   球、`side` 变 `null`；
6. 拖到屏幕中间**按住不动**一两秒 → 球停在手底下；松手就停在落点；尺寸与位置必须同一档：贴右边展开态是 `x = 屏宽 − 76`，
   出现「76 宽窗口挂在 `x = 屏宽 − 6`」就是摆位被拆开了；
7. 重启应用 → 球回到记账里那个位置（`ball::load` 读的就是那份记账）；
8. 平时带点流量（1~2MB/s）→ 刻度环亮出**十几二十格**、中心数字在动；速率翻倍时弧长**回落到 1/4 圈那头**（换挡，不是
   掉速）；下载大文件 → 弧继续爬；把管子跑满（或量程顶到链路带宽）时整圈点亮（`net_counters` 的 `inOctets` 在涨，单位
   进位与一位小数由 `@workbench/net-meter` 用例覆盖）。**只有一两格就是量程没生效** —— 千兆链路上 1.6MB/s 按老的「占
   链路带宽比例」正好这样；
9. 关掉设置里那个开关 → 窗口消失，`ball.json` 仍在。
