# 工作日志

工作日志的文档：先读「约束」一节（不能破的规矩）；「实现」一节装为什么这么做、踩过哪些坑。
跨模块的通用事实（导航壳层、数据与隐私、目录结构）见
[features-and-architecture.md](../features-and-architecture.md)，跨模块红线见 [AGENTS.md](../../AGENTS.md)。

## 约束

关键落点：`packages/work-log/src/work-log.ts`（时间轴口径）、`apps/desktop/src/renderer/src/workbench/work-log.ts`（懒加载整份文件）、
`packages/core/src/markdown.ts`（渲染）、`apps/desktop/src/renderer/src/components/MarkdownView.vue`（点击接管）。

- **本机 `work-log.json` 是权威；多机共用走已有的同步仓库（可选）**：登录且设置里填了 `tokenSyncRepo` 时，
  每台机器把合并后的快照推到 `work-log/<设备id>.json`（单写者分片），读别人的分片合并后**写回本机** ——
  与活跃度「只在内存合并」不同：条目可编辑、可删除，不写回就没有落点，下一轮又会从别处读回来。
  合并按条目 id 做**后写胜出**（`updatedAt`，同毫秒用 `by` 设备 id 破平），删除留**永久墓碑**（`tombstones`），
  墓碑不清理（清掉后离线设备回来会让删掉的记录复活）。**不新增网络出口**：与用量 / 活跃度 / 保险库同一个仓库、
  同一把锁、同一条 `enqueue`；没登录 / 没配仓库时安静跳过。它仍然不写进 `workbench-data.json` 或 `theme.json`。
- **工作页一次只看一台设备的记录**：合并只发生在数据层（别的设备的条目照样写进本机文件，编辑 / 删除要有落点），
  界面上**不把多台设备的条目混在一条时间轴里** —— 默认本机，工具带上的「设备」下拉切到别的机器。
  条目属于哪台设备只看 `by`（没有 `by` 的老数据算本机），筛选与设备清单在
  [work-log-devices.ts](../../packages/work-log/src/work-log-devices.ts)。**新建条目与「从提交生成」永远写本机**，
  正在看别的设备时写完把选择切回本机 —— 否则刚存的记录会从眼前消失，看着像没存上。
- **「从提交生成」只读项目仓库**：`project_git.rs` 只跑 `git log` 与 `git config user.email`，一个字节都不写仓库、不联网、
  不新增网络出口；**日期范围由弹窗里选**（必选、默认今天，可快捷选今天 / 昨天 / 本周），按**作者时间**落在本地时区的哪一天判断（不是 git 的提交时间）；
  **项目可以多选、也可以不选**（不选 = 全部项目，生成前会确认一次），选了几个就只读那几个仓库。
  仓库配了 `user.email` 就只收自己的提交（读不到身份就不过滤）；已导入的哈希记在条目的 `source.commits` 里，
  换个日期再点一次也不会重复写。**别改成后台自动导入** —— 工作日志是个人记录，自动写会把噪音（临时提交、rebase 残留）也收进来。
- **正文按 markdown 渲染，解析用 markdown-it**（[markdown.ts](../../packages/core/src/markdown.ts)，唯一新增的前端运行时依赖）：
  `html: false` 转义原文里的标签、`linkify` 认裸地址、`breaks` 让单个换行就是 `<br>`；链接一律 `target="_blank"`，且点击在
  [MarkdownView.vue](../../apps/desktop/src/renderer/src/components/MarkdownView.vue) 里被接管交给 `openExternal` —— 界面是个 WebView，
  点 `<a>` 默认会把应用自己导航走。**别再自己手写解析器或引第二个 markdown 库。**
- **时间范围与排序维度是「行为习惯」，住在数据文件里**（设置里的 `workRange` / `workRangeCustom` / `workSort`，收敛用
  `sanitizeWorkRange` / `sanitizeWorkRangeBounds` / `sanitizeWorkSort`）：上次看的那一档、自定义区间的两端，下次打开还停在那儿。
  它们**不进 theme.json**（那张白名单里的项会被同步到别的机器，
  见 [ipc-and-state.md](ipc-and-state.md)）。同一排最左的「待办」也是这一排里的一档，同样会记住 —— 它是一个视图
  （所有还欠着的事），不是临时戴上的镜片。
- **改完成状态只有卡片右上角那颗开关这一条路，整条卡片不可点**（[WorkLogCard.vue](../../apps/desktop/src/renderer/src/components/WorkLogCard.vue)）：
  曾经挂着整条的点击（点哪儿都算对切），在「待办」档里点一下那条会当帧从列表里消失、又没有任何回执，
  读起来像被删了。**别再往卡片上挂整条的点击。**

## 实现


- 导航栏第三项「工作」：一条按天分组的**时间轴**，记「今天/昨天做了什么」。一天可以有多条记录，
  同一天里按写入时间倒排；**时间的最小刻度就是天**（没有「几点几分」这一层，那些细节写在正文里）。
  工具带的左右留白由外壳给（`--card-gap`，见 global.css 的 `.filter` 一节）——
  与时间轴同一条竖线，范围标签不会贴死窗口边
- 顶部六档：最左是**待办**，其后是 **今天 / 昨天 / 本周 / 本月** 四档预置范围，最右是**自定义**（选中后旁边出现
  日期范围选择器，两端都可选）。待办这一档筛的是状态、不看日期 ——
  列出**所有还没做完的事**（分页照旧按「天」走，所以是最近那些待办日在前），其余几档才按日期收。
  本周从周一起算（与首页贡献图那列「按周日切」是两回事，后者是网格排版约定）；没有记录的日子不占一栏 ——
  本月按自然日铺会有大半是空行，滚起来像翻日历。跨过午夜时「今天」这一档会自己跟着时钟走。
  **范围与维度都会被记住**（下次打开还停在那一档，自定义的两端也在，见[设置那一节](../features-and-architecture.md)的「上次看的那一档会被记住」）
- **设备切换在工具带右侧（「排序」左边）**：本机恒在第一位、标「（本机）」，是默认；别的设备取
  「同步拉到的分片」+「条目里出现过的 `by`」的并集 —— 分片已经在盘上就列出来（老数据没有 `by`，
  那台设备切过去是「这台设备还没有记录」的空态，但用户应该看得见它、也能切），
  名字来自它推上来的分片，没拉到分片时用设备 id 前 8 位兜底。
  只有一台设备时不摆这颗下拉；选中哪台只活在本次会话里（重启回到本机），换设备后分页回到第一页。
  本机标识拿不到（`device.json` 读不出来）时**不按设备筛** —— 宁可把合并后的记录都显示出来，
  也不要把整份日志藏起来
- **这一档里没有记录时，空态会说「最近一次是哪天」**（从当前设备整份日志里数，所以拿到的必定是范围外的那一天）：
  只说「本月还没有记录」的话，用户分不清是自己没记、还是记录丢了，而此刻真正要知道的是前者还是后者。
  整份日志真的一条都没有时才是原来那句引导（`packages/work-log/src/work-log.ts` 的 `dayMeta` 给「昨天 / 前天」这层相对说法）。
  待办那一档的空态分两句：一条记录都没有时给引导，有记录但都做完了时说「所有记录都已完成」
- **两种排序维度**（工具带右侧的下拉）：
  **按项目**是默认（`WORK_SORT_DEFAULT`，数组顺序也就是下拉里的顺序）—— 一个项目一栏、栏内仍从新到旧，
  回看「这个项目这段时间做了什么」用（栏内每条会带上日期，因为它跨了好几天）。
  **按时间**那档一天一栏、记录从新到旧，留给记流水账。
  项目维度里「未关联」与「已删除的项目」各占一栏，排在已知项目之后；已知项目按名字排。
  两种维度共用同一套筛选与分页
- **分页按「栏」走**（页大小 7）：时间维度是每页 7 天、项目维度是每页 7 个项目 ——
  一天（或一个项目）里的多条记录不该被翻页切成两半。页脚写着当前单位下有多少栏 / 多少条
- 一条记录四个**可编辑**字段：**所属项目**（下拉取自项目列表，非必填，选项上带该项目的标识色；项目被删掉后
  记录仍留着，标签显示为「项目已删除」）、**日期**（默认今天，停在「昨天」这一档时默认昨天）、
  **状态**（待办 / 已完成，**默认已完成**）、**工作内容**（必填，多行，支持 markdown）。
  弹窗里能在「编写 / 预览」之间切换，预览用的就是时间轴那套渲染
- **工具带右侧还有「从提交生成」**（「记一条」左边，「待办」档也能用）：弹窗里选**日期范围**
  （必选、默认今天；可快捷选今天 / 昨天 / 本周）与**项目**（多选、默认空；空 = 全部项目，这时点生成会先确认一次），
  按选中的项目逐个项目读仓库提交（`git log --all --no-merges -- .`，以项目目录自身为范围 ——
  monorepo 的子目录不会把同仓库别的目录的提交带进来；`--since` / `--until` 只按范围两端各放一天做粗筛），弹窗预览后写入。
  **一个项目一天一条**：同项目同一天已有生成记录时新提交接在它后面（标「追加」），否则新建一条「已完成」；
  预览里每行可改正文、可取消勾选。底部「添加并继续」写入后不关弹窗（写进去的行从预览里摘掉，剩下没勾的行留着，
  换个日期或项目可以接着加），「生成 N 条」写入后关闭。已导入过的提交按哈希跳过，手写条目不会成为追加目标。
  不是 git 仓库的项目静默跳过，部分项目读取失败不影响其余项目生成
- **待办与已完成**：默认是「已完成」（写下这条时事情多半已经做完了），要记待办就在弹窗里点一下「待办」；
  停在顶栏「待办」那一档时，弹窗的默认状态改成待办（`WorkView` 的 `defaultStatus`）—— 否则刚记下的那条
  会立刻从眼前的列表里消失，看着像没存上。
  待办的记录在项目标签后面挂一枚「待办」el-tag，**已完成的一条什么都不显示**（卡片本身与普通记录
  长得一样，不做置灰）。
  **切换状态只认卡片右上角那一颗开关**（**整条卡片不可点**，点一下卡片只是看）：待办时它是
  「标记为已完成」的勾、已完成时是「改为待办」的回箭头，两态共用一颗、**常显**（编辑 / 删除那两颗
  仍要鼠标移上去才显形）—— 只给待办那一侧留按钮的话，改回待办就没路可走了。
  顶栏最左的「待办」档就是这份待办清单（不分日期），在那一档把一条勾成已完成后它会从清单里走掉，
  要看回来切到别的档。**不再另设「只看待办」的筛选标签**：它曾经是一枚带计数的 chip，现在升成了同一排里的一档。
  状态是一次普通改动，照样会刷新记录的最后修改时间
- **左沿不挂任何竖条**（`WorkLogCard` 曾经有一条 4px 的 `.log__rail`，用户看过后要求去掉）：
  卡片本身（半透明底 + 毛玻璃 + 一圈描边）已经把它从时间轴的底色上立起来了，再加一根「脊」是多余的。
  顺带留一条口径：**左边这个位置在本应用里是状态灯带**（项目卡那条 3px 就是运行状态，见
  [projects.md](projects.md)）—— 所以就算以后想在这里加什么，也**别按项目色上色**，一条记录按
  标识色亮起来会被读成「这条在跑 / 这条失败了」，何况预设色只有五个、项目一多必然撞色。
  认项目只认那枚标签
- 项目标签是一枚 **el-tag（`effect="dark"`）**：实心标识色 + 反白文字，用的是 Element Plus 自己的
  标签主题，**跟应用的明暗没有关系** —— 亮暗两套下都是同一枚实心块（预设色由 EP 按主题变量取色，
  自定义色则由组件把标签的几个 CSS 变量换成算好的底色与字色）。**它是「这条属于哪个项目」的唯一记号**
  （写项目名 + 实心标识色）；首页「今日完成」那张卡里的几行用的是同一枚标签（`ProjectTag.vue`）
- 正文按 **markdown** 渲染（标题、列表、粗体、行内代码、代码块、引用、链接、裸地址自动成链）。
  **正文不折叠**：来了就整篇摊开，没有「展开 / 收起」——展开再收起要多一道手，日志是拿来读的；
  链接点击交给系统默认浏览器打开 —— 界面是 WebView，
  点 `<a>` 默认会把应用自己导航走。解析用 markdown-it（`html: false`，原文里的标签只当文字显示）
- 记录写入本机的 `work-log.json`（v2：条目 + 删除墓碑），**配了同步仓库时会推上去**：
  进工作页（含从别的页切回）与每次增删改成功后自动跑一轮「拉 → 合并 → 写回本机 → 推本机分片」，
  失败只在工具带留一行字（不弹消息、没有手动按钮，与保险库同一套）；成功一个字都不写。
  **合并只发生在数据层**：别的设备的条目也写进本机文件（下一轮还要接着合、删除要留墓碑），
  工作页按 `by` 分开显示（见上面那条「设备切换」）；设备名字跟着分片回来，本机那份以 `device.json` 为准
- **项目列表本身不跨设备同步**：条目里冗余一份 `projectName`，别的设备按 id 找不到项目时用它显示；
  本地项目还在时以本地名字为准，本地删掉的项目仍显示「项目已删除」
- 从提交生成的条目多一个 `source`（`{ kind: 'git', commits: [...] }`，提交哈希）：**只用于去重，界面不显示**；
  手写条目没有这个字段，手工编辑生成过的条目也不会把它丢掉
- 每页只读一次文件：进「工作」页时取回整份、之后一直在内存里增删改，每次改动整份落盘
  （防抖在 Rust 侧，与其余三份数据同一套）
- 首页还有一张**「今日完成」卡片**读同一份记录（只列今天已完成的，见[「首页」](home.md)）：
  它不另存一份数据、也不写，切回首页时重读一次；**只数本机的条目**（与工作页默认看的那台一致，
  卡片上没有设备切换 —— 别的设备去工作页切）。卡片上点一行就跳到这一页
- **记一条就是首页活跃度里的一笔**（来源 `log`，改与删不算）：这一处没有 store
  （组件直接调适配层），所以计数记在 `workbench/work-log.ts` 的 `addWorkLog` 里、
  写盘成功之后那一句 —— 页面本身不管这事，也不该管（口径见 [home.md](home.md) 那张图）


## 涉及文件

```
    work-log.ts         工作日志的适配包装（workbench/，整份读 / 增删改后整份落盘；多机同步也在这里编排）
  src/project_git.rs     项目仓库的只读提交读取（git log / git config user.email，不写仓库）
  packages/work-log      条目 / 时间轴 / 提交生成的纯逻辑（git-import.ts 管分组、去重与草稿；
                         work-log-sync.ts 管分片、后写胜出与墓碑合并；
                         work-log-devices.ts 管按设备筛条目与切换器的设备清单）
```
