### 密码学与密钥

- **加解密一律在渲染层，用 WebView2 自带的 WebCrypto**（`shared/vault.ts`）。Rust 侧**一行密码学都没有**，
  也**不要**为了「把它挪回后端」去引 `rsa` / `p256` / `aes-gcm` 这类 crate —— 项目对新增依赖的判据是
  「不新增编译单元」（AGENTS.md 第 1 节），这几套都会拉进成片的编译单元。
- **本机密钥过一次 IPC，这是全项目唯一的例外**（`vault_key_read` / `vault_key_write`）。理由是解密后的正文本来
  就要在渲染层显示，而 Rust 侧没有能做这件事的工具。**别把这个例外推广**：账号的 access_token 仍然只在 Rust 侧流转
  （它给 git 用，那边拿得到），不进渲染层。
- 密钥是**一把 ECDH P-256 密钥对**，私钥存在 Windows 凭据管理器（`Workbench/vault/key`，DPAPI 按当前用户加密），
  **不进任何数据文件、不进仓库**。公钥写在文件里（`key` 字段）—— 它是公开信息，作用只有一个：
  让「这份文件是用别的密钥加的密」当场看得出来，而不是满屏解不开的条目。
- 每条条目走一次 **ECIES**：现生成临时密钥对 → 与那把公钥 ECDH → HKDF-SHA256（盐与 info 都是常量）→
  AES-256-GCM。**不要把 HKDF 那两步换成「用公钥直接加密」**：ECDH 本身只是密钥协商，少了 KDF 就等于把
  共享秘密当密钥用。临时密钥对**每次现生成**，所以同一条正文加密两次的密文完全不同。
- `seal` 收的是公钥，而 `VaultPrivateKey` 在结构上是 `VaultPublicKey` 的子集 —— **收公钥的地方一律先过
  `publicKeyOf()`**，不能把入参整个摊开交给 `importKey`：带着 `d` 的 JWK 会被 WebCrypto 当成私钥，
  而私钥不接受空 usages，报出来的是一句与「密钥不对」毫无关系的 `Usages cannot be empty`。
- **界面上不摆「主口令」这一层**，也**不要**加：设计上密钥就存在本机（用户的要求），能打开程序就说明已经过了
  Windows 登录。加一道本地口令只会多出一个可以忘掉的东西，而它挡不住已经坐在这台机器前的人。
  界面上那颗「收起密码」是把内存里那把丢掉、把明文从屏幕上撤掉，**不是访问控制** ——
  解锁不需要口令，点一下就回来。**这句必须写在界面上**（引导语与 tooltip 都写）：一个叫「锁定」的
  按钮会让人以为它挡得住别人，而它挡不住，那比没有这个按钮更糟。真正的访问控制只有一条路 ——
  主口令（用它派生一把密钥把本机密钥包起来），那是另一件事，别顺手加上。
- **换 / 导入密钥之后必须走一遍 `adoptKey`**（`workbench/vault.ts`）：能读出来的条目解开再用新密钥封回去，
  读不出来的留墓碑。少了这一步，旧条目会以「只在远端有」的身份在下一次同步里被并回本机 ——
  合并只认 id 与时间、看不见密文，于是界面上多出一堆永远解不开也删不掉的条目。
  换密钥的代价要跟用户说全：别的机器得重新导入这份新密钥，否则它们那边只剩解不开的条目。

### 文件与合并

- 文件形状见 `shared/vault.ts` 的 `VaultFile` / `VaultItem`。**信封是明文、正文是密文**，这不是疏漏：
  跨设备合并要在没有密钥的情况下算出同一个结果 —— 认身份靠 `id`、判新旧靠 `updatedAt`、破平靠 `by`、
  认删除靠 `deleted`。**给信封加字段要同时想清楚它在合并里是什么意思**，否则两台机器会各执一词。
- `mergeVaultItems` 是**同步的全部**，两条不能破：
  1. **它必须是纯的、且两边算出的结果逐字节一致**（`updatedAt` 大的赢、撞上时 `by` 大的赢、输出按 id 排）。
     规则里任何一处「以本机为准」都会让两台机器来回覆盖、永远收敛不了 —— 那里有单测钉着，改口径先改测试；
  2. **墓碑永不清理**。清掉之后，一台离线很久的机器再回来时，本地那条老记录就成了「只在一边出现」的并集项，
     于是被原样推回去 —— 用户看到的是删掉的密码自己回来了。墓碑约 90 字节，留着不心疼。
- **改动只重封那一条**（`workbench/vault.ts` 的 `save`）：其余条目的密文原样留着。整份重加密一遍会让字节全变，
  「内容没变就不产生提交」这条约定随即失效，仓库里会堆出一串无意义的提交。
- 条目的 `id` **在落盘之前就得存在**（新建时现生成一个 uuid）：它是跨设备合并时唯一认得出「这是同一条」的东西，
  保存时才现编的话，两台机器各存一份就成了两条。

### 这一页的对齐口径

界面的对齐**靠量、不靠看**（`getBoundingClientRect` + `getComputedStyle`，配方见
[dev-notes/browser-preview-verification.md](../dev-notes/browser-preview-verification.md)）——
这一块前后错了四次（工具带比卡片墙右 10px、卡片那一行三条中线、段头小字矮两像素、
引导屏比导航栏低 10px），每一次都是「看着不对但说不出哪儿」：

- **一条左基准线**：工具带、段头、卡片的左缘都在 `left: 108`。工具带那份留白归外壳
  （global.css 的 `.vault > .filter`，取 `--card-gap`；整页自带内边距的页面才不给这一份），
  段头不留内边距 —— 这一页不再自己补，两处都写就是两倍。
- **一条顶线**：导航栏卡片、工具带、引导屏面板的 `top` 都是 0（紧贴顶栏下沿）。
- **卡片那一行是 22px 一条带子**：标签、值、图标三者同高同顶。
- **字号不同的文字按基线对齐**，不是按盒子居中。
- 引导屏里**文字与按钮等宽同左缘**，图标居中。

### 同步

- 那份文件在同步仓库的 `vault/vault.json`（`paths.rs` 的 `VAULT_DIR` / `VAULT_FILE`），
  与用量 / 外观 / 图片 / 笔记是**同一个仓库、同一条凭据**，**不是第七个网络出口**：
  没登录就没有同步（适配层照旧经 `syncRepo()` 取地址），保险库在没登录时照常能用，只是推不出去。
- **它是仓库里唯一一个多写者文件**。`token-usage/` 与 `config/` 那套「一台机器一个文件、每个文件一个写者、
  所以不需要人工合并」在这里不成立，所以**绝不能让 git 去合它**：同一个文件的两种改法交给 git 只会留下冲突标记，
  而这份数据本来就有确定的合并结果。做法是 `vault_push` 写入前核对远端还是不是合并时的基准（`base`），
  变过就**一个字都不写**、把远端交回去（`pushed: false`），由渲染层重走一轮（最多三轮，见 `SYNC_ROUNDS`）。
- **推送失败时不做 rebase，而是 `git reset --mixed origin/<branch>`**：把刚落下的那笔提交退回未提交状态，
  免得它成为下一次 `ensure_clone` 里 `pull --rebase` 的源头 —— 那会卡在同一个文件上每次同步都撞一次冲突，
  克隆就此废掉。在这里用 `reset --mixed`（不是 `--hard`）是安全的：那个克隆是应用自己的缓存
  （见 `paths.rs`），里面每个文件的内容都由本机数据现算，没有任何只存在于那里面的东西。
  同理，`drop_stale_rebase` 会中止克隆里遗留的 rebase —— 用量 / 外观那两个文件也能从本机数据重算出来。
- **本机那份先落盘、再推**：推送失败时合并结果也已经在本机了，下次同步不必从头来。
- 从远端读的是 **`origin/<分支>` 那个 ref**（`git show`），不是工作区里那份：工作区可能压着上一次没推上去的
  一笔提交，照着它读会让「远端变了没有」判断错。路径不存在靠 `git cat-file -e` 先问一句存在性，
  **不能**把 git 那句 `does not exist in 'origin/main'` 当成失败报给用户。
- 远端那份与本机这把密钥对不上时**必须如实说出来**（`keyMismatch`）：那些条目能合并、能推，
  但在这台机器上永远解不开 —— 不说的话用户看到的是「同步成功，一条都没多出来」。

## 实现


- 导航栏第六项「密码」：**按分组分段的卡片墙**（每段一个段头：分组名 + 条数；1440 窗口一行五张、
  每张 256px）。**段头不画拉到右缘的细线**（一组一张卡时那条线露馅，这个应用带标题的分组
  本来就靠字号与留白分层）。**工具带上只有搜索** —— 分组筛选标签与段头把数摆了两遍，删掉：
  找某一条用搜索、看某一组用分段。搜索框按 `.sort` 规范（28px、`--r-sm`、`--bg-surface`）。
  **整页一条左基准线**：搜索框、段头、卡片左缘落在同一条竖线上（工具带左边是有硬边的输入框，
  差 10px 明摆着没对齐）—— 工具带那份留白由外壳给（`--card-gap`，见 global.css 的 `.filter`
  一节），段头不留内边距。
  **引导屏（还没建库 / 已收起）**：段落统一 `width: 32em` 并左对齐（`.empty` 那套居中无上限会把
  两三段说明铺成参差的长句），图标与按钮居中
- 一条记录就是**名字、密码、备注、分组**四样（`VaultEntry`）—— 它是**备忘不是密码管理器**：
  没有用户名 / 网址字段、不生成口令，多一个字段就多一份要填的东西。
  分段用 `groupVaultRecords`（吃**排好序的那份**，相邻同组自然连段；排序管先后、分段管断开，
  拆两个函数才不会在两处各写一遍比较规则）。**分组名不写在卡片上**（段头说了）。
  卡片上只有**一行「标签 + 值」**（`密码` 灰字标签锚住值列）；**备注不上卡片**（长短不定，
  摊上去高矮不齐），跟着弹框走。密码默认遮住（**固定八度**的点，不按真实长度 —— 长度也是信息）；
  **一键复制 / 一键查看**常显、压暗一档；亮着时**换行不截断**。改删收在悬停才显形的「⋯」菜单
  （Teleport 到 body，指针进菜单卡片就不算悬停了，开着的要单独记 —— `openMenu`）。
  添加与编辑走弹框，名字唯一必填，校验就地显示（`vaultEntryProblem` 唯一一份规则，store 再兜一次）
- **非对称加密**：一把 **ECDH P-256** 密钥对，每条条目单独一次 ECIES（现生成临时密钥对 → ECDH →
  HKDF-SHA256 推出 AES-256-GCM 密钥 → 加密正文）——「有公钥能写、没有私钥读不出来」成立，
  同一条正文加密两次密文不同。密码学的形状与边界见上文「约束」一节
- **密钥全部在本地**：私钥存 Windows 凭据管理器（`Workbench/vault/key`），**不进数据文件、不进仓库**，
  所以**没有主口令这一层**（能打开程序就说明过了 Windows 登录）。**「收起密码」不是访问控制**：
  它把明文从屏幕与内存清掉（离开座位按一下），解锁点一下就回来 —— 这句写在界面上
  （叫「锁定」会让人以为它挡得住别人，那比没有这个按钮更糟）。换机器用同一保险库 =
  密钥屏**导出成文件**带过去导入一次（纯文本文件等于保险库本身，只走文件、不上屏不进剪贴板）
- **多机同步的规则**（信封字段、合并定死、墓碑永不清理、不交 git 合、只重封改动那条）见
  上文「约束」一节。同步**只有手动那一次**（工具带按钮）；没登录 / 没填地址时
  按钮给一句能照做的话，不静默失败
- 界面上**如实说三件读不出来的事**：有几条**解不开**（别的密钥加密的）、几条**读不出来**
  （内容坏了或来自更新的版本）、**仓库那份与本机密钥对不上**（能合并能推，但那些条目这台机器
  永远解不开）—— 不说「同步成功，一条都没多出来」就说不通。密钥屏显示**公钥指纹**（`A1B2-C3D4-E5F6`），
  两台机器应当同串，对不上就该重新导出密钥
- **分组名在收敛时 trim**（`sanitizeVaultEntry`）：排序、筛选、分段三处都按 `record.group` 一个值比，
  收敛只在这一处、下游依赖这个不变量；适配层 `save` 回来的记录用**收敛之后**的正文
  （`seal` 内部也 sanitize，否则界面与磁盘差一个空白，刷新一次标签就换写法）
- **分组是一栏自由文本**（`el-select` + `filterable` + `allow-create`），没有「新建 / 改名 / 删除分组」
  那一套、也没有分组表 —— 候选项从卡片现算（`groupVaultRecords` / `vaultGroups`），某组最后一条
  挪走那一段自己就没了；未分组自成一段垫底。**当前看哪一组刻意不落盘**（临时的镜片）
- 布局上的三条硬数：**卡片行高由 22px 一个数说了算**（标签 / 值 / 图标同一条带子：图标按钮压到 22px、
  横向内边距收到 4px、行高 22px —— 混进 20px / 28px 就是三条中线，改任何一个都要一起改）；
  **「⋯」平时透明但占位**（28px，悬停显形时整行不跳，别改 `display: none`）；
  同行字号不同的文字**按基线对齐**（段头 15px 名字配 10.5px 条数，盒子居中小字会矮两三像素）。
  **引导屏上边距必须是 0**（别页第一个元素都贴顶栏下沿，再补 `--card-gap` 就比导航栏低一截），
  左右与下仍取 `--card-gap`；文字与按钮共用一条左缘（都 `width: 32em`），图标居中在上
