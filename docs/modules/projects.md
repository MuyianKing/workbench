# 项目

## 约束

关键落点：`packages/core/src/project-color.ts`（标识色的分配与收敛，唯一真源）、`stores/projects.ts`（项目、分组、筛选
排序、启动编排）、`stores/environment.ts`（包管理器 / nvm / nrm / 数据目录）、Rust 侧 `nvm.rs` / `nrm.rs` / `proc.rs`
（残留清理的进程判据）、`system.rs`（`open_in_vscode`）。
跨模块通用事实见 [features-and-architecture.md](../features-and-architecture.md)，红线见 [AGENTS.md](../../AGENTS.md)。

- **项目标识色只认 `project-color.ts` 一处**：预设色存名字不存色值，自定义色 `#rrggbb` 一律经 `sanitizeProjectColor()`
  收敛；颜色怎么分配别在界面自己另拍一个。
- **项目标签统一走 `ProjectTag.vue`**（`el-tag` + `effect="dark"`），别自绘浅底同色字标签；调用方只负责限宽与
  `.el-tag__content` 的 `overflow: hidden`。
- **排序结果稳定**：按「最近使用」排序时，点启动不会让卡片跳到第一位；**排序方式本身被记住**（数据文件里的行为偏好），
  **分组筛选刻意不记**（临时的镜片）。
- **监听端口不手填**：启动后从日志认出的实际端口写回 `Project.port`，停止时清空（应用直接退出、服务还在跑时保留到下次
  启动）；界面只读展示，占用检查与外部探测都只认这一个值，别在抽屉 / 添加弹窗里再开一个输入口。
  更新安装只杀应用本身、dev server 会活下来，下次启动**按这个端口把它接着认成「外部运行中」**（见下面「残留清理」）。
  **探测失败不能清端口**：`checkPort` 超时 / 通道出错时端口状态是未知的，`detect()` 只在确认空闲（`known && !running`）
  时清空。一次超时就把端口抹掉，下次启动的残留清理会把还在跑的 dev server 当残留 `killTree`（端口没了 = 无法接管）；
  失败原因写进 error.log（`[端口探测]`），同一端口 60 秒只记一条。
- **活跃度计数在适配层**（`workbench/state.ts` 的 `recordActivity('run')`，按下「启动 / 打包」的当天记一次），不在 Rust
  侧 —— 迁 Tauri 时漏过一次，症状是贡献图不再变深。它只是首页那张图的**来源之一**（另有工作日志 / 新建笔记 / AI 助手跑
  一轮 / 知识库整理，见 [home.md](home.md)），写账与广播成对走
  [workbench/activity.ts](../../apps/desktop/src/renderer/src/workbench/activity.ts)。
- **「在 VS Code 中打开」走 `vscode://` 协议**（`system.rs` 直启 ShellExecute），不去找 `Code.exe` 的安装路径；
  **不要照着再引别的编辑器**（VS Code 是唯一那个可选外部程序）。
- **残留清理宁可漏掉几个，也不能杀错进程**：先核记录里的 `ownerPid`，再按进程创建时间 + 存活判据（`OpenProcess` +
  `GetProcessTimes` + `GetExitCodeProcess`）认进程；老记录缺字段一律跳过。
- **更新 / 强杀后的开发服务不清**：`kind === 'start'` 且项目端口还在监听就保留进程（交给端口探测认成「外部运行中」），
  打包 / 安装 / 命令类残留才清；老记录缺 `kind` 按可接管处理（接管只是不动进程，弄错只留个残留）。**启动时的端口探测
  必须排在残留处理之后** —— 并行时探测可能先看到残留还在监听、随后又被清理杀掉，卡片会一直挂着「运行中」。
- **归属设备随项目只存本机、不跨设备同步**：`Project.deviceIds`（设备 id 列表）在详情抽屉「基本信息」里维护，
  供工作页「从提交生成」按设备预选项目；设备 id 与清单都取工作日志那套口径（`workLogDevices` / `workLogDeviceLabel`），
  **别在路由之外另起一套设备身份**。写入前经 `sanitizeDeviceIds` 收敛（去空 / 去重），空数组表示不绑定。
  数据层只按 id 记归属，不存设备名 —— 名字跟着同步分片走，与工作页切换器同一份。
- **nvm 只按项目前置 PATH**，不动全局软链、不需要管理员权限；**nrm 的镜像清单一律解析 `nrm ls` 输出**（不写死在代码里），
  镜像名先进合法性检查再交给 shell。

## 实现

### 项目管理

- **项目页**：整页铺开项目卡网格（1440 宽下一行 4 张），顶部一条工具带是分组筛选标签 + 分组管理 + 排序；原先它在首页的顶部带
  与中间那张卡片里，独立成页后不再受栏宽限制。工具带的左右留白由外壳给（`--card-gap`，见 global.css 的 `.filter` 一节）——
  与下面第一张卡片的左缘、最后一张卡片的右缘同一条竖线，工具带贴死窗口边就是漏了这一段。
- 选目录即自动读取 `package.json`：识别框架、版本、全部 scripts、锁文件与产物目录。
- 按命名约定预分类启动命令（`serve` > `dev` > `start` > 变体）与打包命令（`build` 及变体），可在界面上改。
- 包管理器按锁文件判定（`pnpm` > `yarn` > `npm`），可手动覆盖；未安装时执行前拦截并说明原因。
- 分组：新建 / 双击改名 / 删除；在**项目页的筛选栏**或「分组管理」弹窗里**拖动分组标签调整顺序**；把卡片拖到分组标签即完成
  归类（两者必须同页面，拖放才成立）；「未分组」标签只在真有未归类项目时出现；按分组过滤、三种排序。
- **排序结果稳定**的实现细节：按「最近使用」排序时点启动不会让卡片跳到第一位（运行过就被记录，但要等主动切换排序方式、
  增删项目或重启应用时才重排）。**排序方式本身会被记住**（见[设置那一节](../features-and-architecture.md)的「上次看的那一档
  会被记住」）；分组筛选刻意不记 —— 它是临时的镜片。
- **在首页展示**（`Project.home`）：首页那张项目卡只画勾了这一项的项目，缺省与老数据都不展示 —— 首页是挑出来的一份名单
  （全量在项目页）。三个入口：添加项目时勾「在首页展示」、项目卡「⋯」菜单里一项跟着状态翻的「在首页展示 / 从首页移除」、
  详情抽屉「基本信息」里的开关。名单顺序跟着项目页的展示顺序走。
- **项目标识色**：抽屉「基本信息」里选一个颜色 —— 预设是 Element Plus 那五个主题色（主题色 / 成功 / 警告 / 危险 / 信息），
  也可以选「自定义」用取色器挑任意颜色。项目卡上那个小圆点与工作日志里的项目标签都取它。**新加项目自动取一个「当前用得
  最少」的主题色**，所以前五个项目两两不同；老数据（没有这个字段）启动时按同一条规则补一次并落盘。预设存的是**主题色名**
  而不是色值 —— 明暗切换与自定义主题色都会跟着走；自定义色存 `#rrggbb`，跟着数据走、不随主题变。
- **归属设备**（`Project.deviceIds`）：抽屉「基本信息」里多选，选项与工作页切换器、从提交生成弹窗同一份设备清单
  （本机 + 同步拉到的）。一台项目可绑多台；留空 = 不绑定（通用项目）。**只存本机项目列表、不跨设备同步**，
  所以在 A 机器绑的要到 B 机器各绑一次；生成日志读的也是各自本机仓库。它决定「从提交生成」的下拉范围：绑定给当前设备的 + 未绑定的通用项目
  才列出，绑定给别处的项目隐藏（见 [work-log.md](work-log.md)），不改工作页的项目显示，也不新增网络出口。
- 目录被移动或删除时卡片标记「路径无效」并屏蔽操作，支持「重新定位」。
- 项目卡的「⋯」里有**在 VS Code 中打开**：走 `vscode://file/<路径>/` 协议，不去猜 `Code.exe` 装在哪 —— 只有协议处理器是
  「这台机器现在用哪个 VS Code」的可靠答案。路径按 URL 规则转义、结尾 `/` 表示目录；没装时按 ShellExecute 错误码给一句
  明确提示，而不是点了没反应。
- 列表与设置写在数据目录下（安装版 `%APPDATA%/Workbench/data/`，开发版 `%APPDATA%/Workbench-dev/data/`；位置固定，没有
  「换目录」这一说）。
- **项目卡是毛玻璃**：底色跟「卡片不透明度」走，底下还有一道共用的磨砂 —— 配方与「哪些面吃这一套」的清单在
  [features-and-architecture.md](../features-and-architecture.md) 的「浮在壁纸上的面一律是毛玻璃」一条，卡片自己只写
  `background: rgba(…--card-alpha)` + `backdrop-filter: var(--glass-filter)` 两行。不透明度调到 100% 时磨砂自然失效
  （用户要的实底）。卡片因此是**层叠上下文** —— 卡里要放浮动面板（popover 那类）得 Teleport 到 body 画，不然会被后画的
  卡片盖住（同 global.css 里顶栏那条坑）。**左沿以状态灯带为界**：左边框 `border-left-width: 0`（不是仅把颜色调成
  transparent —— 背景默认铺到边框下，透明边框会把卡片白底露成灯带左边一道浅线，2026-11 用户指出后去掉）；
  `padding-left` 比常规多留 1px（`+4` 而非 `+3`）补回边框占的位置，box-sizing: border-box 下卡片外框与文字都不横移。
- 一个项目都没有时，**项目页**换成欢迎页：一枚 [EmptyState](../../apps/desktop/src/renderer/src/components/EmptyState.vue)
  （「还没有项目」+ 添加项目按钮），别的什么都不放 —— 2026-11 用户定「不关心上手三步那些内容」，眉题 / 三步 / 水印已去掉。
  裸压画布、水平垂直都居中、白色（ink，不描边不垫底），与技能 / Git 的整页空态同一待遇。

### 一键操作

- 安装依赖 / 启动 / 打包 / 停止 / 重启；dev server 跑着时照样能点打包（一个项目可同时挂几条会话），所以**「停止」停的是
  卡片当前显示的那一类**：写着「打包中」就停打包，写着「运行中」才停开发服务（按 `runtime.kind` 命中对应会话；按端口结束
  外部服务那条路只在界面显示的就是那个外部服务时才走，否则停掉的是旁边的 dev server，打包照旧在跑）。
- 抽屉顶部那排主操作统一 `size="small"`：420 宽的抽屉里默认尺寸放不下四颗，打包那组的 split-button 箭头（浮动子项）会被
  挤到下一行。
- 打包成功后自动打开产物目录（探测顺序：手动配置 > 构建配置 `outDir` > `dist` 等常见目录 > 项目根目录），可项目级关闭；
  输出目录除了手填也能直接**选目录**：选项目内的会落成相对写法（如 `dist`），项目挪位置也不失效，选到项目外才记绝对路径，
  输入框下方始终显示拼好的实际路径。
- **监听端口由应用自己维护**：启动日志里认出 `localhost` 端口就写回项目，卡片与详情抽屉显示的都是它（抽屉里只读，不能
  编辑）；点「停止」时连同运行态一起清空，应用直接关掉、服务还在跑时保留到下次启动 —— 启动时的全量探测靠它认出「在
  Workbench 之外还跑着」的服务，探测到端口已经空了也清掉。启动前若还记着端口，先查占用：被别的进程占着就提示占用者名称与
  PID，可选择结束它后重试；首次启动（还没记下端口）不做占用检查，交给 Vite 这类工具自己换端口，日志里认出来再写回。
- **不代开浏览器，但给了手动入口**：项目跑着时，卡片**右上角**多一颗分享图标（状态胶囊右边），点它用系统默认浏览器打开
  `http://localhost:<端口>/`。**只在跑着、且端口已知时画** —— 端口先取运行态里那个（卡片上显示的同一个，来自启动日志认出
  的实际监听端口），没有才退回上次运行记下的，两个都没有就不画（端口被占时 Vite 这类会自己往上找一个，所以实际认出的那个
  更可信）。**项目跑起来时应用自己不会弹浏览器**，那一条交给项目脚本（如 Vite 的 `server.open`）；地址的拼法只有一处
  （`devServerUrl()`，`packages/core/src/dev-port.ts`），它解释了两件事：为什么写 `localhost` 而不是 `127.0.0.1`、为什么
  结尾那个 `/` 不能省。
- 自定义命令（名称 + 命令行）挂在项目上，卡片「⋯」菜单里一键运行。
- 状态机与指示灯：灰=空闲、黄=运行/安装/打包中、绿=命令正常退出（只有打包才显示成「打包成功」，其余按「已结束」）、
  红=失败。
- 用户点一次「启动」或「打包」记一次活跃度（按下的当天），首页贡献图里那一格就有这一笔；安装依赖、自定义命令、停止与启动
  失败都不算 —— 计数落在适配层 `recordActivity('run')`，**不在 Rust 侧**（Electron 迁 Tauri 时漏过一次，症状是贡献图的
  格子不再变深）。

### Node 版本与残留清理

- 读取 `package.json` 的 `engines.node` 或 `.nvmrc`，与系统 node 比对，不满足时提示（不阻断）。
- 检测 nvm-windows 已安装的版本，可为单个项目指定 Node 版本：执行时把该版本目录前置到子进程的 `PATH`，不动全局软链、
  不需要管理员权限，多个项目可以同时跑不同版本。
- 应用被强杀 / 更新安装时被杀后，下次启动先处理上次留下的子进程：先核对记录里的 `ownerPid`（宿主还活着就一律不动），再按
  **进程创建时间 + 存活判据**（`OpenProcess` + `GetProcessTimes` + `GetExitCodeProcess`）认进程 —— 只判进程存在会把 PID 被复用
  的情况误当成「有主」而永远保留，而**已退出但进程对象尚未回收时创建时间依然可查**，得比对退出码才知道它已经死了；这两个坑
  都记在 `proc.rs` 的注释里。老记录缺这些字段时一律跳过，清理残留宁可漏掉几个，也不能杀错进程。
- **开发服务的残留不清，交给端口探测接管**：记录里 `kind === 'start'`、且项目记着的端口还在监听，就保留进程、丢掉记录 ——
  界面按端口把它认成「外部运行中」（可见、可停止、可重启），更新完项目不会莫名其妙被停掉。打包 / 安装 / 自定义命令 / 命令卡片
  那几类，以及端口已经空了的开发服务，照旧按进程树清掉。老记录没有类别字段时按可接管处理：接管只是「不动进程」，弄错也只留
  一个残留，比升级后的第一次启动把它误杀更符合预期。端口检查与「外部运行中」同一条通道（一次 TCP 连接）。
- **启动编排有先后**：残留处理跑完才做端口探测（`stores/projects.ts` 的 `init`）。两者并行时，探测可能先看到残留还在监听、
  随后清理又把它杀掉，状态就再也没人收回来 —— 症状是更新重启后卡片一直挂着「运行中」，点停止报「端口上没找到监听进程」。
  「外部运行中」只是探测出来的快照，窗口重新获得焦点时再复认一遍（自己起的会话有退出事件，不重探）。
- **清理决策写 error.log**（`[残留清理]`）：每条保留 / 接管 / 结束的结论都带 PID、类别、端口与当时的监听判定，结束那条还写清
  当时端口是「未记录」还是「未在听」。排查「在跑的项目被关」时，据此能还原是端口记录先丢了，还是端口探测误判成没在听。
- 清理有一处已知局限：会话记的是 `cmd /C` **包装进程**的 PID，应用被强杀时 cmd 往往先于真正的 dev server 退出，后代无法
  定位 —— 这类孤儿清不掉。彻底解决要给每个会话建 Job Object（与退出确认里「直接退出（保留进程）」的语义冲突，需先定取舍）。
  **「直接退出（保留进程）」保留的 dev server 下次启动也按上面那条接管**：进程继续跑，卡片显示「运行中（外部）」。

### npm 镜像源（nrm）

- 系统状态卡片里多一行 nrm：能读到时显示**当前 npm 镜像**，点开下拉换一个（`nrm use <name>`）；命令行要等一次 node 冷
  启动，所以这一行是首屏之后异步补上的。
- 镜像清单不写死在代码里：一律解析 `nrm ls` 的输出（含各镜像地址），taobao 改名 npmmirror 这类变化不用改代码；当前项优先
  认输出里的 `*`，认不出（没打星号 / 颜色干扰）时再拿 `npm config get registry` 对一遍地址。
- 没装 nrm 时这一行整块是个安装按钮，点一下走 `npm install -g nrm`，过程与包管理器安装共用同一条通道（输出顶在卡片上、
  完整日志进底部终端、超时按进程树收掉）。
- 切换改的是 npm 的**全局** registry，此后所有不带自己的 `.npmrc` 的项目都走新源；镜像名会先进一次合法性检查再交给 shell，
  避免名字里混进命令分隔符。

## 涉及文件

```
  src/nvm.rs             nvm 只读探测（目录 / settings.txt / 软链）
  src/nrm.rs             nrm 探测与镜像源切换（清单来自 nrm ls）
```

渲染层三处（原注解）：

```
    nvm.ts / nrm.ts     nvm 与 nrm 探测的适配包装（workbench/）
    projects.ts          项目、分组、筛选排序、抽屉；也是启动编排的落点（init）（stores/）
    environment.ts       包管理器、nvm、nrm、数据目录（stores/）
```

项目详情抽屉按区块拆开（`components/`）：`ProjectDrawer.vue` 只是壳（开关动画 + 共用表单样式 +
危险操作），内容在 `ProjectDrawerHeader.vue`（头部与主操作）与五个 `Project*Section.vue`
（基本信息 / 命令配置 / 环境 / 打包输出 / 运行记录）。各块自己读 `store.drawerProject`，
不为每一块在父组件里转一遍 props。

**配置变更自动落盘盯的是「可落盘字段的投影」**（`stores/projects.ts` 的 `editableProjects`），
不是 `projects` 的深遍历：主进程推回来的 `history` / `lastUsedAt` 不再触发一次全项目重算与 IPC。

nvm / nrm 的探测结果不再手写 `json!`：`nvm.rs` / `nrm.rs` 的 `NvmStatus` / `NrmStatus` 带 `// @contract`，
TS 类型由 `pnpm run contract:gen` 生成。「没装 nvm / nrm」是正常状态（`available: false` + `error`），
只有探测本身失败（命令起不来）才是 `Err`。
