# 技能（skill）

技能（skill）的文档：先读「约束」一节（不能破的规矩）；「实现」一节装为什么这么做、踩过哪些坑。
跨模块的通用事实（导航壳层、数据与隐私、目录结构）见
[features-and-architecture.md](../features-and-architecture.md)，跨模块红线见 [AGENTS.md](../../AGENTS.md)。

## 约束

关键落点：`shared/skills.ts`（frontmatter 解析、版本校验与比较、路径口径，带单测）、
`apps/desktop/src-tauri/src/skills.rs`（列目录 / 提交 / 历史 / 恢复 / 对比 / 导入 / 仓库归属探测 / sync）、
`workbench/skill.ts`（每次一版提交的编排）、`stores/skills.ts`。

- **技能库与笔记文件夹互不相干**：两边各自挑各自的（`skillDir` / `noteDir`），
  可以正好是同一个目录、同一个仓库，也可以不是；版本就是 git，同步就是「提交 + 拉 + 推」，
  与笔记同步共用同一套机制，但**不另开凭据、不另设机制**。
- **仓库归属从目录往上找**（8 层为限），笔记那边只认「文件夹自己有 `.git`」——
  差别是有意的：技能的提交**带 pathspec**（只动技能库那一层），笔记的 `commit_notes` 是
  `git add -A` 整棵工作树。**两边别互相「对齐」**。
- **git 调用全是本地操作**：复用 `sync.rs` 开放的原语，不设凭据、不出网络；
  「不是仓库」与「内容没变」都不算错误。增删改只在本机提交，**只有点同步才出网**（走笔记同步那条通道）。
- **保存有必经的版本门槛**：SKILL.md 的 frontmatter 必须有语义化版本的 `version` 字段
  （校验与归一化在 `skillVersionProblem` / `skillVersionOf`），没有或不合语义就**整个不落盘**；
  提交信息带着版本号。「有没有更新」**只看 version**（逐段数字比较，字符串比会答反）。
- **恢复先把该目录下已跟踪的内容 `git rm` 掉再检出旧版**（直接 `checkout` 会残留新版新增的文件），
  恢复本身也是一次提交。
- **取历史版本的内容走 `git_stdout` 且不能 trim**（原始字节，见
  [../sync-and-auth/constraints.md](sync-and-auth.md)）。
- **没有 `SKILL.md` 的目录不是技能**：装不出去、列出来挂警示；复制整棵跳过点开头的目录。

## 实现


- 导航栏第五项「技能」：管理一批自定义 skill（一个文件夹 + 一份带 frontmatter 的 `SKILL.md`）。
  **卡片网格**（与项目页同一副外壳）：卡片展示自动提取的名字与描述（解析 frontmatter 的
  `name` / `description`，只认「围栏内单行键值」；口径在
  [shared/skills.ts](../../packages/skills/src/skills.ts)，带单测）加文件数，没有 `SKILL.md`
  的挂警示（装不进项目）；底部一排**悬停才显形**的操作（安装到项目 / 打开文件夹，点击
  `stopPropagation` 免得顺带拉开详情）。点卡片开**详情弹窗**（1200px `el-dialog`，窄窗收着不出界）：
  编辑清单、安装到项目、版本历史、删除都在里面；关闭前有「放弃修改」确认（编辑是手动保存的）。
  没有 frontmatter 的照样列出来，名字回落目录名
- **技能库是它自己的一个目录**（`skillDir`，与笔记文件夹互不相干）：同类东西（几份 markdown）、
  同一套机制（版本 = git 提交，同步 = 提交 + 拉 + 推），不另开凭据。仓库归属从目录往上找
  （`skill_state` 给「仓库根 + 相对路径」，库自己就是根时相对路径是空串）；与笔记那边**故意不同**
  （笔记 `git add -A` 不带 pathspec 只认自己的 `.git`，技能提交带 pathspec 所以往上找是安全的）
  —— 两者别互相「对齐」，细则见上文「约束」一节
- **笔记树里那一层**：技能库正好落在当前笔记本里时整层藏掉（`withoutSkillDir` +
  `libraryInNotebook`）—— 技能有自己的页面，树里再挂一份会让人以为它也是笔记
- **版本管理 = git 提交历史**：每次改动由适配层提交一次（信息 `skill: <id> 动作`，只 add 技能库
  那条路径）。**保存有版本门槛**：frontmatter 必须有语义化 `version`（`skillVersionProblem` /
  `skillVersionOf`，模板自带 `0.1.0`），没有就**整个不落盘**；通过后提交信息带版本号。
  「版本历史」现问 `git log`；每版两条路：**「对比」**开差异弹窗（底下那颗才是「恢复到这个版本」）、
  **「恢复」**直接回去（先 `git rm` 已跟踪内容再检出旧版，恢复也是一次提交）。取内容按原始字节、
  清单 `ls-tree -z` —— 硬约束见 [../sync-and-auth/constraints.md](sync-and-auth.md)。
  不是 git 仓库时照常增删改、如实没有版本与同步（说明放在保存按钮旁）；是仓库没远端则版本照记
- **同步走笔记同步通道**（同一仓库一次带上）：增删改只在本机提交，**只有点同步才出网**；
  冲突同样不替用户挑边（见 `sync_notes`）
- **项目里优化过的内容能更新回库**：详情弹窗打开时**只读检测**各项目里的副本
  （`installed_versions`，路径拼死在项目目录内）；「有没有更新」**只看 SKILL.md 的 version**
  （`compareSkillVersions` 逐段数字比较 —— `1.10.0` > `1.9.0`，字符串比会答反；库版本解析失败按
  `0.0.0` 兜底）。**详情页只看库里的文件**；差异只在对比弹窗里看 —— GitHub split 视图的逐行差异
  （行模型是纯函数 [shared/text-diff.ts](../../packages/core/src/text-diff.ts)，jsdiff 出行块与
  行内变化段、组件只画；红绿借 `--st-fail` / `--st-ok` 语义，深浅 color-mix、不新增颜色；
  整表一个滚动容器，左右天然同步）。「用项目版本更新到库」走正常保存那条路（version 门槛照常）；
  比对基准是**库里盘上那份**，没装或读不出的项目不参与。**「版本历史」的「对比」用同一个弹窗**
  （右栏换成所选版本、按钮换成「恢复到这个版本」，左栏都是库里现在这份 —— 见 `SkillCompareDialog`
  的 `mode` 与 `mergeVersionCopies`）
- **技能可以多文件**：详情里有文件清单（相对路径），附属文件与清单同一条保存通道、每次保存记一版
  （信息 `skill: <id> 保存 <文件路径>`）；**version 门槛只对 SKILL.md**。切换文件有未保存修改先确认；
  二进制读不出文本就如实提示。清单在打开 / 保存 / 刷新时重拉
- **一键安装到项目**：整棵复制到 `<项目>/.agents/skills/<技能名>/`（各 agent 通用的项目级约定）；
  已安装先问要不要覆盖（覆盖必须确认）；没有 `SKILL.md` 的目录装不出去（复制走 `walkdir`，
  点开头的目录整支跳过）
- **添加三个入口**：新建（生成 frontmatter 骨架，名字即目录名即 id）、从文件夹导入（整棵复制，
  同名报错不悄悄覆盖）、直接往技能库里放文件后点刷新 —— 磁盘上的文件就是数据本身


## 涉及文件

这些条目的原文注解从主文档「目录结构」迁来（主文档的树里各留一行，指回这里）。

```
  src/skills.rs          技能库（它自己的一个目录，见 shared/skills.ts）：列目录 /
                        提交版本 / 历史 / 恢复 / 版本对比 / 导入与安装（整棵复制，跳过点开头的目录），
                        外加 state（从技能库目录往上找它所在的仓库）与 sync（只提交技能库那一层，
                        再拉推那个仓库）。
                        git 调用全是本地操作，复用 sync.rs 开放出来的那几个原语 ——
                        不设凭据、不出网络；「不是仓库」与「内容没变」都不算错误。
                        取历史版本的内容另走 `git_stdout`（不能 trim，见 modules/sync-and-auth.md）
```

渲染层两处（原注解）：

```
    skill.ts（技能：文件动作 + 每次一版提交的编排，见 shared/skills.ts）
    skills.ts            技能：技能库列表、当前打开的那一篇、增删改 / 版本历史 /
                         版本对比 / 恢复 / 安装的编排（同步复用笔记同步那条通道）（stores/）
```
