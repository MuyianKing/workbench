# 官网（site/ 与 site-claude/）

官网（site/ 与 site-claude/）的文档：先读「约束」一节（不能破的规矩）；「实现」一节装为什么这么做、踩过哪些坑。
跨模块的通用事实（导航壳层、数据与隐私、目录结构）见
[features-and-architecture.md](../features-and-architecture.md)，跨模块红线见 [AGENTS.md](../../AGENTS.md)。

## 约束

关键落点：`site/`（第一版，照 `apps/desktop/src/renderer/src/styles/tokens.css` 重画配图）、
`site-claude/`（第二版，照根目录 `DESIGN.md` 那套规范画）、
[DESIGN.md](../../DESIGN.md)（site-claude 的视觉真源）。

- **无构建、无依赖**：`index.html` + `styles.css` + `app.css` + `main.js`，双击就能看；
  在 `src/` 之外，**不进 `pnpm run typecheck` 与打包流程**。
- **不引外部 webfont**：应用是离线优先的，官网不该为此单开一个网络出口；
  用系统栈里最接近目标字体的那一档。
- **两版的视觉真源不同，别混**：`site/` 的应用配图照 `tokens.css` 重画
  （改了令牌要一起改 `app.css` 顶部那批 `--ap-*`）；`site-claude/` **独立于 tokens.css**，
  要改的是 `DESIGN.md`（或换一套规范重新导出），配图尺寸照应用比例、颜色圆角照规范。
- **文案里的数字取自文档**（卡片数量、加密算法链、网络出口、技术栈），
  改功能时记得回头对一遍。

## 实现


`site/` 是项目的落地页（`index.html` + `styles.css` + `app.css` + `main.js`，**没有构建步骤、没有依赖**，
双击 `index.html` 就能看，起个静态服务也一样 —— 它在 `src/` 之外，不进 `pnpm run typecheck` 与打包流程）。

视觉照苹果那套做法：大字号紧字距的标题、白 / `#f5f5f7` / 纯黑三段底色交替、44px 毛玻璃导航、
发丝分割线。**不引外部 webfont** —— 应用是离线优先的，官网不该为此单开一个网络出口，
所以用系统栈里最接近 SF Pro Display 的那一档（Windows 11 的 Segoe UI Variable Display，
中文回落微软雅黑）。苹果的观感主要来自字号阶梯、负字距与留白比例，这三样不依赖具体字体。

页面上那五张应用窗口**不是截图，是照着 `tokens.css` 重画的界面**（`app.css`）：原截图带着个人壁纸，
放进落地页太吵且改不了；重画还能同时给出亮 / 暗两套（应用默认暗色）。所以它跟真界面**会漂**：
改应用的颜色、圆角、栏宽时，`app.css` 顶部那批 `--ap-*` 要一起改。三条实现上的约定：

- 每个窗口按固有像素尺寸画（HTML 上的 `--w` / `--h`，**无单位数值**），容器用 `aspect-ratio` 预留高度，
  再由 `main.js` 写一个 `--s` 整体 `transform: scale()` 缩放。`aspect-ratio` 只吃纯数字，
  所以那两个变量不能带 `px`，用到处现乘 `1px`（带单位会让整条声明失效，窗口塌成 0 高）。
- 窗口里 `text-align: left` 与 `letter-spacing: normal` 是必须的：首屏是居中的、正文字距也压过，
  这两样会顺着继承钻进配图，把应用自己的对齐与字距带偏。
- 首页布局那一节的小画布（`#labGrid`）**可以真的拖**：卡片留在自己的网格槽里、只被 transform 拖着走，
  松手时把两张卡的「内容 + 跨度类名」对调，再用 FLIP 补上位置动画。网格是
  `grid-auto-flow: row dense` —— 跨度不同的两张卡对调后，原来那行的空档要让后面的小卡回填，
  否则换一次位就多出两个空格。

文案里的数字都取自媒体文档（卡片数量、加密算法链、六处网络出口、技术栈），改功能时记得回头对一遍。

### 第二份：照 `DESIGN.md` 落地的那一版（`site-claude/`）

`site-claude/` 是同一套内容的**第二份实现**（也是 `index.html` + `styles.css` + `app.css` + `main.js`，
同样无构建、无依赖、双击就能看），视觉整体换成项目根目录 [`DESIGN.md`](../../DESIGN.md) 里那套设计规范
（Claude：AI 与大模型，浅色系，主色 `#cc785c`）。它的用途是验收**样式参考库导出的规范能不能直接落地**：
规范给什么值就用什么值 —— 颜色按规范的名字声明成 CSS 变量、14 档字阶一一对应成 `.t-*` 类
（`display-xl` … `caption-uppercase`，字号 / 字重 / 行高 / 字距逐条照抄）、圆角 7 档与间距 8 档一个不少；
规范没给的中间值往相邻一档取（窄屏把 96px 收到 48px、标题从 `display-xl` 退到 `display-lg`）。
所以它**不受 `tokens.css` 约束，也不跟着应用令牌改**：要改它的样子，改的是 `DESIGN.md`（或换一套规范重新导出）。

应用窗口配图是四张（比 `site/` 少一张：技能那一节改用规范组件表里的 `code-window-card` 直接展示
`SKILL.md` 的 diff），**颜色、圆角、字号换成了规范的色值**（`app.css` 顶部那批 `--ap-*` 映射到
规范的画布 / 表面 / 暗面 / 状态色），尺寸则保留应用自己的比例（窗口 1160×742、标题栏 36px、顶栏 64px、
导航栏 88px）—— 照真界面的比例画，看起来才是那个应用；因此它比 `site/` 更会漂：改规范时这两处要一起改。
落地页自己的按钮、输入框、卡片、标签页、徽标则完全按规范「组件」一节的规格来（40px 高、`12px 20px`
内边距、8px 圆角、`4px 12px` 胶囊…），没有第二套数字。

比 `site/` 多两处交互：用量趋势那三个区间标签页**能真的切**（示意数据，合计与区间日期由脚本按同一批值现算），
首页布局示例那颗「重置布局」把卡片摆回进页面时的样子。
