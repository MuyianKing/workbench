# TBuddy（网关：CodeBuddy 反代）

## 约束

- **只监听 `127.0.0.1`**。这不是默认值可以改的配置项 —— 网关进程里带着账号 token，任何监听
  `0.0.0.0` 的版本都不该存在。端口可改，回环地址不可改。
- **Qoder 网关是另一套独立实现**（自己的端口 17879、密钥与 `wb-qoder/settings.json`），
  与这一页互不相干、可以同时跑；换这一页的密钥不影响 Qoder。细则见 [qoder.md](qoder.md)。
- **监听默认随程序启动，可在设置·通用里关掉**。打开时应用启动即绑 `127.0.0.1`（不连上游；
  点「登录」才连）。手动「停止」只在本次会话有效，下次启动照旧监听；关掉开关后仍需手动点「启动」。
  开关只改配置，不立刻启停；监听地址不可改。
- **接入信息值得单独一层弹层，但不进设置**：地址与密钥是第三方客户端缺一不可的两样，一件都不能藏；
  但它们只是「配客户端时抄一次」的东西 —— 收进 `AccessDialog`，页首统计带最后一格点开。
  常驻过一版：那张卡把下面三栏一直往下推，而这两样一天看不了一回。
- **模型目录从上游拉，不写死、也不轮询**：**每次进入「模型」栏**都用第一个可用账号探
  `/v3/config`（字段最全），失败再退 `/console/enterprises/personal/models`，合并去重后落进
  `models.json`；界面、`/v1/models` 与接入信息都读那一份。进入时先把缓存读上屏，再在后台刷一次；
  **不挂定时器** —— 停在这一栏时不重复请求，切走再回来才拉。`SEED_MODELS` 只在一次都没拉过时
  给 `/v1/models` 兜底（免得首启返回空数组），**不往界面上摆**：界面没拉过就是空表 + 「登录一个
  可用账号后会自动拉取」。刷新失败时如果表里还有缓存就静默保留，只有空表才弹提示。
  上游没给的字段（上下文、最大输出、思考档位、倍率）显示 `—` / 「未知」，不拿本地推断冒充事实。
- **这一页的字号比全局大一号**（`--gw-fs-*`，定义在 tokens.css）：主体是表格与小号说明字，
  压在壁纸上 10.5 / 12px 读着发虚。只有 `components/gateway/*` 吃这套 —— 别处要放大先想清楚，
  不然全应用一起长。
- **各栏都不单起标题带**：页签已经写着栏名，再为标题铺一块玻璃卡只多占一行；
  「账号」栏不再写「账号池」；右下角一排浮动圆键：导出 / 导入两枚工具键（账号搬运，
  没有账号时导出置灰）、刷新积分一颗工具键（页面数据走 15 秒轮询，不放手动键）、登录加号
  （点一下就去浏览器授权）；
  **这几颗钉在页面可视区的右下角，不是窗口右下角**：`position: sticky` + `margin-top: auto` 停在
  `.gw` 这个滚动容器里面，终端面板展开、页面变矮时跟着上移到面板上沿 —— **不许改回 `position: fixed`**
  （会贴在窗口底边、正压住终端面板）。`bottom` 与两条外边距都写成 `calc(sp-5 - sp-3)`：
  sticky 的 inset 与外边距都从内容盒量起，而 `.gw` 自己有一圈 `sp-3` 内边距，减掉才落在离页边 `sp-5`
  「请求」的条数并进条件带右端、与「重新读取」同侧；「模型」连条件带都不留（进栏自动拉取，
  没有要手动点的按钮），直接铺卡片网格。
- **三张数据表（请求 / 用量明细 / 成长任务）共用一个 `GatewayTable`，列宽交给内容**：
  一律 `table-layout="auto"`，**不写 `width` / `min-width`** —— EP 的 auto 布局只有在没有任何列宽时
  才不生成 colgroup，写了宽度又会回到固定列。不再手写 `<table>`、也不写死每列像素宽
  （优先级那颗输入框自己的宽度除外）。**所有列（表头与内容）一律居中**：`el-table-column` 全部
  `align="center"`，首末列也不做「贴左 / 贴右」的单边内边距 —— 否则居中会被 4px 的偏移带歪。
  数字列一律等宽体 + `tabular-nums`（列上挂组件约定的 `gw-num`；请求栏的值本身包在 `req__mono` 里），
  别再各起一个类名。
- **两排统计卡固定 6 列、不折行**：账号页六张（末列积分卡给 `1.5fr`，它的数字最长）与用量页
  六张 KPI 在内容宽度 1100 以内都不换行；窗口最小 1080（内容约 980）也放得下。
  **别写回 `repeat(auto-fit, minmax(...))`** —— 它会在 1100 左右把第六张挤到下一行。
- **用量栏与 Qoder 共用同一份 `UsagePane.vue`**：Qoder 通过 `:load-rows` / `:load-names` 注入自己的
  `wb_qoder_usage_rows` 与账号名，布局、统计口径与刷新节奏都跟着这一页走 —— 改用量页时两边一起看。
- **账号池是卡片网格，不是表格**：每个号一张毛玻璃卡（与统计卡同一套 `.panel` 玻璃），
  卡头是名字 + 状态、右上角是查余额 / 启停 / 删除（**不显示 uid**：一串 36 位的号没有信息量），
  卡头下面一排左边是额度恢复提示（多数账号平时没有）、右边是优先级，再往下是积分与余额条、
  成功失败 / 用量 / 均速三格；
  积分一行同时给「剩余 / 总额」与「已用」，行尾再给**最近到期**那枚天数
  （`N 天后到期` / `今日到期`；无期限、到期未知、已过期、已花光都不占位），余额条的彩色段是剩余、灰底是已用；
  左侧一截 3px 状态色标（可用绿 / 待续期灰 / 额度用完与部分模型用完琥珀 / 已停用红），颜色只表达状态。
  **积分那一行整块可点开明细**（点与回车 / 空格都行）：卡上只给最近一个到期日，逐包的到期时间
  放在 `CreditsDialog` 里 —— 按到期从近到远排，只列还有剩余的包。
  **卡片里的每一格高度固定**：额度恢复提示与优先级同一排，空着时也 `visibility: hidden`
  占住左边的位（这排的高度由优先级输入框兜着，删掉它优先级会跳到左边）；余额条即使没有内容也照样留位 ——
  这些只有部分账号才有，按条件删掉会把同一排卡片下面的积分条与三格顶得错开。
- **模型栏也是卡片网格**：每个模型一张玻璃卡（极淡的主题色柔光 + `Cpu` 图标，图标与底都取主题色），
  卡头是模型 ID + 名称 + 复制按钮，下面是上下文窗口 / 最大输出 / 倍率三格，
  再下面是思考档位与单价两行（未定价标琥珀）。**不再用表格**。
- **这一页的彩色是明确例外（用户要求）**，只落在这几处：
  统计卡图标（总数蓝 `#2f6bd8`、可用 `--st-ok` 绿、已停用 `--st-fail` 红、待续期灰 `#8a94a6`、
  额度用完 `--st-run` 琥珀、积分紫 `#7c3aed`，图标底是同色 16% 的 `color-mix`）、
  用量页六张 KPI 的图标（请求蓝 / 总 token 紫 / 输入青 `#0e7490` / 输出橙 `#c2410c` /
  成功率绿 / 延迟琥珀）、账号头像（紫 `#7c3aed`）、
  余额条（≥50% 绿 / 20–50% 琥珀 / <20% 红）、
  积分明细弹层里的到期档位标签（≤10 天琥珀 / ≤5 天橙 / ≤3 天红 / 今日红实心；
  已过期 / 无期限 / 到期未知保持灰）、
  福利栏的数字格图标（Buddy 加油站蓝 / 连登绿 / 补签灰 / 抽奖琥珀 / 猫猫紫 / 能量青 / 福利积分橙，
  与统计卡同一套图标底）、福利栏里「今日已打卡 / 未打卡」这类状态字与任务状态标签（只取
  `--st-ok` / `--st-run` / `--st-fail` / 灰）。
  账号卡只铺 7% 的状态色柔光，别把这个色板扩到别的页或别的部件。
- **表头钉住；常驻一层主色浅底**：「请求」与「成长任务」给 `GatewayTable` 传 `height="100%"`
  （外层定高），滚动收进表格内部；auto 布局下表头是 `.el-table__body-header`，EP 在
  `.el-table--scrollable-y` 上已经给了 `position: sticky`。表头无论停在顶部还是滚着都铺
  **主色最浅那一档的实色浅底**（`--el-color-primary-light-7`，与导航栏当前项同一档口径，
  没配主题色时是灰阶）+ 下沿短投影 —— 行会从字底下滚过，不铺实底行文就透上来
  （`backdrop-filter` 不采样同一滚动容器里滚过的内容，「磨砂表头」做不出来）。
  之前那套「平时透底、滚起来才补底」会在回到顶部的一瞬跳回全透明，2026-10 起改成常驻。
- **表格铺满面板**：`GatewayTable` 的面板外壳内边距归零（`padding: 0`），表头与首行直接贴到
  卡片四边，单元格自己的间距保留；已经在页面自己的面板里的表传 `flat`（用量明细），不再套第二层卡。
- **页签与筛选不要长一个样**：页签（账号 / 用量 / 请求 / 福利 / 模型）用共用组件
  [GatewayTabs.vue](../../apps/desktop/src/renderer/src/components/gateway/GatewayTabs.vue)
  （与 Qoder 同一份）：下划线式导航，文字 + 2px 主色下划线、不铺底色、字号走 `--gw-fs-body`（14px）、
  项间 `--sp-5`；**页面里别再自己写 `el-tabs` 的 deep 规则**。时间范围这类筛选继续用
  `el-segmented` 药丸 —— 两排一模一样的药丸叠在一起时，分不清哪个是「在哪一栏」、哪个是「看多长时间」。
- **启停就在页首那一行**：页签靠左、网关状态与启停靠右，每个页签下都看得到 ——
  这一页最高频的动作不该先点开一层，也不该只在「账号」栏才有。点状态开接入弹层，
  旁边那枚按钮就地启停，所以弹层里也不再放第二份。「随程序启动」在设置·通用 → TBuddy；
  「福利每天自动」也在那一块（TBuddy 与 Qoder 共用一个开关），都不占页首这一行。
- **密钥默认开启**：首次启动自动生成（`wbg-` + 32 位 hex），除 `/health` 外一律校验。
  它不是防外人的（只监听回环），是防本机其它程序随手调，以及满足客户端"key 不能为空"的要求。
- 账号视图**不含 token**。`wb_gateway_accounts` 只回展示字段，界面拿不到凭据；想加"顺便把令牌读回来"
  的接口，先读这一条（**唯一例外**是用户显式点「导出」时走的 `wb_gateway_accounts_export`，见「账号导出 / 导入」）。
  **账号卡上不写类型**：只接国内版（CodeBuddy），一行类型标签只是把同一件事写两遍。
- **账号池先按积分到期时刻、再按优先级选号，额度用完自动让位**：账号文件里的
  `creditExpiresAt`（最近一笔还有剩余、明确会作废的包的到期时刻，查余额时由 `wb_gateway_credits`
  写回）最早的那个号先用 —— **谁家的流量先作废就先花谁家的**；没有已知到期（无期限 / 没查过 /
  已过期）的号排在已知到期之后，同一档再按 `weight`（1..=100，界面上叫「优先级」，数大的先用）
  与加入时间排。停用、待续期、额度标记未到期的号跳过（`wb_pool::order`）。
  `creditExpiresAt` 是派生数据、只跟着查余额刷新：跨过那个时刻就按「没有紧迫的包」处理，
  不会把已经作废的包算成紧迫；想让它保持新鲜就打开网关页（进页面会把所有号的余额查一遍）。
  额度标记分两档，**粒度不能混**：
  - **按模型**（上游 `code 6004`：「您的使用量已超出频率限制，将在 … UTC+8 重置」）：
    实测同一个号这个模型 429、换个模型立刻 200，所以只挡这一个模型（`quotaModels`），
    界面上是「部分模型用完」+ 「模型名 时间 恢复」那行小字；
  - **按号**（正文说「额度 / 余额 / 积分用完」这类，`wb_quota::looks_exhausted`）：整个号停一段时间。

  **认不出的 HTTP 429 不打标，但会再换一个号试一次**：上游用 429 同时表达「模型繁忙」
  （`code 14003`，实测同一个号几秒后就正常出数）与「模型额度用完」（`code 6004`）——
  前者误判会把好号封一整天，所以不封号；但也不该直接丢给客户端，所以按顺序再试**一个**号，
  仍被拒才回 429（整池试一遍会让客户端白等，实测一次 429 往返 2–7 秒）。
  打标后同一条请求同样按顺序换下一个号重试；同一个模型一条能用的号都不剩才回 429（带上最近恢复时刻）。
  恢复时刻优先取正文里的「将在 YYYY-MM-DD HH:MM:SS UTC+8 重置」，其次企业额度的周期结束时间，
  都没有才按 24 小时兜底；到期自动失效，不需要定时器。「查余额」查到还有余额只清**整号**标记
  （积分没动但模型限额仍在的情况很常见），手动启用则两档一起清 —— 都不需要用户去改文件。
- 余额查询是**显式动作**，不是 GET 副作用。原项目把 `GET /accounts/credits` 做成"遍历每个号真打一次
  上游"，一个读请求带着写代价 —— 这里拆成「读缓存」与「点刷新」两个动作。
- **不猜数字**。上游没给的字段（token 数、到期时间、积分）一律留空或 0，界面上显示"未查询 / 未记录"，
  不拿估算值冒充事实。**积分只认上游 `usage.credit`，不拿 token × 倍率去推**。
- **积分比率的口径固定**：分母是**积分大于 0 的请求的总 token**（`creditTokens`）；缺积分与
  `credit = 0` 的免费请求都既不进样本数（`creditSamples`）也不进分母（零消耗的 token 不参与折算）；
  跨账号 / 跨模型汇总时，先把积分与 token 两个总量分别累加，再**直接相除**，
  不平均各组比率。总 token 含缓存命中的 token，而缓存 token 的积分单价远低于输出 token —— 比较两个账号 /
  模型时先把缓存命中率一起看，别把这个数当模型单价。
  **序列化名是大写的 `creditsPer1MTokens`**：serde 的 `camelCase` 会把 `credits_per_1m_tokens`
  中间的 `1m` 原样留下（`creditsPer1mTokens`），与前端契约对不上；三个汇总结构上都要显式
  `#[serde(rename = "creditsPer1MTokens")]`，`wb_usage` 的「积分比率字段按前端契约序列化」
  用例守着这一条。名字对不上时 KPI 会静默显示 0、明细表在 `undefined.toFixed` 上抛错。
- **明细只有一张表、积分总账单独一张面板**：「用量明细」的每一行同时给用量（请求 / 失败 / token / 延迟 / 速度）
  与积分（扣除积分 / 匹配 Token / 比率 / 缓存命中率），由同一个「按账号 / 按模型」切换控制；
  积分汇总（扣除积分 / 匹配 Token / 平均积分每百万 / 有效样本 / 命中率）放在表格**上面**，
  **单独一张 `.panel` 毛玻璃面板**（不再套在明细面板里）：左侧主数字（扣除积分）占满两行、右侧 2×2 放佐证，
  一整块面用发丝线分隔，层级靠字号与留白拉开 —— **不是五张并列小卡**，也不许靠放大字号充数。
  它内部照样把 `.panel` 的内边距与间距收掉（`.usage__cost.panel`），发丝线才能铺到卡片四边；
  覆盖 `.panel` 的规则要写成 `.usage__cost.panel` —— 同权重时组件样式排在全局样式之前，覆盖会静默失效。
  不要再拆回两张表 —— 同一个账号要在上下两处对齐看，请求数还会写两遍。
  主数字那格左侧带一截 3px 主题色标，佐证里只有「平均积分」取状态色的绿（它是唯一带「划不划算」判断的一项）。
- **用量页没有手动「同步 / 刷新」按钮**：刷新沿用 15 秒轮询；网关流水改成**按用量自动同步** ——
  30 天总 token 每新增 10M 就强制推一次 git（`GatewayView` 的 15 秒轮询里判定，用量页只是其中一栏）。
  第一次刷新只记基线、不立刻推；流水被清或老行滚出 30 天窗口时把基线压回当前值；
  失败 5 分钟后再试，不顺带每 15 秒撞一次；没登录 / 没配仓库时什么都不做。
  **进页面还会只拉不推地刷新一次远端克隆**（`gateway_sync_pull`，一分钟节流）：读路径只读本地副本，
  而克隆平时只有本机推送时才顺带 pull —— 本机一天没有流水时，别的机器推上来的今天会一直「没同步到」。
- **时序图固定看最近 24 小时，并且排在最底下**：横轴是 24 个 UTC+8 小时桶（`recentHourBuckets`，
  没有请求的小时补 0），纵轴四档 25 / 50 / 75 / 100%，刻度取整数、单位（M / K）只标在轴顶一次；
  网格线是压淡的虚线，画在柱子后面；顺序是 KPI → 积分总账 → 明细表 → 时序图 ——
  先看这段时间花了多少、分在谁身上，再往下看最近这一天的节奏。
  页面顶上选的时间范围（**默认「今日」**）只管 KPI 卡与明细表，不改图表的窗口 —— 两者回答的不是同一个问题。
  柱子仍取主题色（`--el-color-primary`），不代表状态。
- **时间范围按自然日算**（`wb_usage::window_start`，UTC+8 零点起）：`今日` = 今天 0 点到现在，
  `昨日` = 昨天 0 点到今天 0 点（Rust 只有「含今天往前数 N 天」这一种窗口，页面取 `days = 2`
  再把今天那一段裁掉），`近 3 天` = 今天加前两天，依此类推。**不是滚动的 N×24 小时** ——
  上午打开时滚动窗口会把昨天下午也算进「今日」，两档显示同一批数，看着像切换没生效。
  取数起点另由 `wb_usage::fetch_start` 定：至少往前铺满 24 小时（「今日」在上午比 24 小时短，
  图表要这一段），所以 `wb_gateway_usage_rows` 回的是 `{ since, rows }`，行可能早于 `since`
  （「昨日」还可能晚于窗口上界），KPI 与明细表由页面按 `since` 与次零点再裁。
  同步仓库那边的窗口也用同一个 `since`（`read_gateway_rows` 收 Unix 秒，不再收天数）。
- **网关只在本机跑**：单账号或少账号、由用户手动启停，**不做账号池的自动轮转 / 熔断与配额护栏**
  （只有到期时刻 + 优先级选号与额度用完让位，见上）；账号由用户手动登录。**历史流水可以可选地
  同步到用户的私有 git 仓库**（见「多机流水同步」）—— 网关进程本身仍然只监听回环、只在本机执行。
- **出站请求体要先过指纹清洗**（`wb_sanitize`）：上游会对 system 里的 Claude Code / Codex CLI 固定模板句
  做逐字匹配，命中回 400 `11-128`「Illegal API invocation from an unapproved channel」。只改确认会被拦的
  那几整句（`Main branch (...)` → `Default branch (...)` 等），**不要把它扩成通用内容过滤**，也不许拿它删
  用户内容；这张字面量表随上游更新（口径来自 workbuddy2api-hub）。同一趟还要把 `developer` 归一到
  `system`、`{type:"reasoning"}` 片段折进 `reasoning_content`、给 DeepSeek 的 assistant 按 thinking 状态
  回填 `reasoning_content` —— 否则长会话分别撞 11101 / 11155。
- **客户端形状在出站前收敛，不改用户内容**（`wb_relay::normalize_body`）：`tool_choice` 对象降级成
  字符串（`none` 时保留 `tools`）、`tools` 丢掉空 function / 裸服务端工具 / 非法 function.name / 重名并补空
  `parameters`、`stop` 字符串包成数组、glm-5.1 缺思考档补目录默认档（拿不到回 `medium`）。这些分别对应
  上游的 11101 / 11133 / 11150；**只做形状归一**，不要借这一步删消息或改提示词。
- **任务福利默认只认用户点出来的动作**：`wb_tasks` 本身没有调度器；进「福利」栏只做只读查询
  （当前号的成长任务与汇总两块并行，外加积分流水，见下），切账号 / 点按钮才会再打上游。
  **唯一例外是设置·通用里的「福利每天自动」开关（TBuddy 与 Qoder 共用，默认关）**：打开后应用启动时补跑一次，之后
  每十分钟由渲染层问一次该不该跑（判断全在 Rust 侧，不该跑时不联网）。白天轮 = 签到 +
  一键做任务（成长任务 / 猫猫旅行 / 盲盒），夜间轮 = 夜猫子（只在 23:00–08:00，每号每自然日一次）。
  **成长连登与抽奖不自动跑**（会消耗补签卡）；应用关着的那天不跑，下次启动补。
  这与参考项目的自动巡检仍不同 —— 不替用户决定什么时候花额度。
- **每一次签到尝试都落一行**（`activity.jsonl`）：时间、uid、昵称、任务、结果、
  一句截断并脱敏过的说明。**不落 token / cookie / 请求体**；上游错误原文先折叠换行、把
  `Bearer …` 与 32 位以上的连续十六进制 / `sk-` 形态打码，再截到 200 字。这是「今日已签到」
  的唯一本地依据，也只代表**这台机器**上的尝试（不参与多机流水同步）。
- **签到只认「真签成」与「今天已签到」**：`code 10001` 不是签到成功专属码（活动补偿、重复操作也用它），
  「请求处理中 / 请勿重复操作 / 系统繁忙 / 稍后再试」一律记失败；`code=0` 但文案带「失败」也记失败。
  **不许退化成「HTTP 200 就记成功」** —— 这条决定界面上「今日已领」是否可信。
- **任务的几条硬口径**：专家 / 团队事件必须用互不相同的 id（上游按 `(eventCode, id)` 去重），
  夜猫子任务只在 23:00–08:00 上报才计数，未接取的任务上报不计进度（先接取、复核一次、仍不成再跳过），
  只认桌面端真实行为的四个任务（`DESKTOP_ONLY_TASKS`）诚实跳过、不伪造事件。
  领奖在桌面端回 HTTP 400 时降级到 `www.workbuddy.cn` 的网页端再试一次 —— 这是这一页唯一会碰
  那个主机的地方。
- **专项任务必须用任务指定的专家 id**：`WorkBuddy_Valorant` / `workstation_expert` /
  `expert_use_*` 走 `TASK_SPECS` 里的固定 id；没预录入的从 `jump_url` 的 `deeplink.expertId`
  解，解不出才退回通用专家池。**通用池轮换上报不会涨进度** —— 上游只认那个真实 id。
- **Buddy 盲盒只在能量够时开**：旅行领奖后与跑完任务后各看一次
  `/v2/activity/growth/buddy/quota`，`affordable > 0` 才调 `/buddy/open`（`count` 取
  `affordable` 与 `max_open_count` 的较小值）；企业版没有成长体系，直接跳过。没有单独按钮。
- **福利栏是一张完整的面板**（`.panel`）：标题、说明与动作都在面板里，
  不把标题直接摆在壁纸上；数字是面板内的格子（`auto-fit` 网格），**底色只用 7% 语义色 + 同色 14%
  细描边，不铺灰底** —— 灰底在玻璃面板上会变成一块块灰砖；数字格下面是积分柱状图，
  再往下才是成长任务表（同样在面板里），
  上方一行「成长任务 · 共 N 项」，表头钉住、表体在表内滚动。**不摆执行日志**：一键做任务的
  接取 / 上报 / 领奖流水只在后端跑，页面只留一条结果提示（新增积分）—— 过程日志没人看，
  摆在面板底下只占版面。
  成长任务表与「请求 / 用量明细」共用 `GatewayTable`（`table-layout="auto"`、所有列居中、
  不写列宽、数字列 `gw-num`）；**表头钉住、表体在卡片里滚**（表格 `height="100%"` +
  表容器 `flex: 1 1 auto`）。**表格吃满面板剩下的高度、面板吃满页签下面剩下的高度**
  （窗口多高就多高，不再给 `clamp(...)` 那种写死的档位）：`.gw` 对 `.perks` 放行
  `flex: 1 1 auto`（与请求 / 模型两栏同一组），`.perks` 与 `.panel.perks__section` 逐层
  `min-height: 0` 往下传；面板里标题 / 数字格 / 柱状图 / 小标题都 `flex: none`，只让表格那一格伸缩。
  **不要改用 `max-height`** —— EP 会在那种情况下把布局切成 fixed，列宽就不再跟内容走。
  边框、圆角与表头外观由组件给；空态 / 读取中同样套面板（`.panel`），不留一行干字。
- **福利积分的口径是「最近一次查到的积分包快照」**：按发放来源 / 包名 / 发放原因筛
  （`grantSource` 是签到 / 成长 / 旅行，或包名带「裂变」，或 `grantReason` 命中签到 / 成长 /
  活动 / 裂变 —— 与柱状图共用 `isGrowthPerkPackage`）；没查过余额时显示 `—`，不拿 0 冒充。
  动作结束后由福利栏通知 TBuddy 页重查余额（`credits-refresh`），福利栏自身不额外打上游。
- **「近一个月积分获取」柱状图的数据是积分包流水**：上游的积分逐包记账，签到 / 成长任务 /
  猫猫旅行各发一个包（`CreateTime` + `grantSource`）。`wb_gateway_credit_grants` 用
  `get-user-resource` 的宽时间窗取整段包历史（**已花光 / 已过期的包也要** —— 余额查询那种
  `begin = now` 的窗口会缺几天），每个号一次只读 POST；界面按 **UTC+8** 的发放日把福利包相加、
  只留最近 30 天（含今天），缺的天补 0。福利包的口径与「已获取福利总积分」一致：`grantSource`
  是签到 / 成长 / 旅行，或包名带「裂变」，或 `grantReason` 命中签到 / 成长 / 活动 / 裂变；
  拉新权益包 / 体验版这类一次性赠送不进图，否则第一天的礼包会把整月的柱子压平。选「全部账号」
  时逐个已启用账号各读一次；某个号失败只在标题旁标出个数，其余账号照常画。企业版是周期额度、
  没有逐包发放记录，直接回空。柱子取「已获取福利总积分」那枚图标的橙，**不是主题色**
  （主题色的适用范围没有扩大）；没有启用账号时不画这一块，整月为 0 时给空态。
  **图用 ECharts 按需画**（`echarts/core` + Bar / Grid / Tooltip + Canvas，不引整包）：
  纵轴仍只标半程与顶格，横轴标签抽稀到七来个、今天必标，悬停按整列高亮（axis 触发）；

### 三个不显然的设计

**1. 上游调用要两根线程。** 网关得先知道上游状态码，才能决定回给客户端的是「200 + SSE 流」还是
「401 + 错误 JSON」；而这两件事都发生在读正文之前。同步做只能二选一：缓存整段（丢掉流式）或盲猜
200。于是 `wb_api_chat` 把上游调用放到单独线程，用通道把「状态码」与「正文片段」按到达顺序送回；
调用方阻塞等到状态码，再组装自己的响应。`http::request_url_stream` 为此多了一个 `on_head` 回调。

**2. 记账写在响应收尾处，不在入口。** 流式请求的 token 数只有末帧才知道，所以 `UsageRow` 在
`Response::sse` 的闭包尾部落盘。写失败**不打断用户** —— 账本的问题不该让对话报错。

**3. 认证凭据是明文的。** 与客户端自己、与原项目同口径：`accounts/<uid>.json` 里的 token 不加密。
这一点在文档里写明，而不是假装它已加密。

### 登录流程

`POST /v2/plugin/auth/state?platform=CLI` 拿 `state` 与授权链接 → 浏览器授权 → 轮询
`GET /v2/plugin/auth/token?state=` 换 token → `GET /v2/plugin/login/account?state=` 取昵称与企业 id。
state 存在内存里（10 分钟过期），不落盘。上游签发 state，没有 PKCE。

之后靠 `POST /v2/plugin/auth/token/refresh`（`X-Refresh-Token` 头）续期，**永不再走登录**。

### 账号导出 / 导入

账号栏右下角那两枚工具键「导出 / 导入」（`Download` / `Upload`，与刷新积分、登录加号并排）把整套凭据在设备之间搬：导出一段 JSON 让用户抄进密码管理器，
另一台设备把它贴回来，**不必每台机器重新登录一次**。全程本地，不走文件对话框、不联网、
也不进 git 同步仓库（同步仓库里只有脱敏后的请求流水）。

- 格式是一层外壳 `{ kind, version, exportedAt, accounts }`：TBuddy 的 `kind` 是
  `"workbench-gateway-accounts"`；Qoder 是 `"workbench-qoder-accounts"`，账号字段按各自的模型，
  互不混用。导入只认自己的 `kind`，版本高于 1 直接拒绝。
- **只导出凭据、身份与偏好**（`accessToken` / `refreshToken` / `expiresAt` / `nickname` / 企业或组织 /
  `product` 或 `userType` / `weight` / `enabled` / `note`）。额度标记、`creditExpiresAt`、Qoder 的
  签到与活动记录、`tokenExpired` 这些是本机瞬时状态，一律不导出；导入时按默认值重建。
- 同 uid 怎么办由用户当场选：「跳过已有」（默认，本机那份可能更新）或「覆盖本机」。
  导入的号 `source` 写 `"import"`；先写盘成功再改内存，最后按 `addedAt` 排序（与 `load_all` 一致）。
- **导出内容含明文 token**，这是账号文件本来就不加密的直接后果：拿到那段 JSON 等于拿到这些号。
  它只由用户点「导出」触发，`wb_gateway_accounts_export` 是账号视图之外唯一回读 token 的通道；
  复制走 `navigator.clipboard`，不加新的 Tauri 权限。
- 两台机器同时长期使用同一个号时，续期可能各自拿到新的 refresh token（上游若轮换，先换的那份会让
  另一份失效）。要长期并行就各登录一次；只做搬家就「导出 → 导入 → 旧机器停用」。

### 随程序启动

设置·通用 → 网关里是**两个独立的「随程序启动」开关**：TBuddy 的经
`wb_gateway_auto_start_set` 写 `wb-gateway/settings.json` 的 `autoStart`，Qoder 的经
`wb_qoder_auto_start_set` 写 `wb-qoder/settings.json` 的 `autoStart`（都只写配置，不启停；
**默认开**，缺字段按开处理，显式写 false 才关）。
`main.rs` 的 setup 在 `commands::load_all()` 之后分别读两份配置：谁开了就拉谁，
端口被占等失败只往标准错误记一笔，不阻塞应用启动，界面照旧显示「已停止」并允许手动重试。
两个 `status` 都把 `autoStart` 一起回给界面，设置屏每次打开弹窗时读一次。
`wb_gateway_start` 成功后仍把实际绑定的端口写回配置；「停止」不改 `autoStart`。

命令都在 `wb_gateway.rs`，网络与解析在 `wb_tasks.rs`；界面是 `components/gateway/PerksPane.vue`

`checkin-activity-status`（只读 POST）——`today_checked_in` 判断今天签没签、`checkin_dates`
算当前连签（上游 `streak_days` 是本赛季累计，不是连签）、`week_checkin_days` 是本周天数。
福利栏的「Buddy 签到连签」用这个；成长连登仍取 `/activity/growth/streak`，两者分开显示。
自动跑也先用 `today_checked_in` 跳过已签的号，查不到才回退本地 `activity.jsonl`。

补签候选：从 `/activity/growth/heatmap` 里选**当月、今天之前、活动上线之后、`score = 0`、
不在 `makeup_dates` 里**的日期，最近的断点优先，每轮最多一张（`MAKEUP_MAX_PER_RUN = 1`）。
没有补签卡就不拉热力墙；日历结构不对就停止，不拿猜测去消耗卡。
签到状态与补签候选口径参考 `88lin/workbuddy-auto-signin`（MIT）。

跑任务前会按需续期一次 token（与查余额同一条规矩：网络请求不占状态锁），跑完只把 token 字段
写回磁盘。单个号失败不会带走后面的号；批量执行时每一轮前面都有一行 `====== 账号 … ======`。
跑完任务会顺手做一次猫猫旅行；旅行领奖后与其它状态下各查一次成长能量开 Buddy 盲盒
（`/v2/activity/growth/buddy/quota` → `/buddy/open`，能量不够就跳过）。

#### 福利自动跑

开关只有一处：设置·通用 → 网关的「福利每天自动」（TBuddy 与 Qoder 共用，默认关）。拨一次同时写
TBuddy 的 `perks-auto.json` 与 Qoder 的 `wb-qoder/perks-auto.json`（两边各读自己的；打开设置时若两份
不一致，按「任一边开着就算开着」对齐）。`App.vue` 启动时调用 `stores/perks-auto.ts` 的
`startWatch()`，立刻问一次、之后每十分钟问一次，一次问两边。**判断在
`wb_gateway_perks_auto_run` / `wb_qoder_perks_auto_run` 里各自做**：开关关着直接返回，不读账号、不联网。

- 白天轮（每号每本地自然日一次）：续期 → 先查服务端 `checkin-activity-status` 的
  `today_checked_in`（查不到回退本地 `activity.jsonl`）→ 已签跳过、未签 `checkin` →
  `run_growth_tasks`。企业版直接跳过（没有成长体系）。跑完把 `daily[uid] = 今天`。
- 夜间轮（每号每自然日一次，只在 23:00–08:00）：`run_night_owl` 只找 `black_cat`，
  未接取就先接取，然后**只上报一次**（`progress_one` 的 `report_limit = Some(1)`），
  进度够了再领奖。白天轮如果本来就在窗口内跑过，夜猫子已被顺手做掉，就把 `night[uid]`
  一起记成今天，23:00 不再重复（任务清单都没读到时除外，留给夜间轮再试）。
- 续期失败不记完成（下一轮十分钟后再试）；其余失败记完成（避免每十分钟锤上游），
  手动按钮仍可重试。自动跑只处理个人号；「成长连登与抽奖」不在自动范围内。
- 应用进程关着时不会跑 —— 桌面应用没有常驻服务，「每天」实际是「应用至少打开过一次的那天」，
  下次打开补。

### 数据落位

数据目录下的 `wb-gateway\`（安装版 `%APPDATA%\Workbench\data\`，开发版
`%APPDATA%\Workbench-dev\data\`；下面按安装版写）：

```
%APPDATA%\Workbench\data\wb-gateway\
  settings.json      端口与自启开关（Qoder 网关有自己的一份，见 [qoder.md](qoder.md)）
  accounts\<uid>.json  账号（token 明文；weight 是选号优先级，creditExpiresAt 是查余额时写回的
                       最近到期时刻，quotaExhaustedAt / quotaResetsAt 是整号额度标记，
                       quotaModels 是按模型的额度标记）
  usage.jsonl        请求流水（一行一条，只追加）
  models.json        上一次从上游拉下来的模型目录（含 fetchedAt）
  activity.jsonl     签到尝试记录（一行一次真实尝试，见「任务福利」）
  perks-auto.json    福利自动跑的开关与每号上次跑的日期（uid → YYYY-MM-DD，见「福利自动跑」）
```

`perks-auto.json` 的 `enabled` 默认 false；`daily` / `night` 是两张 `uid → 本地自然日` 的表。
它只在本机，不参与用量同步 —— 换一台机器视为「今天还没跑过」，会在那台机器上再跑一次。

`activity.jsonl` 的一行只有 `ts`（Unix 秒）、`date`（本地自然日，读「今天」不必再猜时区）、
`uid`、`nickname`、`task`（`checkin`）、`ok` 与 `message`（折叠换行、
打码、截到 200 字）。它**不参与**用量同步；跨机器的签到记录不合并，所以「今日已签到」只代表
这台机器上试过。文件超过 1 MiB 时只留最近 2000 行。

`usage.jsonl` 的一行除 token 数之外还记：`machine`（产生这条流水的机器名，旧行没有就是空串）、
`effort`（客户端要的推理强度，取自请求体）、`stream`（流式与否）、`reasoningTokens`（思考 token）、
`credit`（上游在 `usage.credit` 里给的单次扣费，没给是 `null`）、`apiKey`（调用方密钥的**末四位**，
`…cdef` 形态）与 `costCny`（早期按价表折的估算花费，未定价是 `null`，**只留在历史流水里，界面不再展示**）。
`error` 记失败原因：额度失败写「额度用完」，非额度失败写「HTTP 状态码 + 上游正文前 200 字」（空白压平）——
上游同一个 429 既可能是模型繁忙也可能是额度用完，只留状态码事后分不出来。
密钥只留末四位是硬约束：这个文件是会被翻着看的。同步到仓库时会再去掉 `apiKey` 与 `costCny`（见下一节）。

### 积分与 token

用量页只回答一个问题：这些 token 一共扣了多少积分。

- 分子是 `UsageRow.credit` 之和，分母是**同一批积分大于 0 的请求的总 token**（`creditTokens`）。
  缺 credit 与 `credit = 0` 的免费请求都不进样本数（`creditSamples`）、也不进分母 ——
  零消耗的 token 不参与积分折算。
- 比率 = `credits / creditTokens × 1_000_000`。跨模型 / 跨账号的总比率由两个总量**直接除**，
  不是各组比率的平均。
- 按账号 / 按模型各自算自己的比率；没有样本的组显示「未记录」，不显示 0。两种维度带上同一套字段
  （请求 / 失败 / token / 延迟 / 速度 / 积分 / 缓存命中率），所以明细表切维度时列不跟着变。
- 总 token 口径包含缓存命中 token，而缓存 token 的积分单价远低于输出 token，所以这个数会随缓存命中率漂移。
  比较两个账号 / 两个模型时先把缓存命中率一起看。
- 单条流水的 `credit` 只保留两位小数，短请求的逐条比率噪声大，**只做聚合，不逐条算**。
- 「模型」栏里的单价是横向比价用的静态快照，不是消费账，也不参与这里的积分比率。
- 用量页**自己每 15 秒重读一次**本机流水（与 TBuddy 页顶栏同一个节奏），页面被 `KeepAlive` 缓存时暂停、切回来立即补读。
  只挂 `onMounted` 的话，打开那一刻读到什么就一直是它 —— 清空流水后正好读到空文件，就会一直显示 0。
- **取数与统计分开**：Rust 的 `wb_gateway_usage_rows` 只回窗口内的流水（本机 + 同步仓库里别的机器）
  与窗口起点 `since`，用量页与「账号」栏都读它；分组 / 分桶 / 积分比率的语义在 `packages/usage` 的
  `summarizeGatewayRows`（单测同目录），与 Rust 的 `wb_usage::summarize` 同口径 —— 改口径时两边一起看
  （界面走的是 TS 那份）。

### 积分明细弹层

- 账号卡上的积分区整块可点（`role="button"` + 回车 / 空格），打开 `CreditsDialog`。
  **弹层只读**：快照取自网关页的 `credits` map（与账号卡同一份），查余额由网关页发起，
  弹层只 emit `refresh`，不另打上游 —— 同一份数据不在两个地方各存一份。
- 列的是 `Credits.packages` 里**还有剩余**的包，按到期时间从近到远排；无期限 / 到期未知沉底。
  一个号往往有多个包、到期日各不相同，所以到期时间只能逐包看，汇总成一行没有意义。
- 账号卡行尾那枚天数取 `soonestExpiry(packages, now)`：还花得出去、到期最近的包，与弹层读同一份快照。
  **不读快照里的 `earliest_expiring`** —— 它是查询那一刻算的，快照放久了跨过到期时刻就不再是「最近」的那个；
  界面当场按 `expiresAt` 比。天数再用 `creditExpiry` 按 UTC+8 自然日折算，所以和弹层里同一个包的标签一致。
  卡上那枚是灰字（不扩彩色档位），悬停 `title` 给包名、剩余与作废日期。
- 到期档位按 **UTC+8 自然日**算（`packages/usage` 的 `creditExpiry`，与福利柱状图同一条口径）：
  今晚 23:00 到期算今天、明天 01:00 算明天（拿毫秒差除一天会把后者算成今天）。
  ≤10 天琥珀、≤5 天橙（琥珀与红混出来的一档）、≤3 天红、今日红实心；
  已过期（`expiresAt` 已过）与到期未知保持灰 —— 它们不催任何动作。
- 企业额度的包 `no_expiry = true`：日期照给（周期结束），标签写「周期重置」而不是「无期限」——
  它是回满不是作废，不进临期档位。个人号的 `no_expiry` 才显示「无期限」。
- 没有快照时给空态 + 「查余额」按钮；有快照但没有剩余包时给「没有还有剩余的包」。
  「刷新」只在弹层里重查这一个号，与账号卡上的「查余额」是同一段逻辑（`queryOne`）。

### 多机流水同步

`usage.jsonl` 是本机账本；把它同步到设置里那个 git 仓库（与 token 用量同一个仓库、同一个克隆）之后，
用量页会把各台机器的流水合起来算。**没登录 / 没填仓库就只有本机**，和 token 同步同一个门禁。

- 仓库里的落点：`gateway-usage/<设备id>/<YYYY-MM>.jsonl`。一台机器只写自己那个目录，每月一个文件；
  月份按 UTC+8（与用量页分桶一致）。所以多机同步没有同文件冲突。
- 同步的是本地流水的一份**脱敏副本**：`apiKey` 置空、`costCny` 置空，其余（账号 uid、模型、token、
  credit、耗时、UA、错误文本、`machine`）原样带过去。密钥尾号即使只有四位也不进仓库。
- `machine` 是主机名：新流水在记账时写入，旧流水在同步 / 读取时补本机名；远端行缺这一项时用设备目录名。
  请求记录页不再单列「机器」与「API Key」两列（单机使用时没有信息量），`machine` 仍留在流水与搜索条件里。
- **本机 `usage.jsonl` 是权威账本**：读取时只合入别的设备的目录，本机目录跳过，避免同一条被算两遍。
  同步失败只影响「看到别的机器」，不影响本机出数与聚合。
- 节奏：**30 天总 token 每新增 10M 自动推一次**（TBuddy 页的 15 秒轮询里判定；用量页不再有手动按钮），
  现有的一小时一轮 token 同步也仍会顺带推一次。内容没变时 `git diff` 会挡住空提交。
- **读永远只读本地克隆，进页面时补一次 pull**：`read_gateway_rows` 不联网；克隆平时只在推送时
  （`ensure_clone`）顺带更新，本机没有流水就不会推送 —— 别的机器推上来的今天因此进不来。
  `GatewayView` 进页面（含从别的页面切回来）在首屏之后调一次 `gateway_sync_pull`（只 pull、不写不提交不推），
  有变化再重读。一分钟内不重复拉（适配层的节流），失败静默、只影响「看到别的机器」。
- 同步只加不删：本机流水被清空 / 删掉某个月时，仓库里已有的旧月份**不会被删**
  （`git add --ignore-removal`）。要清理某个月：先删本机 `usage.jsonl` 里那个月的行，再在仓库里手工删
  对应文件；只删仓库那边，下一次同步会按本机流水写回来。

### 已知边界

- 只做 Chat Completions（含 `/completions` 别名）。Responses API 与 Anthropic Messages 未接。
- 只查 `p_tcaca` 这一本积分账 —— 另一本（评测侧）网关看不到，这是上游边界不是遗漏。
- 静态价表（`wb_pricing`）与 `costCny` 仍在历史流水里，但界面不再展示，也不参与积分口径。
- `扣除积分` 一列只有上游在 `usage.credit` 里给了数才有值，否则是 `—`：不拿 token 乘倍率去推，
  推出来的数看着像真的，实际只是另一份估算。
- 积分比率的分母是总 token（含缓存命中），不是「未命中输入 + 输出」的计费 token；这是为了口径简单，
  读数时要连缓存命中率一起看。
- **按模型的限额认 code 6004，整号的额度仍认正文关键词**：上游的按模型限流有稳定 code
  （`{"code":6004,"msg":"您的使用量已超出频率限制，将在 … 重置"}`），正文那句完整措辞也认；
  整号的余额 / 积分用完没有 code，只认「额度 / 余额 / 积分」+「用完 / 不足」这类成对出现的关键词
  （`wb_quota::looks_exhausted`）。认不出的额度错误不会自动打标记，只会原样报给客户端。
  **HTTP 429 单独不算额度用完** —— 那多半是瞬时限流（上游 `code 14003`「模型繁忙」），
  误判会把好号封 24 小时；但会换一个号再试一次，全被拒才把 429 翻给客户端（见上文「账号池」那条）。
- **只在拿到状态码之前接手**：上游先回 200、再在 SSE 帧里报额度用完的那种，不会打标记
  （此时调度层已经交出了账号快照）；请求流水里能看到那条失败，界面上的标记要等下一次
  「查余额」或下一次 HTTP 级失败才补上。
- **恢复时间先看正文、再看企业周期**：按模型的 6004 正文里带「将在 YYYY-MM-DD HH:MM:SS UTC+8 重置」，
  取它；企业号取 `cycleEndTime`；个人资源包只有包到期时间（`DeductionEndTime`，不是每日重置），
  不拿它当恢复时间，一律按 24 小时兜底。没有后台定时器，标记到期是在选号 / 读账号时
  按时间判定的 —— 到期那一刻不会主动刷界面，最多等一次轮询。
- **按模型标记不是整号下线**：界面上是「部分模型用完」，统计卡的「额度用完」只数整号标记；
  同一个号换别的模型仍然会被选中。判断当前能不能发某个模型用 `wb_pool::order(accounts, model, now)`，
  只看整号用 `first()`（拉模型目录那条路）。
- **按模型的标记以客户端请求的模型名为键**：上游 6004 的正文不带模型名，`auto` 这类别名又可能在
  上游落到具体模型（实测 `auto` → `hy4-preview`）。所以别名与具体模型各记各的，换一种写法可能
  再撞一次 —— 这是信息边界，不是漏判。
- **流内错误按失败记账**：上游 200 之后的 SSE `error` 帧、`finish_reason: "error"`、
  以及一帧有效内容都没有的空流，都写 `ok: false`；非流式聚合遇到 error 帧同样先记失败再回 502。
  成功率与「额度用完」的界面标记都依赖这一条。
- **成长任务的范围**：已接参考项目的 6 个专家任务、`Sequential_Tasks_7` 与 Buddy 盲盒；
  `RichMeow_Chat` / `Library_read` 仍按桌面专用任务跳过，小程序链式任务
  （`Sequential_Tasks_1..6` + 校园日）未接 —— 后两类要模拟桌面 / 小程序事件，跟
  「只认桌面端真实行为」的约束冲突，没做。
- **成长抽奖次数 0 不等于活动下线**：2026-11 实测 `lottery/chances` 回 200、`balance: 0`，
  `lottery/summary` 的 `module.enabled` 仍为 true；0 只是没有可抽次数。次数来自连登 7 / 14 / 28
  档位兑换（每档 1 次）：连登 0 天、补签卡 0 张时三档全 locked，界面自然显示 0 次。
  「成长连登与抽奖」按钮仍然有效，只是没有可兑换 / 可抽的东西。
- **「连登」按成长热力墙算，不是 Buddy 加油站签到**：`streak.days` / `month_total_days` 与
  `/activity/growth/heatmap` 的 `score > 0` 对齐。2026-11 实测 11-02 / 03 / 05 / 06 有签到积分
  （福利柱状图有柱）但热力墙 score = 0，只有 11-04（新 Buddy，score = 40）计了 1 天。
  `wb_gateway_checkin` 走计费域 `daily-checkin`，不会推进成长连登；`run_streak_bonus` 只做补签 /
  兑换 / 抽奖，本身不产生每日成长活跃。福利栏的「Buddy 签到连签」另取 `checkin-activity-status`
  的 `checkin_dates` 计算，不拿成长连登冒充签到连签。
- 渠道指纹清洗是**字面量黑名单**（`wb_sanitize` 的 `FEATURES` / `REWRITES`）：上游新增一种客户端模板句时
  要手工补表；它只保证「请求能发出去」，不代表上游认可这种用法，账号风险仍由用户承担。
- 同步仓库会随月份文件长期增长，**不做自动清理**；清理办法见「多机流水同步」。
- 两台机器共用同一个 `device.json` 会写同一个设备目录并互相覆盖；本机 `usage.jsonl` 丢了但设备 id
  还在时，自己的远端目录会被跳过（避免双计），那段历史在界面上看不到。
- **福利自动跑没有后台服务**：应用关着时不会执行，只能在启动后补跑或应用开着时补；
  「每天」按本地自然日算，同一台机器上的同一账号每天最多自动跑一次。夜猫子按上游口径
  每晚只上报一次，进度要累计三天，所以不会因为打开了自动跑就当天领完。
  自动跑只写本机 `perks-auto.json`，不参与多机同步：换一台机器视为「今天还没跑过」。
- **开发版与安装版都默认随程序启动时会争同一个 17878**：后启动的那份绑定失败只记标准错误，
  界面显示「已停止」并允许手动重试；在接入弹层把其中一份的端口改掉即可。
  端口冲突不影响应用启动，也不影响本机其余功能。
