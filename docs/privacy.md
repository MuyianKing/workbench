# 数据与隐私

十四条联网出口、落盘位置与不同步的边界。**动联网代码前先读这一节**；模块内的出网点在各自 `modules/<模块>.md`。

应用**默认不联网**。对外发请求的只有十四处，且都是你自己开出来的。**截图与钉图一处都不占**：抓屏走 Win32（BitBlt）、
剪贴板与落盘都在本机、钉图只是一扇置顶窗口，整个过程没有一次网络请求（也正因如此，取字 / OCR 这一版不做：云端那条会多出
一处出口）。

- **用量同步**（可选、默认关闭）：登录账号且设置里填了仓库地址才会推 / 拉那个仓库，退出登录就停。推的内容是 Coding 用量
  快照、外观配置（只在设置里手动点）与**网关请求流水**（`gateway-usage/`：模型 / token / 积分 / 账号 uid / UA / 错误文本；
  不含 apiKey 与 costCny，也没有对话正文）。**首页活跃度另推一份计数账本**（`activity/<设备id>.json`：日期 + 五类操作次数，
  没有操作明细），多台机器按天求和后画在同一张图上 —— 同一个仓库、同一个出口。**工作日志也走这条出口**
  （`work-log/<设备id>.json`：日期 / 状态 / markdown 正文 / 项目名，外加删除墓碑），登录且填了地址才推，进工作页与每次增删改
  后自动同步。**ETF 页另推一份公开行情缓存**（`etf/<设备id>.json`：份额与净值，没有用户内容）—— 同一个仓库、同一个出口，只是
  给别的机器复用，省掉重复回填。**密码保险库推的是同一仓库的另一个目录**（`vault/vault.json`），推上去的只有密文（密钥只在
  本机，见[「密码保险库」](modules/vault.md)），所以不是多出来的出口；它**没有同步按钮** —— 登录且填了地址之后，进密码页、
  或在那一页增删改一条，就自动推拉一次（换 / 导入密钥那几步不自动推）。
- **TBuddy（网关，可选；监听默认随程序启动，可在设置·通用关掉）**：应用启动即绑 `127.0.0.1` 的一个端口；关掉后点「启动」
  才绑。手动停止只在本次会话有效。仍是回环，不对外暴露。**Qoder 网关是另一套独立实现**：自己的端口（默认 17879）、密钥与
  随程序启动开关，两个代理可以同时跑。点「登录」才连 CodeBuddy 的登录与计费接口（对话 `copilot.tencent.com`，计费
  `www.codebuddy.cn`）。它把账号额度包成一条本机 OpenAI 兼容接口给别的客户端用；**只监听回环**，不对外暴露、不上报任何数据
  （历史流水只在开启上面的用量同步时随那个仓库走）。定价估算用的是随包价表，不联网取价。**账号导出 / 导入只在本机**：导出的
  是一段含明文 token 的 JSON（用户自己存进密码管理器），不写同步仓库、不联网；导入只读用户贴回来的那一段。「福利」栏的签到 /
  成长任务 / 猫猫旅行 / 成长连登与积分流水**也走同一条出口**，默认只认用户点出来的动作；用户显式打开设置·通用里的「福利每天
  自动」开关（TBuddy 与 Qoder 共用，默认关）后，启动补跑与每十分钟一次的本机判断才会自动发签到 / 一键做任务（夜猫子另有
  23:00–08:00 夜间轮；成长连登与抽奖不自动）。领奖在桌面端回 400 时降级到 `www.workbuddy.cn`（这一页唯一会碰那个主机的地方）；
  尝试记录只写本机 `activity.jsonl`，自动跑的日期标记只写本机 `perks-auto.json`，都不随任何仓库同步。
- **Qoder 网关（可选；独立端口 / 密钥，可与 TBuddy 同时跑）**：点「登录」才打开浏览器完成 Qoder 国内版 OAuth 设备授权；之后
  只有用户手动「启动」或随程序启动时才绑 `127.0.0.1`。出口只有三个国内版主机：账号与计费 `openapi.qoder.com.cn`、推理
  `gateway.qoder.com.cn`、授权页 `qoder.com.cn`；请求体走 COSY 签名，**不上报任何数据**。请求流水只写本机
  `wb-qoder/usage.jsonl`（不进多机同步），签到尝试只写本机 `activity.jsonl`，自动签到开关随设置·通用那一个「福利每天自动」
  写本机 `wb-qoder/perks-auto.json`（默认关；打开后启动补跑、每十分钟由渲染层问一次，判断在 Rust 侧）。不实现国际版 / PAT /
  本地凭证扫描。细则见 [qoder.md](modules/qoder.md)。
- **账号登录**（可选）：点登录时才访问 GitHub / Gitee 的授权接口，之后不在后台反复打请求（头像只在打开账号弹窗时重拉）；
  唯一例外是 access_token 到期后的**续期** —— 只在同步之前（或刷新账号资料时）按需发生一次，走的还是换 token 的接口。
- **笔记图片上传与清理**（可选、默认关闭）：填了图片仓库、且你**真的往正文贴了图片**（或打开素材管理删图）才会碰那个仓库，
  没填就是一句提示；文档里存的是外链，图片在你自己仓库里。正文里的外链图与素材缩略图由 webview 按地址直接取，同一条边界
  （页面级 `no-referrer` 让请求不带来源，见[「笔记」](modules/notes.md)）。
- **笔记本身的同步**（可选、默认关闭）：前提是**笔记文件夹自己是个连了远端的 git 仓库**（应用不替你建），且你**点了同步
  按钮**才走一次 git，推到它自己的 `origin`。**知识库是同一族实现**（sync.rs 的同一条 `sync_folder` 路，各一份薄壳：
  `kb_sync` 提交拉推、`kb_pull` 只拉不推），推的也是那个知识库文件夹自己的 `origin`，不另算一处出口：提交是 `git add -A`
  不带 pathspec、等于**整棵工作树**，同步内容 = `raw/`（原始数据）+ `data/`（条目与生成物）。**知识库多两个触发时机**：
  打开知识库页后台 `kb_pull` 一次（列表数据来自远程仓库），以及**每次清洗前后各一次** `kb_sync`（清洗的硬前置是把原始
  文件上传远程；跑完把新条目也推上去）—— 触发时机变了，出网的地址与内容没变。
- **技能库的同步**（可选、默认关闭）：前提是**技能库在连了远端的 git 仓库里**（从它往上找），且你**点了技能页同步按钮**。
  推的是技能库所在的那个仓库（可能是笔记仓库的同一远端，也可能是专门的技能仓库）；平时增删改只在本机提交 —— 技能不是多出来的
  出口。
- **命令执行本身**访问网络（`npm install`、dev server 之类），那不属于应用的行为。
- **AI 热点**（量子位，免费、不需要凭据）：首页「AI 热点」卡片的数据源。**源地址是内置白名单**（Rust 侧 `ai_news.rs` 的
  `SOURCES`，**只放中文源**），渲染层只能报源 id、拿不到任何地址；只有首页画着那张卡片、且到了它自己的刷新间隔才 GET，只读
  不传（每源独立 TTL + ETag 条件请求 + 429 退避，见 `packages/ai/src/ai-news.ts`）。**站内阅读**是同一条出口的延伸：点开某
  一条才抓那篇正文，域名另有 `article_hosts` 白名单（只认源站自己的域名与子域），页面脚本不执行、只取正文纯文本。
- **实时天气**（Nominatim + Open-Meteo，免费、不需要凭据）：顶栏问候旁那小段实况的数据源。**设置里填了天气城市
  （`weatherCity`）才会取**，留空整条出口是关着的；填了之后半小时一次 GET。白名单是 Rust 侧 `weather.rs` 里那**两个**主机名
  各管一段：城市名 → 经纬度走 OpenStreetMap 的公开 Nominatim（Open-Meteo 自带检索对部分中文名匹配不上，实测「常州」搜不到、
  Nominatim 能搜到），实况走 Open-Meteo 的 `/v1/forecast`（坐标越界发请求前就拒）。**城市名会作为查询串发出去** —— 这条出口
  唯一的用户内容。解析与 WMO 码表在 [packages/weather/src/weather.ts](../packages/weather/src/weather.ts)；经纬度只在本机内存
  里缓存（换城市才重查），不落盘、不参与同步；取不到就少显示一段，问候语不报错。
- **AI 助手用的模型端点**（可选、默认关闭）：配好服务（挑厂商或自定义端点 → 粘 API Key → 挑模型）、选了默认模型并点了发送，
  才会请本机 Pi 干活 —— **请求是那个子进程直接发给你配置的端点的**（不经应用的 HTTP 客户端），**它在工作目录里读到的内容与
  这段会话的历史都会发到那个端点**（清洗知识库那一轮读的是知识库仓库里的 **raw/** —— 原始数据物理在仓库里，见 [kb.md](modules/kb.md)）；预设表在 [packages/ai/src/ai.ts](../packages/ai/src/ai.ts)，密钥与端点的规矩见
  [docs/modules/ai.md](modules/ai.md)。**同一条出口还包括「拉模型列表」**：粘上 Key（或点「获取列表」）时**应用自己**按你填的
  Base URL GET 一次 `{Base URL}/models`（Anthropic 那套是 `/v1/models`）—— 同一主机同一把 Key，不点不走。**Pi 自己的遥测与
  版本检查由应用在起进程时关掉**（`PI_TELEMETRY=0` / `PI_SKIP_VERSION_CHECK=1` / `PI_OFFLINE=1`），不关它会替用户往 pi.dev
  发请求。「安装 Pi」跑 `npm install -g`，属于「命令执行」那一类。
- **装技能**（可选；AI 助手页「技能」按钮里的「粘地址」，第九条出口）：**你粘上地址、再点「装上」**应用才 GET 一次 ——
  **主机不设白名单**（与「你自己填的 git 仓库」同类：地址由你给），跟着 `Location` 最多跳 5 跳，只收 zip、超过 64 MB 就停。
  **除那个地址本身，这一趟不带任何用户数据**；下载的包**只解压落盘，脚本一概不执行**（要不要跑是 Pi 的事，受权限档管）。
  另两种安装方式（导入本地 zip / 目录）与列表、开关、卸载、`--skill` 注入全在本机。实现与边界见
  [pi_skills.rs](../apps/desktop/src-tauri/src/pi_skills.rs) 与 [docs/modules/ai.md](modules/ai.md) 的「技能」那几条。
- **邮箱**（可选、默认关闭；第十条出口）：邮箱账户**可同时配多个**（163 / 126 / QQ 的收发服务器跟着地址后缀自动带出，自定义
  域自己填），每个账户填了地址、授权码进了凭据管理器，才会连**它配置的**收发服务器（IMAP 收信 993、SMTP 发信 465，隐式 TLS；
  主机不设白名单 —— 与「装技能」同类，地址由你给）。**收件箱与已发送**各合并成一条按时间排的清单（服务器上的文件夹名由应用
  现认，网易 / 腾讯各是一种写法），行上标注来源账户。授权码存 Windows 凭据管理器（DPAPI 按用户加密，按地址一条），不落明文、
  不回渲染层；连接参数进设置（明文 JSON，但那几项不是秘密）。**本机还有一份通讯录**（右击「存为联系人」攒的、写邮件时收件人
  从里面挑，也允许当场打新地址）—— 它只住设置里，不参与同步、不发往任何地方。**邮件 HTML 正文的外链图片跟着信里的地址加载**
  （营销信的主视觉能直接看到；请求不带 Referer），脚本 / 字体 / 音视频等其余外链资源照旧不加载：沙箱 iframe + 只放行图片的
  CSP —— 除收发服务器与信里引用的图片主机，这条功能没有别的网络目标。进页面、点刷新、发信各是一次现连现断的连接；此外配了
  账户后有**后台新邮件检查**（`mail_watch.rs`，连的还是你配置的那台收件服务器；周期在邮箱账户弹层里设、默认 30 分钟、可关）：
  有未读的新信弹 Windows 系统通知，点通知唤出主窗口并打开那封信（通知是 `notify.rs` 手写的 WinRT toast，不引通知插件）。
  实现与边界见 [mail.rs](../apps/desktop/src-tauri/src/mail.rs) 与 [docs/modules/mail.md](modules/mail.md)。
- **禅道**（可选、配置开启；第十一条出口，**应用自己的请求只读**）：在 `oauth.local.json` 的 `zentao` 节填写部署根、账号与
  密码后重新构建。**默认每 30 分钟后台检查一次**（通用设置里可改，0 = 关闭）：Rust 先 POST `/api.php/v1/tokens` 登录，随后
  GET 可见产品与各产品「指派给我的」Bug 分页；间隔由 Rust 计时线程计时并到点发事件，取数、比编号全集与弹通知在渲染层 ——
  计时放 Rust 是因为窗口收进托盘后 WebView 定时器会被节流。只有配置完整、周期非 0 才发检查事件；第一轮成功只建立基线，之后
  有新增才弹系统通知（复用邮件那条 toast 路径，点击用系统浏览器打开禅道）。请求只发往配置的部署根与固定端点，不跟重定向；
  账号密码仅由 Rust 读取，token 仅留 Rust 内存，不回渲染层、不写数据文件或凭据管理器。配置缺失不出网；重启清 token。HTTP 的
  凭据传输不加密，个人密码随配置内嵌到二进制，不能分发带密码的构建。实现与边界见 [zentao.md](modules/zentao.md)。
- **ETF 资金流**（可选；第十三条出口，**三个公开行情主机、全部只读 GET、不发用户内容**）：打开「ETF」页（或点那一页的
  刷新）才会拉：沪深交易所的份额披露（`query.sse.com.cn` 单日一份、`www.szse.cn` 区间批量）与天天基金的单位净值脚本
  （`fund.eastmoney.com`）。主机白名单钉死在 `etf.rs`，渲染层只给得出日期 / 基金代码 / 页码；请求串里没有任何用户数据。深市
  那一路 HTTPS 拿不到响应时会把协议换成明文 http 重发一次（同主机同路径、同一份公开只读 JSON；深交所会对高频回填的出口 IP
  在 TLS 层直接断连），是全项目唯一没有 TLS 的出口，沪市与净值两路照旧只走 HTTPS。首次使用回填五年份额（上千个请求、断点
  续传，进度与数据都在本机 `data\etf.json`），之后每次进页面只增量补缺。没有定时器、没有后台轮询。**开了同步时这份缓存的
  副本也走你自己的同步仓库**（`etf/<设备id>.json`，与用量同一个出口、同一份仓库地址；一台机器跑完回填，其他机器进页面把它
  并进本机就够）。实现与边界见 [etf.md](modules/etf.md)。

十四处都没有自建服务端：四处 git 同步发往你自己的仓库（知识库与笔记是同一条 `sync_folder` 实现的两个入口、不另算），登录走两家平台官方 OAuth，
AI 热点与天气只 GET 白名单里的公开源，AI 助手发给你自己配的端点，装技能只 GET 你粘的地址，邮箱连的是你自己配的收发服务器，
禅道只访问凭据配置中的部署地址，ETF 资金流只 GET 交易所与行情的四个公开主机，Qoder 只连它国内版的三个主机 —— 不上报任何
数据。落盘除了数据文件，还有一处**应用之外**的：

- **Windows 凭据管理器**：登录凭据（access_token / refresh_token / 到期时刻）存成一条 `Workbench/<平台>/token`，**刻意不写进
  `workbench-data.json`**（那是数据目录里的明文 JSON；这里能在「控制面板 → 凭据管理器 → Windows 凭据」里看到并手工删，登出时
  应用也会删）。**保险库密钥也在这里**（`Workbench/vault/key` —— 落数据目录等于把明文密码摊在盘上）；**AI 助手的 API Key
  同样在这里**（`Workbench/ai/<服务名>/token`，一个服务一条）：只被读出来注入子进程环境变量，**连渲染层都拿不到**。唯一的
  例外是**保险库密钥会过一次 IPC**（加解密在渲染层做，见[「密码保险库」](modules/vault.md)），是全项目唯一一处机密进渲染层，
  别当先例推广。
- 数据文件里的账号资料只有昵称、头像与登录名，**没有 token**。
- 两处后台常驻检查的周期住本机数据文件（**不进外观同步**）：`mailPollMinutes`（邮件新邮件检查）与 `zentaoPollMinutes`
  （禅道 Bug 检查，默认 30，0 = 关闭）。两者的计时线程都在 Rust —— 窗口收进托盘后 WebView 的定时器会被节流。

其余落盘都在**数据目录**里（安装版固定 `%APPDATA%/Workbench/data/`，开发版固定 `%APPDATA%/Workbench-dev/data/` —— 两边不
共用，开发时改的设置不会盖掉装着的那份；根目录 `%APPDATA%/Workbench` 是迁到 Tauri 之前的 Electron 版留下的 Chromium 配置
目录，数据文件不跟它混）：

- `workbench-data.json`：项目列表、分组、快捷启动的常用软件、应用设置（含 `activeView` 与「上次看的那一档」那几项行为偏好）；
  AI 助手的服务清单（`aiProviders`：名称 / Base URL / API 形态 / 模型清单，密钥不在这里）、默认模型、会话清单（只存调度字段，
  对话本身由 Pi 写进下面的 `pi/`）、**关掉的技能**（`aiSkillsOff`，键是「技能根 + 技能名」）；按天聚合的活跃度计数
  （**分来源**存，只留最近一年，总数由分项现算）、残留子进程记录、账号显示资料。
- `pi/`：**内置 Pi 自己的东西**（`PI_CODING_AGENT_DIR` 指到这里，与用户全局 `~/.pi` 互不掺和）：`models.json`（整份由应用
  写出，`apiKey` 只是环境变量引用）、权限扩展 `permission.js`、Pi 自己的 trust.json / auth.json，以及 `pi/sessions/` 下
  **一段对话一份的会话文件**（`<时间戳>_<会话 id>.jsonl`，Pi 自己写；删会话就是删这里那份）。不是应用的数据格式，别当第二份
  真源：读对话走 RPC 的 `get_messages`，删会话走 `ai_session_delete`。
- `token-usage.json`：**本机** Coding 用量快照，按「工具 → 天 → 模型」聚合（只留最近一年），也就是同步推到 `token-usage/`
  的那份（旧名 `token-data.json` 启动时自动改名）。明细不复制 —— 各工具的本地数据是明细账本，快照用于对抗上游清理。带一个
  `credits` 字段（额度口径，只有 Qoder 填），同一套合并规则但**不参与 token 总量**。
- `work-log.json`：工作日志（v2：条目 + 删除墓碑）。**本机这份是权威**；登录且配了同步仓库时按设备推一份
  `work-log/<设备id>.json`，读别人的分片按 id 后写胜出、墓碑不复活，合并结果**写回本机**（见
  [work-log.md](modules/work-log.md)）。它仍然不在 `workbench-data.json` 里。
- `ai-news.json`：AI 热点的上次拉取结果，**按源分开**存（每源一份 `etag / nextFetchAt / failCount / lastError / items`），
  合并视图读时现算 —— 撤掉一个源，它的内容立刻从卡片消失。**只在本机、不进同步仓库**。单源时代（v1）的老结构不再迁移。
- `vault.json`：**密码保险库**（见[「密码保险库」](modules/vault.md)）。**只有密文** —— 条目正文全在密文里，明文只在内存中，
  露出来的只有条目条数、每条的改动时刻与设备 id、哪些 id 被删过。它同时是同步到 `vault/vault.json` 的那份：与别处不同**这份
  文件是所有机器共写的**，合并规则自己定死（按 id 取并集、取改动时间新的那份），不交给 git 合。
- **笔记没有数据文件**：笔记本就是用户挑的那个文件夹（见[「笔记」](modules/notes.md)），`.md` 就是全部内容；应用只记「当前
  打开的目录」与「打开过的那几个」（`noteDir` / `noteDirs`，左栏**宽度**在 `theme.json`）。天然**不进同步仓库**，换台机器选
  同一个文件夹即可。旧版笔记 JSON 树（`note-data.json`）不再读写，盘上那份可以删掉。
- `pins.json` 与 `pins/<id>.png`：**钉图的记账与图本身**（位置 / 尺寸 / 透明度）。（截图那几帧**只在内存里**：一场会话用完
  即弃，不落盘。）**只在本机**：位置是这块屏上的坐标，换台机器不成立，也不进同步仓库。钉图关掉时连图一起删掉。
- `ball.json`：**网速球的记账**（窗口左上角的 x / y + 贴着哪一侧）。与钉图同一待遇：位置是这块屏上的坐标，**只在本机**、不进
  同步仓库。它不记「收起还是展开」（那是位置的即时结果，重启按位置重算），窗口被系统关掉也不清 —— 它是位置偏好，不是「球还
  开着」的凭据（见 [float-ball.md](modules/float-ball.md)）。
- 快捷启动只存程序路径与参数，不放程序本体。
- 程序图标按「路径 + 程序文件修改时间」缓存在 `workbench-data.json`（每个 1.5~4.4 KB）：修改时间没变就直接用（实测每次重抽
  27~53ms）；只缓存抽成功的，失败的下次照常重试。
- `device.json`：本机设备标识（uuid），首次用到同步时生成，**不会被同步**（两台机器同一个 id 会互相覆盖文件且无报错）。

**一件需要如实说明的事**：安装包内置了 OAuth 的 client_id（Gitee 还有 client_secret）—— 这是「使用者零配置」的前提（VS Code
同路），代价是 secret 理论上能从安装包逆出来。影响面被「回调地址必须是 `127.0.0.1:45871`」限死：拿到 secret 也接不到别人的
回调，且只能冒充本应用。不接受就退回「每个使用者自己去两家平台注册应用」那条路。

同一份 `oauth.local.json` 还可包含禅道的个人账号密码，构建时整份内嵌到二进制；修改后必须重新构建，运行时不会重读文件。这类
个人密码泄漏后可以直接登录禅道，不受 OAuth 回环地址限制；`.gitignore` 不保护构建目录或安装包，不能分发带个人密码的构建。

读取别人的数据一律只读、不改文件：ZCode 是 `~/.zcode/cli/db/db.sqlite`（WAL 只读打开，`ZCODE_HOME` 可指别处）；DeepSeek
Harness 是 `~/.dsh/sessions/<项目>/<会话>/`（`DSH_HOME` 可指别处；v3 与旧版并存时**只读 v3**，都读会把那次会话算两遍）；
CodeBuddy 是 `%APPDATA%/CodeBuddy CN/logs`（国际版没有 `CN`，`CODEBUDDY_DATA_DIR` 可指别处）里扩展目录
`Tencent-Cloud.coding-copilot` 下的 `.log`；WorkBuddy 是 `~/.workbuddy/projects/<项目>/`（`WORKBUDDY_HOME` 可指别处；与
Electron 那个 `%APPDATA%/WorkBuddy` 不是一个目录，后者只有窗口状态）；Qoder 是 `~/.qoder-cn/projects/<项目>/`（国际版
`~/.qoder`，`QODER_DATA_DIR` 可指别处）。五处正文都带对话内容，只解析用量字段、**正文不进快照** —— 同步推的只有模型名与计数。
Qoder 不产生 token 计数，解析出的只有每次请求扣掉的额度，落在 `credits` 一个字段上、只喂 credits 口径。

同步的克隆目录在用户数据根目录下（安装版 `%APPDATA%/Workbench/token-sync/`，开发版
`%APPDATA%/Workbench-dev/token-sync/`；本地缓存，删了下次同步重新克隆）。仓库里四个路径：
`token-usage/<设备id>.json`（模型名与 token 计数，**没有对话内容**）、`config/<设备id>.json`（那份 `theme.json` 的副本：
明暗 / 主题色 / 顶部样式 / 卡片不透明度 / 毛玻璃描边 / 终端高度 / 程序名称 / 工作区背景 / 导航菜单 / 首页布局）、
`gateway-usage/<设备id>/<YYYY-MM>.jsonl`（网关请求流水：模型、token、积分、账号 uid、UA、错误文本；**没有密钥尾号、没有对话
正文**）与 `etf/<设备id>.json`（沪深份额与天天基金净值，全是公开行情、没有用户内容）。四者都没有图片本体与项目信息，别的
机器的文件从不改动、只读自己那份。仍建议私有仓库。

网关流水的同步节奏与 token 用量一致：30 天总 token 每新增 10M 推一次、一小时一轮的用量同步也顺带推一次；进 TBuddy 页时另会
**只拉不推**地刷新一次克隆（一分钟节流）—— 读路径本身不联网，而克隆平时只有推送时才顺带 pull，本机没有流水时别的机器推上来
的今天就进不来。读取时只合入别的设备的目录（本机 `usage.jsonl` 是权威账本，跳过本机目录避免双计）。月份键按 UTC+8；仓库只加
不删（`git add --ignore-removal`），本机丢文件不会抹掉旧月份。

`config/` 的背景字段是原样复制的：本机若用自己磁盘上的图，那条路径会出现在文件里（只是路径）。这份**只在设置 → 外观点
「同步一次」时才推**，采用别人的配置也只能手动「应用」。

已知边界：重装系统 / 清掉数据目录后设备 id 变「新设备」，仓库里的旧文件会把同机历史算两遍（需手工删掉）；日期按各机本地时区
归天，跨时区对不齐；网关流水的月份目录会随请求长期增长，不做自动清理（先删本机 `usage.jsonl` 里那个月的行，再手工删仓库
文件）；**数据目录不要设成多机共享位置**（网盘 / 网络盘）—— 设备身份写在 `device.json` 里，共享后两台机器顶着同一个 id 写
同一个文件（网关的 `gateway-usage/<设备id>/` 也会互相覆盖）；共享目录本来就不成立（项目列表整份覆盖写，会互相盖掉），别为了
同步把它指到网盘上。
